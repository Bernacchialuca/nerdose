# Story Plan: S-059 (admin) - Auditoría de accesibilidad y mobile de la plataforma

## Status

**Status:** Completed

## Referencia de la Story

- **Story:** [S-059](../stories/S-059.auditoria-accesibilidad-y-mobile.md)
- **Servicio:** admin
- **Resumen:** auditoría **puntual** de todas las pantallas y overlays del responsable (`apps/admin`) con Playwright + `@axe-core/playwright`, la red simulada con `page.route` y los fixtures tipados que ya usan los tests de MSW de `admin`. Solo proyecto `desktop` (la superficie `admin` tiene un único viewport y el requisito de 320 px es de la superficie del jugador). Se audita cada pantalla en sus estados principales, con specs de teclado de los flujos críticos (login → reportes → anular, próximos → regenerar, stock, métricas, cierre de sesión). Se corrige en `apps/admin` lo que es propio de `admin`, se registran como derivadas las violaciones con origen en `@nerdose/ui` o en los `client` de los juegos (preview de O-02), se completan las secciones de `admin` del informe `docs/audits/accesibilidad-REQ-011.md` y al final se desinstalan Playwright y axe-playwright de `admin` y se borran specs, configuración y scripts.

> **Alcance de este plan:** solo el servicio `admin`: `apps/admin/**`, las secciones de `admin` del informe `docs/audits/accesibilidad-REQ-011.md` (ya creado por el plan `web`) y, si una corrección de `admin` cambia una apariencia documentada, `docs/design-system/admin/**`. Queda **fuera**:
> - **`web`** (plan `S-059.web.*`, **Completed**): sus secciones del informe no se tocan, salvo la frase «Las tablas de métricas quedan para la sección de `admin`» de «Sin color», que se reemplaza por la fila de `admin`.
> - **`ui`** (plan `S-059.ui.*`): correcciones en `packages/ui` (p. ej., `buttonClass({ variant: 'icon' })`, `dataTableClass`, `Badge`, `Banner`, `Alert`, `Panel`, `AppHeader`, `navItemClass`).
> - **`games`** (plan `S-059.games.*`): correcciones en `packages/games/*/src/client` (los `Preview` que `admin` muestra en O-02 desde Próximos).
>
> **Orden de ejecución de la story:** **web (hecho) → admin → games → ui**. Este plan no espera las correcciones de `ui` y `games`: sus hallazgos se agregan a «Hallazgos derivados» del informe con todo lo necesario para corregirlos sin volver a correr la auditoría (P-1).
>
> **Rutas:** las de «Archivos a crear/modificar» son relativas a `apps/admin/`, salvo las que empiezan con `docs/`, `packages/` o `pnpm-lock.yaml` (raíz del repo).

### Arquitectura del servicio (`docs/architectures/admin/overview.md`, extracto verbatim)

> SPA del responsable de nerdose (`admin.nerdose.dev`). Permite iniciar sesión, revisar reportes de jugadores y anular desafíos, ver los próximos 14 días (preview con solución y regeneración), controlar el stock de contenido de los bancos y consultar las métricas del producto. Es una herramienta interna de un solo usuario, solo en español y sin analítica.
>
> - **auth** — `/login`, token JWT en `sessionStorage`, guard de rutas y cierre de sesión.
> - **reports** — `/reports`: reportes de jugadores; resolver, descartar y anular el desafío.
> - **upcoming** — `/upcoming`: próximos 14 días con preview de cada desafío usando el `client` de cada juego en modo solución (es y en lado a lado) y pedido de regeneración con polling.
> - **content-stock** — `/content`: stock de los bancos de contenido y estado de los jobs.
> - **metrics** — `/metrics`: las vistas `metrics_*` mostradas como tablas HTML simples (sin librería de gráficos).
>
> - Pruebas: Vitest + Testing Library (unit) y axe-core vía `vitest-axe` (accesibilidad de componentes). Sin suite e2e (deuda D3, ver `testing-e2e`); la auditoría de accesibilidad de REQ-011 (S-059) fue puntual.
> - **Convenciones compartidas con `web`.** `_base`, `data-fetching`, `styling`, `state-management`, `accessibility`, `testing-unit` y `testing-e2e` son idénticas a las de `web`; si se cambia una, hay que cambiar la otra.

Rutas reales (`src/app/router.tsx`): `/login` (pública, `lazy`), y bajo `<RequireAuth><Shell /></RequireAuth>` con `errorElement: <RouteError />`: índice → `<Navigate to="/reports" replace />`, `reports`, `upcoming`, `content`, `metrics`. **No hay ruta `*`**: una ruta desconocida dentro del área protegida cae en `RouteError` («Algo salió mal»), que es lo que se audita como «no encontrado».

### Convenciones activas (partes aplicables, verbatim)

#### `accessibility` (idéntica a la de `web`)

> ### Structure and semantics
> - One `<main>` per page, landmarks for header/nav/footer, one `<h1>` per screen, headings in order.
> - Use native elements first: `<button>`, `<a>`, `<input>`, `<label>`, `<table>`. Use ARIA only when no native element fits.
> - Every input has a visible `<label>` or an `aria-label`; errors are tied with `aria-describedby`.
>
> ### Keyboard
> - Everything operable with the mouse is operable with the keyboard, in a logical tab order, with no keyboard traps.
> - Provide a visible focus ring on every focusable element (`focus-visible`).
>
> ### Not only color
> - Feedback that uses color (Devdle marks, Timeline correct/wrong, win/loss) is also expressed with an icon, a pattern or text, and exposed to screen readers as text.
>
> ### Dynamic messages
> - Result, errors and notices appear in `role="status"` (polite) or `role="alert"` (errors) regions.
> - On navigation, move focus to the new page heading and update `document.title`.
>
> ## Rules
> - Contrast is at least 4.5:1 for text (3:1 for large text and UI boundaries) against its actual background.
> - No interactive element is built from a `<div>` or `<span>` with a click handler; use a native control.
> - Every image or icon is either decorative (`aria-hidden`) or has an accessible name.
> - Color is never the only carrier of meaning.
> - Focus is never removed (`outline: none`) without a visible replacement.
> - Modal and overlay UI traps focus while open, closes with `Escape` and returns focus to the trigger.
> - Dynamic updates are announced via live regions; do not move focus unexpectedly.
> - axe-core reports zero violations in unit checks and in page audits (one-off while e2e is not adopted, see testing-e2e).
> - Language is declared (`<html lang>`) and updated when the locale changes.

Paquetes declarados: `axe-core / vitest-axe` (component checks), «`@axe-core/playwright`: not installed; only for one-off page audits (see testing-e2e, debt D3)», `eslint-plugin-jsx-a11y`.

> Nota: la regla de objetivos de toque de 44×44 y el reflow a 320 px de esta convención aplican a la superficie del jugador. Para `admin` manda el supuesto del REQ «el admin se audita en accesibilidad (WCAG, teclado) y en desktop únicamente» (ver P-2).

#### `testing-e2e` (estado vigente, verbatim)

> - **There is no e2e suite in the repo.** Playwright, `@axe-core/playwright`, `e2e/` and `playwright.config.ts` are **not** installed and MUST NOT be assumed by stories or plans. Critical flows are covered by route tests in jsdom (`testing-unit`), `vitest-axe` on components and manual verification.
> - **Debt D3 stays open:** adopting e2e requires a running `api` with seeded challenges of every game (there is no `seed:dev`).
> - **REQ-011 accessibility and mobile audit (S-059) was one-off:** Playwright + `@axe-core/playwright` were installed temporarily (mocking `/api/*` with `page.route` and fixtures typed with `api.yaml`), the violations were fixed, and then the dependencies, specs and configuration were removed. The result (violations found, fixes, accepted exceptions with justification) lives in `docs/audits/accesibilidad-REQ-011.md`. A future audit follows the same one-off approach unless D3 is closed.
>
> ```ts
> // e2e/helpers/a11y.ts
> import AxeBuilder from '@axe-core/playwright';
> export async function expectNoA11yViolations(page: Page) {
>   const { violations } = await new AxeBuilder({ page }).withTags(['wcag2a', 'wcag2aa', 'wcag21aa']).analyze();
>   expect(violations).toEqual([]);
> }
> ```
>
> ## Rules (reference design)
> - Select with roles, labels and text (`getByRole`, `getByLabel`); avoid CSS selectors.
> - Each critical flow has a spec, and every page-level spec ends with `expectNoA11yViolations`.
> - Specs are independent: each starts from a known state and does not rely on another spec's data.
> - No fixed `waitForTimeout`; rely on auto-waiting assertions.
>
> ## Update (REQ-011)
> - The accessibility and mobile audit of REQ-011 (S-059) is one-off: Playwright + `@axe-core/playwright` are installed only while it runs, with `/api/*` mocked through `page.route` and fixtures typed with the `api.yaml` contracts (tags `wcag2a`, `wcag2aa`, `wcag21aa`; `mobile` 320 px and `desktop`, `admin` only `desktop`). When it ends, the dependencies, specs and Playwright configuration are removed and the report stays in `docs/audits/accesibilidad-REQ-011.md`. Playwright is not a current tool of the repo; flows against a real `api` remain open debt (D3).

#### `testing-unit` (reglas aplicables a los tests de regresión de las correcciones, verbatim)

> - Query by role, label or visible text. `data-testid` only when no accessible query exists.
> - Use `userEvent`, not `fireEvent`, for interactions.
> - Each interactive component has an axe check; fix violations instead of disabling rules.
> - Fixtures use the API's `snake_case` names; do not write camelCase fixtures.
> - Mock the network with MSW, never the app's own modules (api client, hooks) except to isolate a single unit.
> - No snapshot tests of large DOM trees.
> - Tests do not rely on the real date or timers; use fake timers.
> - Tests never hit a real `api`.

#### `styling` (reglas aplicables a las correcciones, verbatim)

> - Use only the tokens above (or later, the Design System's). No literal hex colors, no arbitrary `[#abc]` color values in components.
> - Tokens live only in `packages/ui`; `web` and `admin` must not redeclare them.
> - Merge conditional classes with `cn()`; never concatenate class strings by hand.
> - Text and interactive-element contrast meets WCAG 2.1 AA against the surface it sits on (4.5:1 text, 3:1 large text and UI components). Verify any new color pair.
> - Focus is always visible: use `focus-visible:` rings with `--color-accent`; never `outline-none` without a replacement.
> - State is never conveyed by color alone: pair it with an icon, text or pattern (see `accessibility`).
> - **Static check:** component and web `.tsx` files must not contain arbitrary values (`/\[(\d|#|rgb)/`) nor generic utilities (`rounded-md`, `shadow-md`, `text-2xl`, `font-semibold`).

(En `admin` el check estático vive en `src/styles.test.ts`.)

#### `routing` (variante de `admin`, aplicable)

> - All routes are declared in `src/app/router.tsx`.
> - Every route except `/login` sits under `RequireAuth`; never rely on hiding links.
> - The nav links and labels are in Spanish; the `lang` of the document is `es`.
> - Route errors render through `errorElement` (see `error-handling`).
> - Each route sets a meaningful `document.title` and moves focus on navigation.

`usePageTitle(title, { focusHeading })` (`src/hooks/use-page-title.ts`) fija `document.title` y enfoca el `<h1 tabIndex={-1}>` al montar (salvo `/login`, que enfoca el campo). Títulos: «Ingresar · Admin · nerdose», «Reportes · Admin · nerdose», «Próximos · Admin · nerdose», «Stock · Admin · nerdose», «Métricas · Admin · nerdose».

#### `auth` (aplicable al arnés)

> - The token lives only in `sessionStorage`; never in `localStorage`, cookies, memory-persisted stores or the URL.
> - Any `401` with `code: unauthorized` clears the token, clears the Query cache and redirects to `/login`; the failed request is not retried.
> - `401 invalid_credentials` from `/api/admin/login` is a form error, not a session expiry.
> - Never log or display the token or the password; the password field is `type="password"` with `autocomplete="current-password"`.
> - Render report texts and any player-provided content as plain text, never as HTML (no `dangerouslySetInnerHTML`).

Clave de sesión: `nerdose_admin_session` = `{ token, expires_at }` (`src/modules/auth/token-store.ts`; `readSession()` descarta un `expires_at` vencido). `clearSession('expired')` deja `getEndReason() === 'expired'`, que el login muestra como «La sesión venció, ingresá de nuevo.».

#### `_base` y `game-clients` (aplicable)

> - **`app/`**: wiring only (providers, router, layout). No business logic.
> - **`modules/{module}/`**: everything that belongs to one module. A module never imports from another module's internals.
> - Shared UI goes to `packages/ui`; if a component is needed in both apps, move it there instead of duplicating it.
> - The shell contains **no per-game logic** (see `game-clients`).
> - Type-only imports use `import type`.
> - Default: no comments. Comment only the why when it is not obvious.

Consecuencia: **`admin` no corrige un problema de la preview de un juego con una rama por `game_id`**. El registry (`src/modules/upcoming/registry.ts`) es el único lugar que lista juegos. Si el problema está en el `Preview` del `client`, es un hallazgo derivado a `games`.

### Aprendizajes del plan `web` (del informe, «Desvíos del método respecto del plan», verbatim)

> 1. `page.route('**/api/**')` también intercepta los módulos fuente de Vite (`/src/modules/*/api/*.ts`) y deja la app en blanco. Usar un predicado: `page.route((u) => u.pathname.startsWith('/api/'), …)`.
> 2. Con `webServer` de Playwright y varios workers, el dev server de Vite se satura (Tailwind v4 escanea la carpeta de trabajo) y los tests agotan el tiempo. Funciona: levantar `pnpm exec vite --port 5180 --strictPort` aparte, `reuseExistingServer: true`, `--workers=2`, y escribir los resultados (JSON de axe, capturas, trazas) **fuera del repo** (variable `E2E_RESULTS`) en lugar de `e2e/.results/`.
> 5. Tras «Empezar» el foco pasa al `h1` de la ruta (`tabindex="-1"`, sin outline por diseño): no se cuenta como foco sin indicador.

En `admin` aplican igual: todas las llamadas de `admin` son `/api/admin/*` y los módulos de Vite están en `/src/modules/*/api/*.ts`; cada ruta enfoca su `h1 tabIndex={-1}` (sin outline por `index.css`).

#### Guideline de accesibilidad (`guidelines/accessibility.md` v0.1.0, placeholder; extracto verbatim)

> - Texto body (≥16pt): contraste ≥4.5:1. Texto grande: contraste ≥3:1. Componentes interactivos (bordes, iconos): contraste ≥3:1. NO comunicar estado solo con color.
> - Todo elemento interactivo es accesible vía teclado. Foco visible (outline o equivalente, contraste ≥3:1). Orden de tab lógico. ESC cierra modales / popovers. Enter / Space activan controles. Sin keyboard traps.
> - Cada componente declara su rol ARIA correcto. Iconos puramente decorativos: `aria-hidden="true"`. Iconos funcionales: `aria-label` descriptivo. Live regions para feedback dinámico.
> - Cada input tiene un `<label>` asociado. Errores anunciados al screen reader (`aria-invalid`, `aria-describedby`).
> - Respetar `prefers-reduced-motion: reduce`.

(El placeholder dice «WCAG 2.2 — Nivel AA»; manda la convención `accessibility` y la story: **WCAG 2.1 AA**, tags `wcag2a`, `wcag2aa`, `wcag21aa`.)

```ts
import type { Page, Request } from '@playwright/test';

export type MockResponse = { status?: number; json: unknown; headers?: Record<string, string> };
export type RouteHandler = MockResponse | ((request: Request, url: URL) => MockResponse);
/** Clave: `${METHOD} ${pathname}`, p. ej. `GET /api/admin/reports`. */
export type Routes = Record<string, RouteHandler>;

export const apiError = (code: string, message: string) => ({ error: { code, message } });

export async function mockApi(page: Page, routes: Routes) {
  const unhandled: string[] = [];
  const calls: { method: string; path: string; body: unknown }[] = [];
  await page.route((u) => u.pathname.startsWith('/api/'), async (route) => {
    const request = route.request();
    const url = new URL(request.url());
    const key = `${request.method()} ${url.pathname}`;
    calls.push({ method: request.method(), path: url.pathname + url.search, body: request.postDataJSON() });
    const handler = routes[key];
    if (!handler) { unhandled.push(key); return route.abort('failed'); }
    const res = typeof handler === 'function' ? handler(request, url) : handler;
    return route.fulfill({ status: res.status ?? 200, json: res.json, headers: res.headers });
  });
  return { unhandled, calls };
}
```
