# Story Plan: S-033 (ui) - Admin, login y sección Reportes (piezas de formulario, diálogo, pestañas y tabla en @nerdose/ui)

## Status

**Status:** Completed

## Referencia de la Story

- **Story:** [S-033](../stories/S-033.admin-login-seccion-reportes.md)
- **Servicio:** ui
- **Resumen:** Promueve a `@nerdose/ui` (`packages/ui`) las piezas genéricas que la story pide para el servicio `ui` («button, text-input, textarea, select, table, tabs, modal, drawer y alert») y que el plan `admin` (Completed, `0caf35c`) tuvo que construir como componentes **locales** de `apps/admin/src/components/` porque `@nerdose/ui` no las tenía: `Dialog` (modal y drawer), `TextField` / `TextAreaField` / `SelectField`, `Tabs`, la variante destructiva del botón (`dangerButtonClass`) y las clases de la tabla de datos. Las deja sin texto propio (ADR-002: el texto entra por props), con `required` y `hint` opcionales en los campos (el admin los tenía fijos), y con tests y axe propios. `alert` y `button` (`primary`, `secondary`, `icon`) **ya existen** en `@nerdose/ui` (`Alert`, `buttonClass`) y no cambian, salvo la variante nueva `error` de `buttonClass`.

> **Alcance de este plan:** solo `packages/ui` y la documentación `docs/reusable-code/ui/`. **No** modifica `apps/admin` ni `apps/web`.
> - **`admin`** (Done, `0caf35c`) sigue usando sus copias locales. Su plan lo previó: «Si al implementar ya existe un equivalente exportado por `@nerdose/ui` (por el plan `ui` de S-033), se usa ese en lugar del local». Cambiar los imports de `admin` es trabajo del servicio `admin` y queda como **seguimiento recomendado** (ver «Seguimiento fuera de alcance» al final). La API de este plan es compatible con la local salvo dos diferencias explícitas: `Dialog` exige `closeLabel` (en admin estaba fijo «Cerrar») y los campos solo ponen `aria-required` con `required` (en admin era siempre `true`).
> - **`web`** (S-034) consume `Dialog`, `TextAreaField` y `SelectField` para O-01 «Reportar un problema» y O-02 «Desafío anulado». La variante **bottom-sheet** en mobile que pide la fila `ui` de S-034 **no** entra acá: es alcance del plan `ui` de S-034. Este plan deja la API lista para sumarla sin romper (`variant` es una unión que puede crecer).
>
> **Regla de compatibilidad (no negociable, igual que S-011, S-021, S-024 y S-029):** `web`, `admin` y los clients de Devdle, Grep Grid y Timeline siguen compilando y pasando sus tests. La API pública crece de forma **aditiva**: ningún export existente cambia de nombre ni de firma; `buttonClass` solo suma una variante. `tokens.css` no cambia (todas las clases usan tokens existentes).
>
> **Rutas:** las de «Archivos a crear/modificar» son relativas a `packages/ui/`, salvo las que empiezan con `docs/` (raíz del repo).

### Arquitectura del Servicio (`docs/architectures/ui/overview.md`, copiado)

Paquete `@nerdose/ui` (`packages/ui`): lo visual compartido entre `web` y `admin`. Contiene los tokens (`tokens.css` con `@theme`), los componentes compartidos, los helpers de clases `buttonClass` y `linkClass`, `cn()` y `track()`. Library en React 19 (TypeScript estricto), sin build propio: exporta su fuente. No importa `@nerdose/db`. Módulos: **tokens**, **components** (componentes compartidos de `web` y `admin`), **utils**.

### Convenciones de Código (`_base`, partes aplicables, copiadas)

- «**`components/`**: reusable pieces specific to the app. Anything shared by `web` and `admin` belongs in `@nerdose/ui`, not copied.»
- «Shared UI goes to `packages/ui`; if a component is needed in both apps, move it there instead of duplicating it.»
- Naming: archivos `kebab-case` (`form-field.tsx`), componentes `PascalCase`, tipos `PascalCase` sin `I`, constantes `SCREAMING_SNAKE_CASE`. «Component files export one main component; tests live next to the file as `*.test.tsx`.» (excepción ya aceptada en el repo: `icons.tsx` exporta tres; `form-field.tsx` exporta los tres campos, igual que en admin).
- Imports: externos y `@nerdose/*` primero; `import type` para tipos. En `ui` los imports internos son relativos (`'../cn'`, `'./focus'`), como el resto del paquete.
- «Default: no comments. Comment only the why when it is not obvious.»
- `ui` **no** importa `react-router`, `react-i18next`, `i18next`, `@nerdose/game-*` ni `@nerdose/db` (TS-57 existente).

### Convención `styling` (partes aplicables, copiadas)

- «Use only the tokens above (or later, the Design System's). No literal hex colors, no arbitrary `[#abc]` color values in components.»
- «Merge conditional classes with `cn()`; never concatenate class strings by hand.»
- «Focus is always visible: use `focus-visible:` rings with `--color-accent`; never `outline-none` without a replacement.»
- «State is never conveyed by color alone: pair it with an icon, text or pattern.»
- «Respect `prefers-reduced-motion`» (los componentes de este plan no animan).
- «Dark theme only … do not add `dark:` variants.»
- «**Static check:** component and web `.tsx` files must not contain arbitrary values (`/\[(\d|#|rgb)/`) nor generic utilities (`rounded-md`, `shadow-md`, `text-2xl`, `font-semibold`).»
- «Touch targets are at least 44 x 44 px.»

### Convención `accessibility` (partes aplicables, copiadas)

- «Use native elements first: `<button>`, `<a>`, `<input>`, `<label>`, `<table>`. Use ARIA only when no native element fits.»
- «Every input has a visible `<label>` or an `aria-label`; errors are tied with `aria-describedby`.»
- «Everything operable with the mouse is operable with the keyboard, in a logical tab order, with no keyboard traps.»
- «Provide a visible focus ring on every focusable element (`focus-visible`).»
- «No interactive element is built from a `<div>` or `<span>` with a click handler; use a native control.» (El overlay del diálogo es `role="presentation"`: el clic fuera es un atajo; el cierre accesible es `Escape` y el botón cerrar.)
- «Modal and overlay UI traps focus while open, closes with `Escape` and returns focus to the trigger.»
- «axe-core reports zero violations in unit checks and e2e page checks.»

### Convención `testing-unit` (partes aplicables, copiadas)

- «Query by role, label or visible text. `data-testid` only when no accessible query exists.»
- «Use `userEvent`, not `fireEvent`, for interactions.»
- «Each interactive component has an axe check; fix violations instead of disabling rules.»
- «No snapshot tests of large DOM trees.»
- «Test names state the behavior ("shows ... when ..."), not the implementation.»

- Los paquetes internos MUST llamarse `@nerdose/<nombre>` (`@nerdose/core`, `@nerdose/db`, `@nerdose/ui`, …).
- Las tareas (`build`, `lint`, `typecheck`, `test`) MUST orquestarse con Turborepo desde `turbo.json`.
- MUST NOT haber dependencias entre apps (`apps/*` no importa de otro `apps/*`). Lo compartido va en `packages/`.

**O-01 Anular desafío (verbatim lo aplicable):**
- Viewport `desktop` — «Modal centrado (6/12) sobre la pantalla de origen.»
- Layout `desktop · 1200px`: row `centrado` → col 3/12 vacía · **col 6/12** (desafio, campo-motivo, campo-culpable, resumen, alerta-conflicto, alerta-sistema, row `acciones` 6/12 + 6/12) · col 3/12 vacía. «`header` es marco de la pantalla y no se lista en el layout.»
- `header`: «Anular desafío», icono `close`, «`h2` del `dialog`».
- `campo-motivo`: label «Motivo de la anulación», obligatorio, hasta 500, placeholder «Ej.: definición incorrecta», error «Contá por qué se anula el desafío.»
- `campo-culpable`: label «Culpable del error», obligatorio, sin opción preseleccionada; error «Elegí el culpable del error.»
- Estado `loading`: «btn-cancelar: deshabilitado; Escape no cierra mientras se anula.» → `closeDisabled`.
- Accesibilidad: «Orden de foco: campo-motivo → campo-culpable → btn-cancelar → btn-anular.» «rol `dialog` con `aria-modal="true"`; el resumen está referenciado por `aria-describedby` del botón destructivo.» «atrapa el foco; Esc cierra (salvo en `loading`) y devuelve el foco al disparador.»

### Decisiones de este plan

- **D1 — Sin texto propio.** `Dialog` recibe `closeLabel: string` (obligatorio) para el `aria-label` del botón cerrar. `admin` pasará `"Cerrar"`; `web` pasará `t('…')`.
- **D2 — `required` explícito.** Los campos ponen `aria-required="true"` solo con `required` (prop propia, no el atributo HTML `required`, para no disparar la validación nativa del navegador; los formularios usan `noValidate`). En admin era siempre `true`.
- **D3 — `hint` opcional en los campos.** Texto de ayuda o contador (S-034: «0 / 1000»; O-01 admin: hasta 500) bajo el control, `font-sans text-caption text-text-dim`, con `id` propio. `aria-describedby` = `hint` y luego `error`, separados por espacio, solo los presentes.
- **D4 — `role` del diálogo.** `role?: 'dialog' | 'alertdialog'` (default `'dialog'`), para cubrir el precedente `surrender-dialog`.
- **D5 — Variante `error` de `buttonClass`.** Nombre igual a la UX (`btn-anular` `variant=error`). Mismo resultado visual que `dangerButtonClass` de admin: `bg-status-error text-status-error-on hover:bg-error font-bold`, tamaños y `fullWidth` como el resto; con `disabled` usa el neutro común.
- **D6 — Tabla como helper de clases.** `dataTableClass()` devuelve `{ region, table, th, td }` (cadenas). La semántica (`<table>`, `<caption>`, `scope`, `tabIndex`, `aria-label`) la arma el consumidor, igual que `buttonClass`/`linkClass` dejan el elemento al consumidor. Se exporta como función por el hallazgo 4.
- **D7 — Bottom-sheet fuera.** La variante mobile de S-034 queda para el plan `ui` de S-034.
