### Decisiones tomadas al planificar (modo automático)

1. **Píldora de racha solo en la home.** El CA-2 de la story dice "CUANDO abre cualquier ruta ENTONCES ve la píldora de racha". El DS (`app-header.md`: la píldora es parte de la variant `home`; Don't "No poner la píldora de racha en Stats"), el product-map ("Píldora de racha global (**solo en `home`**) → `estadisticas` (REQ-003)") y los screen.md de la revisión UX de REQ-003 (`acerca-de`, `no-encontrado`, `estadisticas`: "`app-header` variant `default` … **sin píldora de racha**") la limitan a la home, igual que el CA 5 del REQ ("CUANDO abre la home"). Gana el DS + UX. El `#número` sí se muestra en todas las rutas (los cuatro screen.md lo listan). El resto del CA-2 (link a `/stats`, `aria-label`, ocultar píldora y número si `GET /api/today` falla) se cumple tal cual. Conviene corregir la redacción del CA-2 en la story.
2. **Orden del header en mobile.** El product-map dice "marca y acciones en un renglón, nav en el siguiente". Con el orden del DOM del prototipo (marca → nav → acciones), que es también el orden de foco que piden `app-header.md` y `home.md` ("marca → `./juegos` → `./stats` → `./about` → píldora → ES/EN"), `flex-wrap` da marca / nav / acciones en 2-3 renglones según el ancho. Reordenar con `order` rompería el orden de foco y el de desktop. Se mantiene el orden del DOM; `home.md` ya admite "2-3 renglones".
3. **Ancho de las columnas "6/12" y "10/12" de los screen.md sin grilla de 12.** Los wireframes de `acerca-de` y `no-encontrado` usan fracciones de 12 columnas solo "para acotar el largo de línea"; el DS (`grid.md`) prohíbe la grilla de 12 y los breakpoints globales. Se resuelve con reglas intrínsecas y tokens existentes, documentadas en el DS (Tarea 7):
   - **404 y error de ruta:** panel centrado con `max-w-lede` (540 px, `--container-lede`, el único ancho de lectura del DS; ≈ 6/12 de 1176 px).
   - **Acerca de:** los 4 paneles en `flex flex-wrap gap-5` con `grow basis-130` (`flex: 1 1 520px`, la base de la columna de texto del hero del prototipo, L36-47) y `min-w-0`: 2 columnas a 1200 px (dos paneles de ~578 px ≈ 80 caracteres de Inter 15, el objetivo del "10/12"), 1 columna por debajo de 1124 px de viewport. El intro usa `max-w-lede`.
4. **Botón de la 404 de ancho completo en todos los anchos.** `no-encontrado.md` pide "ancho completo en mobile" y el código actual usa `w-full lg:w-auto`; sin prefijos `lg:` se usa `buttonClass({ fullWidth: true })` siempre, dentro de un panel de 540 px máximo (mismo criterio que el CTA de ancho completo al pie de la tarjeta, `button.md` → Spacing).
5. **Links dentro de prosa ("Wikipedia", "Wikidata", "CC BY-SA 4.0").** `link.md` exige que un link dentro de prosa se distinga por algo más que el color ("subrayado o 3:1 contra el texto vecino"; estética **Pendiente**). `#3DDC84` contra la prosa `#A9B4BF` da 1,2:1, así que se deriva la variant `inline`: hereda la fuente del párrafo (Inter), color `accent.brand`, subrayado de 1 px con offset de 4 px, hover `accent.brand.hover`, foco del DS. El link "Volver a los juegos" sí va sin subrayado (`linkClass()`), que es la desalineación "Links" del CHANGELOG.
6. **Paneles de "Acerca de" y la 404 sin etiqueta `// …`.** `panel.md` recomienda empezar con la etiqueta-comentario, pero los screen.md no la definen y REQ-003 alinea "sin cambiar contenido". Se usan `Panel` con `title` (h2) en "Acerca de" y con el `h1` como contenido en la 404, sin copy nuevo.
7. **Footer.** El DS deja **Pendiente** la ubicación del aviso de privacidad y de "Acerca de" (`site-footer.md`); los screen.md la resuelven: "el lema a la izquierda y `exit 0` a la derecha; debajo, el aviso de privacidad y el enlace «Acerca de», todo en Mono 13 gris". El dominio `nerdose.dev` (texto actual del footer) **se quita**: no está en el prototipo ni en los screen.md. "Acerca de" usa `linkClass({ tone: 'subtle' })` con `→` decorativo (`link.md`: "Siempre con `→`").
8. **`index.css`** (listado en la story): suma `@layer base { html { @apply bg-bg; color-scheme: dark; } }` para que el fondo fuera del shell (rebote de scroll, error de ruta) sea el del DS y los controles nativos (scrollbar) se vean oscuros. Sin `--color-` literal (lo prohíbe `styles.test.ts`).
9. **Padding vertical de `main`:** home `64/48` (`layout.page.padding.home`, L34); resto de las pantallas de plataforma `48/56` (`layout.page.padding.stats`, L301; "Acerca de" y la 404 no existen en el prototipo y toman el de la otra pantalla de plataforma). El `gap` de 72 px entre secciones de la home es de S-013.
10. **Playwright.** `apps/web` no tiene suite e2e. El "sin scroll horizontal a 320 px" (CA-8) se cubre con guardas estáticas (sin prefijos responsive, sin anchos fijos, `min-w-0` en hijos flex) y una verificación manual documentada (TS-49). Montar Playwright queda fuera de esta story.
11. **Discrepancia menor de UX:** `no-encontrado.md` anota el título como "Mono 800"; `type.title.page` es Mono **700** (`typography.md`). Gana el DS; conviene limpiar la anotación.

### Convenciones de Código (`_base`, copiadas lo aplicable)

- Archivos `kebab-case`; componentes exportados `PascalCase`; hooks `use-*` → `useX`; constantes `SCREAMING_SNAKE_CASE`; campos de la API en `snake_case` tal cual; tests al lado del archivo (`*.test.tsx`).
- **Imports:** absolutos con `@/*`. Orden: (1) librerías externas y `@nerdose/*`, (2) `@/`, (3) relativos de la misma carpeta; línea en blanco entre grupos; tipos con `import type`.
- Un módulo no importa internals de otro: usa su `index.ts`. `app/` solo cableado. `lib/` sin JSX.
- Comentarios: por defecto ninguno; solo el porqué no obvio. Sin `// TODO` sin issue.

### Convención `styling` (partes aplicables, verbatim)

**Rules:**
- Use only the tokens above (or later, the Design System's). No literal hex colors, no arbitrary `[#abc]` color values in components.
- Tokens live only in `packages/ui`; `web` and `admin` must not redeclare them.
- Inter for prose, JetBrains Mono for everything else (`foundations/typography.md`), both via `@fontsource/*`, self-hosted. No Google Fonts or other external font requests.
- Merge conditional classes with `cn()`; never concatenate class strings by hand.
- Text and interactive-element contrast meets WCAG 2.1 AA against the surface it sits on (4.5:1 text, 3:1 large text and UI components). Verify any new color pair.
- Focus is always visible: use `focus-visible:` rings with `--color-accent`; never `outline-none` without a replacement.
- State is never conveyed by color alone: pair it with an icon, text or pattern (see `accessibility`).
- Respect `prefers-reduced-motion`: animations are disabled or reduced under it.
- No CSS-in-JS and no component CSS files, except the token file and third-party overrides.

**Dark theme only:** "The product is dark. There is no light theme and no theme switcher in v1. Tokens are defined once on `:root`; do not add `dark:` variants."

**Updates from REQ-003 (alignment with the Design System 1.0.0+):**
- **Responsive design:** no global media queries. Layout uses `flex-wrap` and `repeat(auto-fit, minmax(min(300px, 100%), 1fr))`; only the 320 px adaptations documented in the Design System are allowed. Page container is `max-w-page` (1240 px) with a 32 px gutter.
- **Buttons and links:** `@nerdose/ui` exports the class helpers `buttonClass({ variant, size, game?, fullWidth?, disabled? })` and `linkClass({ tone? })`, so they apply both to `<button>` and to router `<Link>` without `@nerdose/ui` importing `react-router`.
- **Static check:** component and web `.tsx` files must not contain arbitrary values (`/\[(\d|#|rgb)/`) nor generic utilities (`rounded-md`, `shadow-md`, `text-2xl`, `font-semibold`).

> La sección general "Responsive design" de la convención todavía dice "use `sm:`/`md:`/`lg:`"; la actualización de REQ-003 la reemplaza. Este plan no usa prefijos responsive en ningún archivo que toca.

### Convención `accessibility` (partes aplicables, verbatim)

- One `<main>` per page, landmarks for header/nav/footer, one `<h1>` per screen, headings in order.
- Use native elements first: `<button>`, `<a>` […]. Use ARIA only when no native element fits.
- Provide a visible focus ring on every focusable element (`focus-visible`).
- Result, errors and notices appear in `role="status"` (polite) or `role="alert"` (errors) regions.
- On navigation, move focus to the new page heading and update `document.title`.
- Honor `prefers-reduced-motion`.
- Touch targets are at least 44 x 44 px. Layout reflows at 320 px without horizontal scroll and supports 200% text zoom.
- Every image or icon is either decorative (`aria-hidden`) or has an accessible name.
- Color is never the only carrier of meaning.
- axe-core reports zero violations in unit checks and e2e page checks.
- Language is declared (`<html lang>`) and updated when the locale changes.

### Convención `routing` (lo aplicable, verbatim)

- All routes are declared in `src/app/router.tsx`; no routes defined elsewhere.
- Use `<Link>` / `useNavigate`, never `window.location` for in-app navigation.
- On route change, move focus to the page `<h1>` (or the `main` landmark) and update `document.title`.
- Route-level errors render through `errorElement` (see `error-handling`).
- Links to external sites use `rel="noopener noreferrer"`.

### Convención `i18n` (lo aplicable, verbatim)

- Every UI string goes through `t()`; no hardcoded user-facing literals in components.
- Every key exists in both `es` and `en`; a missing key fails the unit test that compares both resource trees.
- Never build sentences by concatenating translated fragments; use interpolation.
- Keys are nested by module (`catalog.title`, `stats.streak`) […]. Plurals and interpolation use i18next (`t('stats.days', { count })`), never string concatenation.

### Convención `error-handling` (lo aplicable, verbatim)

- Every route has an `errorElement`; a render error never leaves a blank page.
- Never show stack traces, raw JSON or internal details to the player.
- Every error state has a way forward: retry, go home, or an explanatory message.
- Error messages are announced to assistive tech (`role="alert"` or an `aria-live` region) and do not rely only on color.

### Convención `data-fetching` (lo aplicable, verbatim)

- Server data lives in TanStack Query. Never copy query results into `useState` or a context.
- Query keys come from per-module factories, never inline string literals repeated across files.

### Convención `testing-unit` (partes aplicables)

- Query by role, label or visible text. `data-testid` only when no accessible query exists.
- Use `userEvent`, not `fireEvent`, for interactions.
- Each interactive component has an axe check; fix violations instead of disabling rules.
- Fixtures use the API's `snake_case` names. Mock the network with MSW, never the app's own modules.
- No snapshot tests of large DOM trees. Tests do not rely on the real date or timers.
- Test names state the behavior ("shows ... when ..."), not the implementation.
