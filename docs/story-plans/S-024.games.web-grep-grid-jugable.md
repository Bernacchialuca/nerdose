### Arquitectura del Servicio (`docs/architectures/games/overview.md`, copiado)

- **Propósito:** Los cinco paquetes de juego `packages/games/<game_id>`. Cada uno implementa el contrato `GameDefinition` de `@nerdose/core` y expone tres entradas separadas: `./definition` (servidor: la usa la `api`), `./client` (React: `Instructions`, `Game`, `Result` y `share()`; la usan `web` y `admin`) y `./generator` (`generate` y `verify`; lo usa el `generator`). ADR-003 y ADR-006.
- **Convenciones por entrada:** `client` sigue `styling`, `accessibility`, `testing-unit` y `game-clients`. `game-package` es propia (estructura, las tres entradas y qué puede importar cada una).

### Convención `game-package` (partes aplicables, copiadas)

```

│   ├── client/       # React UI: Instructions, Game, Result, share()
│   │   ├── index.ts

│   ├── generator/
```

| Entry | May import | Must not import |
|---|---|---|
| `./client` | `@nerdose/core` (`.`), `zod`, `react`, `@nerdose/ui`, `shared/`, types from `./definition` | `@nerdose/polyglot`, `node:*`, `@nerdose/core/notify`, `./generator`, runtime code of `./definition` that carries solutions |

**Rules (aplicables, verbatim):**
- `exports` contains exactly `./definition`, `./client` and `./generator` (code entries). No default entry.
- `moveSchema` is the single schema used by `web` (before sending) and by `api` (validation); a parse failure is `422 invalid_move`.
- `share(result, number)` never includes the solution and ends with `nerdose.dev`.
- `./definition` and `./client` never import `@nerdose/polyglot`, `node:child_process` or anything that executes code.

**Interpretación para este plan (igual que Devdle):** `src/definition/schemas.ts` no lleva solución (schemas Zod y `WORDS_COUNT`), así que el client **puede** importarlo en runtime. El client **no** importa `src/definition/index.ts` (el objeto `grepGrid`, con `applyMove`/`result`) ni ningún `test-fixtures.ts`. De `src/shared/geometry.ts` usa solo `GRID_SIZE`, `sameCell` y el tipo `Cell`: **no** usa `lineCells`/`directionOf` para decidir si una selección es válida (NFR-S02: decide el servidor).

### Convención `game-clients` (copiada)

- Every game provides its own UI in `packages/games/<game_id>/client` (ADR-006). The app keeps a **registry** that maps `game_id` to that entry, and the shell talks to every game through the same contract. Adding a game means adding a package and a registry line.
- `GameClient` is the shape of the `./client` entry: React components `Instructions`, `Game`, `Result` and `share(result, number): string`. The exact props of those components are owned by the game packages; the app passes them through and does not reinterpret them.
- The host fetches the public view and the play state with TanStack Query (`/api/games/{game_id}/today`), then hands them to the client components. Moves go through the game's `moveSchema` (Zod) before `POST .../move`.
- `share(result, number)` produces the text. The shell calls `navigator.share({ text })` or `navigator.clipboard.writeText`, then `track('share:<game_id>')`.
- **Rules:** The shell renders games only through `Instructions`, `Game`, `Result` and `share`; it does not read game-specific fields. The `client` never receives the solution before the round ends in `web`. Share text is never built by the shell. Validate every move with the game's `moveSchema` before sending, and still handle `422 invalid_move` from the `api`. Adding a game must require only a new package, a registry line and its translations.

### Convención `i18n` de `web` (partes que fijan el contrato del client, copiadas)

- i18next translate only the **UI texts**. Challenge content (definitions) arrives **already resolved in the player's locale** from the `api`.
- "Game packages ship their own UI strings through the same i18n instance (a namespace per game, e.g. `devdle`)."
- **Rules:** Every UI string goes through `t()`. Every key exists in both `es` and `en`; a missing key fails the unit test that compares both resource trees. Never translate content from the `api`. Never build sentences by concatenating translated fragments; use interpolation. Do not translate error codes; branch on codes and show the `api`'s message or a UI key.

### Convención `styling` (partes aplicables, copiadas)

- Tailwind CSS v4 con tokens en `@theme` de `@nerdose/ui` (`tokens.css`). **Tokens live only in `packages/ui`**.
- **Rules:** Use only the tokens. No literal hex colors, no arbitrary `[#abc]` values. Merge conditional classes with `cn()`. Contrast WCAG 2.1 AA. Focus always visible (`focus-visible:` rings); never `outline-none` without replacement. State is never conveyed by color alone. Respect `prefers-reduced-motion`. No CSS-in-JS, no component CSS files.
- **Values from data:** CSS variable via `style={{ '--x': … }}` consumed by a class (`text-(length:--x)`, `p-(--x)`).
- **REQ-003:** no global media queries; layout con `flex-wrap`. **Static check:** `.tsx` sin `/\[(\d|#|rgb)/` ni `rounded-md`, `shadow-md`, `text-2xl`, `font-semibold`.
- Per-game accent applied by the game's `client` via its token.

### Convención `accessibility` (copiada, partes aplicables)

- One `<h1>` per screen, headings in order. Native elements first. ARIA only when no native element fits.
- Everything operable with the mouse is operable with the keyboard; visible focus ring on every focusable element.
- Feedback that uses color is also expressed with an icon, pattern or text, and exposed to screen readers as text.
- Result, errors and notices appear in `role="status"` or `role="alert"` regions.
- Touch targets ≥ 44 × 44 px (excepción aceptada por la story para la grilla a 320 px, CA-13). Layout reflows at 320 px without horizontal scroll.
- **Rules:** no interactive element built from `<div>`/`<span>` with a click handler; every icon decorative (`aria-hidden`) or named; **each of the 5 games can be completed with the keyboard alone (NFR-U03)**; dynamic updates announced via live regions, focus not moved unexpectedly; axe-core reports zero violations.

### Manejo de errores (aplicable al client)

- El client **no hace requests**. Recibe `moveError: { code, message } | null` (web lo memoiza por identidad: `toMoveError` en `apps/web/src/modules/game-host/game-view.ts`, con `INLINE_MOVE_ERRORS = ['not_in_word_list', 'rate_limited', 'invalid_move', 'validation_error']`). Grep Grid ramifica por `code`: `invalid_move` → `hint.invalidMove`; `rate_limited` → `hint.rateLimited`; cualquier otro → `hint.message` con el `message` tal como llegó.
- `feedback` llega como `unknown | null` y se parsea con `feedbackSchema` (`nullable`).
- Datos con forma inválida (`publicView`, `state`, `feedback`, `result`) → `ZodError` que captura el error boundary de la ruta en `web`. Es error de contrato, no estado de pantalla.

### ADRs Relevantes

#### ADR-006: Contrato `GameDefinition` y juegos como paquetes enchufables

- **Decisión:** cada juego es un paquete `packages/games/<game_id>` con tres entradas; `./client` expone `Instructions`, `Game`, `Result` y `share(result, number): string`.
- **Reglas de Implementación (verbatim):**
  - Cada juego MUST vivir en `packages/games/<game_id>`, con `game_id` ∈ `devdle | grep-grid | timeline | big-o | bug-hunt`.
  - La entrada `./definition` MUST exportar un objeto que implemente `GameDefinition` de `@nerdose/core`, con todos los métodos de la interfaz.
  - Las rutas de juego de la `api` MUST resolver el juego por el registry. MUST NOT haber `if (game_id === '…')` ni `switch` por juego en `apps/api` ni en el shell de `apps/web`.
  - La `api` MUST NOT serializar `challenges.payload` en ninguna respuesta de jugador. Antes de terminar la Play solo puede responder `toPublic(payload)`; después, `result(payload, state)`.
  - `toPublic` MUST NOT incluir: la palabra de Devdle, `placements` de Grep Grid, `correct_order`/`event_date`/`fact_id` de Timeline, `answer` de Big O, ni `bug_node_id`/`failing_test`/`fix`/`line_of`/`mutation` de Bug Hunt.
  - Cada juego MUST tener un test de contrato anti-spoiler: se serializa `toPublic(payload)` y toda respuesta pre-resultado, y se verifica que no contienen ningún valor de la solución.
  - `moveSchema` MUST usarse tanto en `web` (antes de enviar) como en la `api` (`@hono/zod-validator`). Si el parse falla, la respuesta es `422 invalid_move`.
  - `share(result, number)` MUST NOT incluir la solución y MUST terminar en `nerdose.dev`.
  - `generate` MUST ser determinista: el mismo `{ date, seed, history }` da el mismo `Payload`. MUST NOT usar `Math.random()` ni la hora actual.
  - `Payload` MUST incluir todos los textos que lee el jugador como `{ es, en }`. `verify` MUST fallar si falta algún idioma.
  - Sumar un juego MUST requerir solo crear su paquete y registrarlo en los tres registries, sin cambiar rutas, tablas ni lógica de rachas.

#### ADR-002: Stack tecnológico (reglas aplicables, verbatim)

- Todo el código propio MUST ser TypeScript con `strict: true`. MUST NOT haber archivos `.js` de código fuente en `apps/` ni en `packages/`.
- Los estilos MUST ser Tailwind CSS v4, con los tokens en `@theme`. MUST NOT cargarse fuentes ni CSS de CDNs de terceros.
- Los textos de UI MUST pasar por i18next con claves en `es` y `en`. Los textos de contenido MUST venir resueltos desde la `api`.
- Los tests MUST usar Vitest; los e2e, Playwright.

#### ADR-003: Monorepo y paquetes compartidos (reglas aplicables, verbatim)

- Los paquetes internos MUST llamarse `@nerdose/<nombre>` (… `@nerdose/game-<game_id>`).
- Las tareas (`build`, `lint`, `typecheck`, `test`) MUST orquestarse con Turborepo desde `turbo.json`.

#### ADR-014: Métricas y analítica (regla que acota al client)

- `web` MUST llamar solo a `track(event)` de `@nerdose/ui`; el evento de share MUST llamarse exactamente `share:<game_id>`. → El client **no** llama a `track()`: `share()` solo devuelve el texto.

### API Context

El client no llama a la `api`. Recibe por props lo que `web` obtiene (`docs/apis/api.yaml`, copiado):

**`GET /api/games/{game_id}/today?lang` → `200 GameToday`** `{ game_id, date, number, challenge_status, public_view, play, result, game_stats }`. `play == null` → `Instructions`; `play.status == in_progress` → `Game` con `play.state`; terminada → `Result`.

**`POST /api/games/{game_id}/today/move?lang` `{ challenge_number, move }` → `200 MoveResponse`** `{ feedback, play: { status, state, score }, result, streaks, game_stats }` (`result`, `streaks`, `game_stats` solo si cerró). `web` hace `setQueryData` con `play` (y `result`/`game_stats` si cerró) y **no** toca `public_view`: por eso la definición de una palabra recién encontrada llega solo por `feedback`.

**Schemas de Grep Grid (`api.yaml`, copiados):**

**Schemas Zod del paquete (`src/definition/schemas.ts`, copiados — los usa el client):**
```ts
export const WORD_PATTERN = /^[A-Z]{4,12}$/;
export const WORDS_COUNT = 8;
export const cellSchema = z.object({ row: z.number().int().min(0).max(11), col: z.number().int().min(0).max(11) });
export const moveSchema = z.discriminatedUnion('type', [
  z.object({ type: z.literal('select'), from: cellSchema, to: cellSchema }),
  z.object({ type: z.literal('give_up') }),
]);
export const stateSchema = z.object({ found_words: z.array(z.object({ term_id: idSchema, cells: z.array(cellSchema) })).max(8), gave_up: z.boolean() });
export const publicViewSchema = z.object({ grid: gridSchema /* 12×12 /^[A-Z]$/ */, words: z.array(z.object({ term_id: idSchema, word: z.string(), definition: z.string().optional() })).length(8) });
export const feedbackFoundSchema = z.object({ found: z.literal(true), term_id: idSchema, word: z.string(), definition: z.string(), cells: z.array(cellSchema) });
export const feedbackNotFoundSchema = z.object({ found: z.literal(false), reason: z.enum(['not_a_word', 'already_found']) });
export const feedbackSchema = z.union([feedbackFoundSchema, feedbackNotFoundSchema]).nullable();
export const resultSchema = z.object({ win: z.boolean(), score: z.number().int().min(0).max(8), gave_up: z.boolean(), words: z.array(z.object({ term_id, word, definition, found: z.boolean(), cells: z.array(cellSchema) })).length(8) });
// Tipos: GrepGridMove, GrepGridState, GrepGridPublicView, GrepGridFeedback, GrepGridResult
```
- `idSchema = z.string().min(1)` (no valida uuid). `result.win` es `true` solo con `score === 8`; rendirse da `win: false`, `gave_up: true`, `score` 0–7.

**Errores de `POST …/move` que `web` pasa como `moveError` (catálogo ADR-015):**
- `422 invalid_move` — selección en reversa, no alineada, de una celda o fuera de 0–11; la partida no cambia.
- `429 rate_limited` — mensaje genérico; la jugada no se procesa.
- `401 no_session`, `409 game_finished`, `409 challenge_expired`, `409 challenge_voided` → **los resuelve `web`** (banner cookies, refetch → resultado, instrucciones con «día nuevo», `locked` + `alerta-anulado`).

### Flow Context

**`abrir-y-retomar-juego` (pasos que tocan al client):**
- `public_view` de grep-grid: `{ grid: string[12][12], words: [{ term_id, word, definition? }] ×8 }` — `definition` solo en las palabras ya encontradas (`term_id` presentes en `plays.state.found_words`), en el locale resuelto; nunca en las no encontradas ni sin Play.
- `state` inicial: `{ found_words: [], gave_up: false }`.
- "En Grep Grid, al retomar o al cambiar de idioma, las definiciones de las palabras encontradas salen de `public_view.words[].definition`; `plays.state.found_words` guarda solo `{ term_id, cells }` (REQ-005)."

**`jugada-y-cierre-de-partida` (copiado):**
- Move grep-grid: `{ "type": "select", "from": { "row", "col" }, "to": { "row", "col" } }` o `{ "type": "give_up" }`.
- "Jugada válida sin cambio de estado (solo Grep Grid): una línea válida hacia adelante que no coincide exactamente con una de las 8 palabras (`feedback.reason = 'not_a_word'`) o una palabra ya encontrada (`feedback.reason = 'already_found'`) devuelven el mismo `state`. No son errores: la respuesta es `200`, sin penalización."
- "`move.type = 'select'`: si `from` y `to` coinciden exactamente con la primera y la última celda de una palabra no encontrada, se agrega `{ term_id, cells }` al final de `state.found_words` y `feedback.definition` va en `ctx.locale`. `move.type = 'give_up'`: `state.gave_up = true` y `feedback = null`."
- "`isFinished(state) = state.gave_up || state.found_words.length === 8`: la octava palabra cierra `won` con `score = 8`; `give_up` cierra `lost` con `score = found_words.length` (0–7) … `result` trae `gave_up: true` y las 8 `words` con `found` y `cells`."
- Fila 2 de errores: "Inválida para el estado (selección en reversa, no alineada o de una sola celda en Grep Grid …) | 422 | `invalid_move` | web muestra el error; nada cambia".

**`preferencias-y-share` (copiado):**
- Paso 2: "En Grep Grid a mitad de partida, `public_view.words[].definition` de las palabras ya encontradas vuelve en el idioma nuevo; `grid`, `words` y `found_words` no cambian."
- Paso 3: "Grep Grid (sin las palabras ni indicio de rendición): `🔎 Grep Grid #8` / `5/8` / `nerdose.dev`". `share()` del client; `navigator.share` / portapapeles y `track` los hace `web`.

**Cambios que introduce esta story en el client:** consume `feedback` (nuevo en `GameProps`) para tachar, pintar, definir y anunciar sin esperar un refetch; arma `term_id → definition` desde `public_view.words[].definition` y lo completa con cada `feedback.found` (CA-7).
