## Referencia de la Story

- **Story:** [S-034](../stories/S-034.web-reportar-problema-desafio-anulado.md)
- **Servicio:** ui
- **Resumen:** Completa el `Dialog` de `@nerdose/ui` (`packages/ui`) con las tres piezas que la UX de O-01 y O-02 pide y que el plan `web` de S-034 (Done, `8354ff6`) dejó explícitamente **pendientes de `ui`** (su decisión D2): (1) una variante `sheet` que se ancla al borde inferior en mobile y es un modal centrado en desktop, (2) `aria-describedby` hacia el contenido que describe el diálogo (aviso anti-spoiler de O-01, texto de O-02) y (3) el contenido de fondo `inert` mientras el diálogo está abierto. Después actualiza los dos consumidores de `web` (cambio de una o dos líneas cada uno, como pactó D2) y la documentación de código reutilizable.

> **Alcance de este plan:** `packages/ui` (servicio `ui`) más el **ajuste mínimo de los dos consumidores** en `apps/web/src/modules/game-host/components/` (`report-dialog.tsx`, `voided-notice-dialog.tsx`) y sus tests. >
> **Regla de compatibilidad (no negociable, igual que S-011, S-021, S-024, S-029 y S-033):** la API pública crece de forma **aditiva**. `variant` suma `'sheet'`; `describedBy` es opcional. Los tests existentes de `Dialog` (S-033 TS-4 a TS-8) pasan **sin cambios**. `web`, `admin` y los clients de los juegos siguen compilando y pasando sus tests. `tokens.css` no cambia.
>
> **Rutas:** en «Archivos a crear/modificar», las rutas son relativas a `packages/ui/`, salvo las que empiezan con `apps/web/` o `docs/` (raíz del repo).

### Estado actual del `Dialog` (verificado en `packages/ui/src/components/dialog.tsx`)

```tsx
export type DialogProps = {
  variant: 'modal' | 'drawer';
  title: ReactNode;
  closeLabel: string;
  onClose: () => void;
  closeDisabled?: boolean;
  role?: 'dialog' | 'alertdialog';
  initialFocusRef?: RefObject<HTMLElement | null>;
  titleRef?: RefObject<HTMLHeadingElement | null>;
  children: ReactNode;
};
```

- `FOCUSABLE = 'a[href], button:not([disabled]), textarea:not([disabled]), input:not([disabled]), select:not([disabled]), summary, [tabindex]:not([tabindex="-1"])'`.
- Un `useEffect([initialFocusRef])`: guarda `document.activeElement`, enfoca `initialFocusRef.current ?? closeRef.current`; el cleanup devuelve el foco al elemento guardado.
- `close()` llama `onClose` salvo `closeDisabled`. `onKeyDown` en el overlay: `Escape` → `stopPropagation()` + `close()`; `Tab` / `Shift+Tab` cicla entre el primer y el último focusable del panel.
- Overlay: `<div role="presentation">` con `cn('fixed inset-0 bg-header', drawer ? 'z-40' : 'z-50 flex items-center justify-center px-4')`; clic con `event.target === event.currentTarget` → `close()`.
- Panel: `<div role={role} aria-modal="true" aria-labelledby={titleId}>` con `cn('flex flex-col gap-5 border border-border bg-surface p-6', drawer ? 'fixed inset-y-0 right-0 w-full max-w-5xl overflow-y-auto' : 'max-h-full w-full max-w-xl overflow-y-auto rounded-panel')`.
- Cabecera: `<h2 id={titleId} ref={titleRef} tabIndex={-1} className="font-mono text-title-panel text-text">` + botón `✕` (`aria-hidden`) con `aria-label={closeLabel}`, `aria-disabled={closeDisabled || undefined}`, `buttonClass({ variant: 'icon', disabled: closeDisabled })`.
- **Lo que le falta frente a la UX** (D2 del plan `web`): no tiene anclaje inferior en mobile, no acepta `aria-describedby`, no pone el fondo `inert`.

**Consumidores actuales de `Dialog` de `@nerdose/ui`:** solo `apps/web/src/modules/game-host/components/report-dialog.tsx` (O-01, `variant="modal"`, `initialFocusRef={selectRef}`, `closeDisabled={pending}`) y `voided-notice-dialog.tsx` (O-02, `variant="modal"`, `role="alertdialog"`, `closeDisabled={pending}`). `apps/admin` importa `@/components/dialog` (copia local) y **no** se ve afectado.

### Convención `styling` (partes aplicables, copiadas)

- «Use only the tokens above (or later, the Design System's). No literal hex colors, no arbitrary `[#abc]` color values in components.»
- «Merge conditional classes with `cn()`; never concatenate class strings by hand.»
- «Focus is always visible: use `focus-visible:` rings with `--color-accent`; never `outline-none` without a replacement.»
- «Respect `prefers-reduced-motion`: animations are disabled or reduced under it.»
- «**Mobile-first from 320 px** (NFR-U01): base classes target the smallest screen; use `sm:`/`md:`/`lg:` to add layout for larger ones. No horizontal scroll at 320 px (WCAG reflow).» · «Touch targets are at least 44 x 44 px.»
- Actualización REQ-003: «no global media queries. Layout uses `flex-wrap` and `repeat(auto-fit, minmax(min(300px, 100%), 1fr))`; only the 320 px adaptations documented in the Design System are allowed.» · «**Static check:** component and web `.tsx` files must not contain arbitrary values (`/\[(\d|#|rgb)/`) nor generic utilities (`rounded-md`, `shadow-md`, `text-2xl`, `font-semibold`).»

> Ver D3: la variante `sheet` usa **un** prefijo `sm:` local al componente (no un breakpoint global de layout). Es la única forma de que un mismo panel sea bottom-sheet en mobile y modal centrado en desktop, que es exactamente lo que la UX fija.

### Convención `accessibility` (partes aplicables, copiadas)

- «Modal and overlay UI traps focus while open, closes with `Escape` and returns focus to the trigger.»

### Decisiones de este plan

- **D1 — Variante nueva `sheet`, no un prop booleano.** `variant: 'modal' | 'drawer' | 'sheet'`. `sheet` = bottom-sheet en mobile + modal centrado (idéntico a `modal`) desde `sm`. `modal` no cambia (O-02 es «modal (ambos viewports)»), `drawer` no cambia. Así el contrato existente queda intacto (S-033 TS-4…TS-8 pasan sin tocarse).
- **D2 — Clases de `sheet` (mobile-first, solo tokens):**
  - Overlay: `fixed inset-0 z-50 flex items-end justify-center bg-header pt-12 sm:items-center sm:px-4 sm:pt-0`. El `pt-12` (48px) deja visible el scrim arriba del sheet para que se lea como capa y se pueda tocar para cerrar.
  - Panel: `flex flex-col gap-5 border border-b-0 border-border bg-surface p-6 max-h-full w-full overflow-y-auto rounded-t-panel sm:max-w-xl sm:rounded-panel sm:border-b`. En mobile ocupa el ancho completo, esquinas superiores de radio 14 (`radius.panel`) y sin borde inferior (está pegado al borde de la pantalla); desde `sm` es exactamente el panel de `modal` (`max-w-xl rounded-panel` con borde completo).
  - Sin sombra (elevation: «No agregar sombras a […] paneles») y sin animación (motion: «`motion.transition` ninguna»).
  - Las clases se arman con `cn()` por variante (tabla `VARIANT_CLASSES` u objeto equivalente), nunca concatenando strings.
- **D3 — Un único corte local `sm:` (640px).** El panel modal mide `max-w-xl` = 576px + `px-4` × 2 = 608px de ancho útil: por debajo de 640px el modal ya ocupa casi todo el ancho, que es justo donde la UX quiere el bottom-sheet. El viewport UX `mobile` (400px) cae en sheet; `desktop` (1200px) en modal. No es un breakpoint global de layout (la página sigue sin media queries): es un cambio de anclaje de un overlay, del mismo tipo que las «adaptaciones requeridas» que el DS admite por componente. Queda registrado como gap **nuevo** para el DS.
- **D4 — `describedBy?: string`** (id del elemento que describe el diálogo) → `aria-describedby={describedBy}` en el panel; sin el prop, el atributo **no** se renderiza. `Dialog` no inventa texto ni ids: el consumidor genera el id con `useId()` y lo pone en un contenedor de lo que describe (`Banner` no acepta `id`, se envuelve en un `<div id>`). En O-01 solo se pasa cuando `from === 'game'` (aviso visible); en O-02 apunta al párrafo `texto` («El texto de racha protegida se lee primero»; patrón ARIA de `alertdialog`).
- **D5 — Fondo `inert` dentro del `Dialog`, sin portal.** `Dialog` no se porta a `document.body` (los consumidores lo montan en su árbol, p. ej. `GameRoute` después del `switch`). Al montar, recorre desde el overlay hasta `document.body` y pone el atributo `inert` en **cada hermano** de cada ancestro (y del propio overlay), salvo los que ya lo tenían; guarda la lista y al desmontar quita `inert` solo de esos. Así queda inerte todo lo de afuera (header, partida, footer) y nunca el diálogo ni sus ancestros. Se usa `setAttribute('inert', '')` / `removeAttribute('inert')` (independiente de si jsdom implementa la propiedad `HTMLElement.inert`). Se ignoran los `<script>`/`<style>` (no son contenido).
- **D6 — Orden en el cleanup: primero quitar `inert`, después devolver el foco.** Un elemento `inert` no puede recibir foco en el navegador; si el foco vuelve al disparador antes de quitar `inert`, se pierde. Por eso `inert` y foco se manejan en **un mismo `useEffect`** (o en dos, con el de `inert` declarado de forma que su cleanup corra antes): al montar, aplicar `inert` y enfocar `initialFocusRef ?? closeRef`; al desmontar, restaurar `inert` y recién después `previous.focus()`. Compatible con `StrictMode` (montar–desmontar–montar deja el mismo estado).
- **D7 — Alcance `web`:** solo los dos cambios pactados en D2 del plan `web` — `ReportDialog`: `variant="sheet"` + `describedBy` del aviso; `VoidedNoticeDialog`: `describedBy` del texto (sigue `variant="modal"`). No se toca la lógica, los textos ni el orden de los botones. Los tests de `web` que ya existen deben seguir pasando; se agregan solo los escenarios de este plan.
- **D8 — Fuera de alcance (registrado):** íconos `WarningIcon`/`InfoIcon` (D6 del plan `web`: se resolvió sin ícono), migrar `SurrenderDialog` (O-04) o la copia local de `admin` al `Dialog` compartido (seguimientos recomendados, no pedidos por la story), safe-area inferior de iOS (requeriría un valor arbitrario `env(safe-area-inset-bottom)`, prohibido por la guarda estática; el `p-6` del panel deja 24px sobre el borde).

  function makeOutsideInert(node: HTMLElement): () => void {
    const marked: Element[] = [];
    let current: Element = node;
    while (current.parentElement && current !== document.body) {
      const parent = current.parentElement;
      for (const sibling of Array.from(parent.children)) {
