# Story Plan: S-011 (web) - Fundamentos visuales y componentes de @nerdose/ui

## Status

**Status:** Completed

## Referencia de la Story

- **Story:** [S-011](../stories/S-011.fundamentos-visuales-ui.md)
- **Servicio:** web
- **Resumen:** `apps/web` adopta los fundamentos visuales que `@nerdose/ui` ya publicó (plan `S-011.ui`, completado): carga Inter 400/700 y JetBrains Mono 800 self-hosted, pasa a Inter como fuente base de la página con JetBrains Mono declarado pieza por pieza, elimina `components/cta.ts` migrando sus usos a `buttonClass` / `linkClass` de `@nerdose/ui`, y extiende `styles.test.ts` para que rechace hex, valores arbitrarios y utilidades genéricas en los `.tsx` de `apps/web/src`.

> **Alcance de este plan:** solo el servicio `web`, y solo lo que la story S-011 le asigna: `@fontsource/inter`, imports de Inter 400/700 y Mono 800, `font-sans` como base (con `font-mono` en cada pieza de interfaz que hoy existe), eliminación de `components/cta.ts` y extensión de `styles.test.ts`. **No** se re-estructura ninguna pantalla: el shell (header con píldora, nav siempre en el header, selector segmentado, footer, layout 1240/32, textura, banner O-03, "Acerca de", 404 y error de ruta con `Panel`) es de **S-012**; la home (hero con terminal, tarjetas con miniatura/badge/`next`/placeholder, "Tu progreso", "Cómo funciona", ancla `#como`) es de **S-013**.
>
> **Regla de compatibilidad:** los tests de comportamiento de REQ-002 (sesión, idioma, cookies bloqueadas, cuenta regresiva, estados de la home, 404) siguen pasando. Solo se ajustan las aserciones que fijan una clase que este plan cambia a propósito (fuente del shell, alto del CTA del hero) y se dice cuál en cada tarea.

### Convención `styling` (partes aplicables, copiadas verbatim)

**Package:**
```
tailwindcss                  # v4
@tailwindcss/vite            # Vite plugin
@fontsource/inter            # self-hosted prose font (400, 700)
@fontsource/jetbrains-mono   # self-hosted font (400, 500, 700, 800)
clsx                         # conditional classes
tailwind-merge               # conflict-free class merging
```

**Setup:**
```css
/* src/index.css */
@import 'tailwindcss';
@import '@nerdose/ui/tokens.css';   /* the @theme block */
@import '@fontsource/jetbrains-mono/400.css';
@import '@fontsource/jetbrains-mono/500.css';
@import '@fontsource/inter/400.css';
@import '@fontsource/inter/700.css';
@import '@fontsource/jetbrains-mono/700.css';
@import '@fontsource/jetbrains-mono/800.css';
```

**Rules:**
- Use only the tokens above (or later, the Design System's). No literal hex colors, no arbitrary `[#abc]` color values in components.
- Tokens live only in `packages/ui`; `web` and `admin` must not redeclare them.
- Inter for prose, JetBrains Mono for everything else (`foundations/typography.md`), both via `@fontsource/*`, self-hosted. No Google Fonts or other external font requests.
- Merge conditional classes with `cn()`; never concatenate class strings by hand.
- Text and interactive-element contrast meets WCAG 2.1 AA against the surface it sits on (4.5:1 text, 3:1 large text and UI components). Verify any new color pair.
- Focus is always visible: use `focus-visible:` rings with `--color-accent`; never `outline-none` without a replacement.
- State is never conveyed by color alone: pair it with an icon, text or pattern (see `accessibility`).
- Respect `prefers-reduced-motion`: animations are disabled or reduced under it.
- No CSS-in-JS and no component CSS files, except the token file and third-party overrides.

**Updates from REQ-003 (alignment with the Design System 1.0.0+):**
- **Responsive design:** no global media queries. Layout uses `flex-wrap` and `repeat(auto-fit, minmax(min(300px, 100%), 1fr))`; only the 320 px adaptations documented in the Design System are allowed. Page container is `max-w-page` (1240 px) with a 32 px gutter. *(Lo implementa S-012; este plan no toca layout.)*
- **Buttons and links:** `@nerdose/ui` exports the class helpers `buttonClass({ variant, size, game?, fullWidth?, disabled? })` and `linkClass({ tone? })`, so they apply both to `<button>` and to router `<Link>` without `@nerdose/ui` importing `react-router`.
- **Tokens grow additively:** per-game tints, status tints, streak amber family, type roles (`--text-*`), radii (`--radius-*`), shadows, `--animate-blink` and the `texture-dots` utility live in `tokens.css`; existing token names are kept.
- **Static check:** component and web `.tsx` files must not contain arbitrary values (`/\[(\d|#|rgb)/`) nor generic utilities (`rounded-md`, `shadow-md`, `text-2xl`, `font-semibold`).

### Convención `accessibility` (partes aplicables, copiadas)

- One `<main>` per page, landmarks for header/nav/footer, one `<h1>` per screen, headings in order.
- Use native elements first: `<button>`, `<a>`. Provide a visible focus ring on every focusable element (`focus-visible`).
- Touch targets are at least 44 x 44 px. Layout reflows at 320 px without horizontal scroll and supports 200% text zoom.
- Contrast is at least 4.5:1 for text (3:1 for large text and UI boundaries) against its actual background.
- Focus is never removed (`outline: none`) without a visible replacement.
- axe-core reports zero violations in unit checks and e2e page checks.

### Convención `testing-unit` (partes aplicables, copiadas)

- Query by role, label or visible text. `data-testid` only when no accessible query exists.
- Use `userEvent`, not `fireEvent`, for interactions.
- Each interactive component has an axe check; fix violations instead of disabling rules.
- Fixtures use the API's `snake_case` names. Mock the network with MSW, never the app's own modules.
- No snapshot tests of large DOM trees. Tests do not rely on the real date or timers.
- Test names state the behavior ("shows ... when ..."), not the implementation.
- Config de `apps/web/vitest.config.ts`: `environment: 'jsdom'`, `css: false`, `include: ['src/**/*.test.{ts,tsx}', 'test/**/*.test.ts']`. Los tests de archivos usan `// @vitest-environment node` (como `styles.test.ts`).
- Utilidades existentes: `renderWithProviders({ route, strict? })` (`src/test/render.tsx`, memory router + QueryClient + i18n en `es`), `server` / `defaultHandlers` (`src/test/msw.ts`), `todayFixture`, `todayNoSessionFixture`, `todayNoChallengesFixture`, `todayFirstVisitFixture` (`src/test/fixtures/today.ts`), `mockViewport('mobile' | 'desktop')` (`src/test/viewport.ts`).

### ADRs Relevantes

#### ADR-002: Stack tecnológico

- **Decisión (front, verbatim):** React 19 + Vite + React Router (cada juego con `React.lazy`). TanStack Query para datos de servidor. Tailwind CSS v4, con los tokens del prototipo en `@theme`. **`@fontsource/inter` (prosa) y `@fontsource/jetbrains-mono` (resto), ambas self-hosted.** i18next + react-i18next.
- **Reglas de Implementación (lista completa, verbatim):**
  - Todo el código propio MUST ser TypeScript con `strict: true`. MUST NOT haber archivos `.js` de código fuente en `apps/` ni en `packages/` (salvo configuración de herramientas).
  - `api` y `generator` MUST correr en Node.js 24 LTS. `engines.node` MUST ser `">=24 <25"`.
  - El framework HTTP de la `api` MUST ser Hono. MUST NOT usarse Express, Fastify ni NestJS.
  - Todo acceso a la base MUST pasar por Drizzle ORM con el driver postgres.js. SQL crudo solo en migraciones, en las vistas `metrics_*` y donde Drizzle no lo soporte (`LISTEN`, `pg_notify`, `pg_try_advisory_lock`, `FOR UPDATE SKIP LOCKED`).
  - Toda entrada HTTP (body, query, params) MUST validarse con Zod vía `@hono/zod-validator`. Los schemas de jugada MUST importarse del paquete del juego, nunca redefinirse.
  - `web` y `admin` MUST ser SPAs con React 19 + Vite. MUST NOT usarse SSR ni Next.js/Remix.
  - Cada juego MUST cargarse en `web` con `React.lazy` en la ruta `/:game_id`. Shiki MUST cargarse solo en las rutas `big-o` y `bug-hunt`.
  - **Los estilos MUST ser Tailwind CSS v4, con los tokens en `@theme`. MUST NOT cargarse fuentes ni CSS de CDNs de terceros.**
  - Los textos de UI MUST pasar por i18next con claves en `es` y `en`. Los textos de contenido MUST venir resueltos desde la `api`.
  - El PRNG del `generator` MUST ser `pure-rand` (xoroshiro128+). MUST NOT usarse `Math.random()` en la generación de desafíos.
  - Los tests MUST usar Vitest; los e2e, Playwright.

#### ADR-003: Monorepo y paquetes compartidos (reglas aplicables, verbatim)

- El gestor de paquetes MUST ser pnpm, con workspaces declarados en `pnpm-workspace.yaml` (`apps/*`, `packages/*`, `packages/games/*`). MUST NOT usarse npm, yarn ni bun.
- Las tareas (`build`, `lint`, `typecheck`, `test`) MUST orquestarse con Turborepo desde `turbo.json`.
- `apps/web` y `apps/admin` MUST NOT importar `@nerdose/db` ni `@nerdose/core/notify`.
- MUST NOT haber dependencias entre apps (`apps/*` no importa de otro `apps/*`). Lo compartido va en `packages/`.

### Código Reutilizable

**De `@nerdose/ui` (`docs/reusable-code/ui/helpers.md`, verificado contra el código):**

- **`buttonClass`** — `packages/ui/src/components/button-class.ts`.
  - Firma: `buttonClass(options?: ButtonClassOptions): string`, con `ButtonClassOptions = { size?: 'lg' | 'md'; fullWidth?: boolean; disabled?: boolean } & ({ variant?: 'primary' | 'secondary' } | { variant: 'accent'; game: UiGameId })`. Defaults: `variant: 'primary'`, `size: 'md'`.
  - Devuelve (código actual):
    - Base: `inline-flex items-center justify-center rounded-control font-mono` + `FOCUS_RING` (`focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-accent`).
    - `lg`: `min-h-12 gap-2.5 px-5.5 text-button-lg` · `md`: `min-h-11 gap-2 px-4 text-button-md`.
    - Peso: `font-medium` en `secondary`, `font-bold` en el resto.
    - `primary`: `bg-accent text-on-accent hover:bg-accent-hover` · `secondary`: `border border-border-strong text-text hover:border-border-hover` · `accent`: `bg-game-{id} text-game-{id}-on hover:bg-game-{id}-light`.
    - `disabled: true` (cualquier variant): `border border-border-strong bg-control text-text-disabled cursor-not-allowed`, sin hover.
    - `fullWidth: true`: `w-full`.
  - **Solo clases:** el consumidor pone `aria-disabled="true"` y bloquea la acción (en un `<Link>`, no navegar; en un `<button>`, no ejecutar).
  - Uso: `<Link to="/play" className={buttonClass({ variant: 'accent', game: 'big-o', fullWidth: true })}>Jugar →</Link>`.
- **`linkClass`** — `packages/ui/src/components/link-class.ts`.
  - Firma: `linkClass(options?: { tone?: LinkTone }): string`, `LinkTone = 'brand' | 'subtle' | UiGameId`, default `brand`.
  - Devuelve: `inline-flex min-h-11 items-center gap-1 font-mono no-underline` + `FOCUS_RING` + (`brand`) `py-3 text-mono-body text-accent hover:text-accent-hover`.
  - Uso: `<Link to="/stats" className={linkClass()}>ver estadísticas →</Link>`.
- **`cn`** — `packages/ui/src/cn.ts`: `twMerge(clsx(inputs))`. Para sumar clases de layout a un helper: `cn(buttonClass(), 'w-full lg:w-auto')`.
- **`UiGameId`** = `'devdle' | 'grep-grid' | 'timeline' | 'big-o' | 'bug-hunt'`, el mismo union que `GameId` de `@nerdose/core` (`(typeof GAME_IDS)[number]`): `gameId` de `GameCard` se pasa directo a `buttonClass({ variant: 'accent', game: gameId })`.
- **Patrón de guarda estática** — `packages/ui/src/components/components.test.ts`: `FORBIDDEN = [{ name: 'hex', re: /#[0-9a-fA-F]{3,8}\b/ }, { name: 'arbitrary', re: /\[(\d|#|rgb)/ }, { name: 'generic', re: /\b(rounded-md|shadow-md|text-2xl|font-semibold)\b/ }]`, filtro `isSource = (f) => /\.tsx?$/.test(f) && !/\.test\.tsx?$/.test(f)` y un test de "no pasa vacío" con muestras buenas y malas. `web` replica las mismas expresiones (no importa un archivo de test de otro paquete).

#### Foundations — Tipografía (`foundations/typography.md`, copiado lo aplicable)

**Familias:**

**Regla de uso (verbatim):**
- **Inter es la fuente base de la página** (el wrapper de cada pantalla declara `font-family: 'Inter', system-ui, sans-serif`). JetBrains Mono se aplica pieza por pieza.
- **Si es prosa de más de una frase → Inter.** Lede del hero, descripciones de tarjeta, explicaciones, pasos numerados, etiquetas de stat, notas al pie y textos de ayuda.
- **Si es interfaz, dato, título o código → JetBrains Mono.** Logo, nav, todos los títulos (`h1`-`h3`), todos los números, botones y links-CTA, selector ES/EN, píldora de racha, badges y chips, etiquetas-comentario `//`, prompts `$`, metadatos, tablas, código, terminal, celdas y teclas de juego, `<code>` dentro de un párrafo Inter.
- **Los títulos nunca van en Inter.**
- Los `<button>` no heredan fuente en los navegadores: todo botón declara Mono explícitamente. *(Con el preflight de Tailwind v4 los botones heredan `font: inherit`; aun así, `buttonClass` ya declara `font-mono` y los botones del header heredan el `font-mono` del header.)*
- **Sin `text-transform`.**

**Ligaduras (verbatim):** "El DS las desactiva en todo texto Mono (`font-variant-ligatures: none`): un juego de código no puede mostrar `≥` donde el código dice `>=`." → Implementado en `tokens.css` de `ui` con `--font-mono--font-feature-settings: "liga" 0, "calt" 0`; la utilidad `font-mono` de Tailwind v4 aplica `font-feature-settings` desde esa variable. `web` solo tiene que usar `font-mono` (nunca `font-family` a mano).
