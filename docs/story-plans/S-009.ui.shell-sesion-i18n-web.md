# Story Plan: S-009 (ui) - Shell, sesión e i18n en web

## Status

**Status:** Completed

## Referencia de la Story

- **Story:** [S-009](../stories/S-009.shell-sesion-i18n-web.md)
- **Servicio:** ui
- **Resumen:** Agrega a `@nerdose/ui` (`packages/ui`) los primeros componentes React compartidos que necesita el shell de `web`: el banner de aviso (`Banner`, usado por O-03 «Activá las cookies para poder jugar») y el header base (`AppHeader` + `BrandMark`, la marca `> nerdose` que hoy está duplicada en los shells de `web` y `admin`). Prepara el paquete para tener componentes (React, JSX, jsdom, Testing Library, axe) y suma el token de advertencia del Design System.

> **Alcance de este plan:** solo el servicio `ui` (impacto **Bajo** en la story: «Componentes compartidos de banner y, si hace falta, header base»). Todo lo demás de S-009 es de `web` (plan `S-009.web.*`): módulo `session`, i18n, selector ES/EN, footer, `acerca-de`, `no-encontrado`, detección de cookies bloqueadas, rutas. Este plan **no** toca `apps/web` ni `apps/admin`: los componentes se publican y `web` los consume en su plan.
>
> **Rutas:** las rutas de "Archivos a crear/modificar" son relativas a `packages/ui/`, salvo cuando se indica la raíz del repo.
>
> **Regla clave (ADR-002):** «Los textos de UI MUST pasar por i18next con claves en `es` y `en`». `ui` no tiene i18next: **ningún componente de `ui` contiene texto visible propio**. Todo texto entra por props (`title`, `label`, `children`), y lo resuelve la app con `t()`. La única excepción es el glifo decorativo `>` de la marca (`aria-hidden`), que no es texto traducible.
>
> **Fuera de alcance:** footer (su texto es de `web` y `admin` no lo usa), selector ES/EN (control de i18n, solo `web`), `nav-movil`, alerta de error de sistema y tarjetas de la home (S-010), `track()` (ADR-014), migrar los shells de `web`/`admin` a los componentes nuevos (lo hace el plan de `web`; `admin` no está en la story).

## Contexto Arquitectónico

### Stack Tecnológico

- **Lenguaje:** TypeScript `strict: true`, `noUncheckedIndexedAccess: true`, `verbatimModuleSyntax: true` (`tsconfig.base.json`). Node.js 24 (`v24.22.2` en la máquina actual).
- **Librería:** React 19 (`manifest.yaml` de `ui`: `type: library`, `language: react`). Versión usada por las apps: `react ^19.3.1`, `react-dom ^19.3.1`, `@types/react ^19.3.0`, `@types/react-dom ^19.3.0`.
- **Estilos:** Tailwind CSS v4 (`tailwindcss ^4.3.4` + `@tailwindcss/vite ^4.3.4` en las apps). `ui` publica `tokens.css` (bloque `@theme`) y clases en sus componentes; el CSS lo compilan las apps.
- **Helper de clases:** `cn()` = `twMerge(clsx(inputs))` (`clsx ^2.1.1`, `tailwind-merge ^3.7.0`).
- **Tests:** Vitest `^5.1.0` (raíz). Para componentes, las mismas versiones que `web`: `jsdom ^30.1.3`, `@testing-library/react ^16.3.3`, `@testing-library/jest-dom ^7.0.1`, `vitest-axe ^0.1.0`.
- **Lint:** ESLint flat config de la raíz. `packages/ui/**/*.{ts,tsx}` ya está en `REACT_FILES` (presets de `jsx-a11y` y `react-hooks`) y tiene `no-restricted-imports` contra `@nerdose/db` y `@nerdose/core/notify`.

### Convenciones de Código (`_base` de `ui`, aplicables)

- Naming: archivos `kebab-case` (`app-header.tsx`), componentes exportados `PascalCase` (`export function AppHeader()`), tipos `PascalCase` sin prefijo `I`. Un componente principal por archivo; **tests al lado del archivo** como `*.test.tsx`.
- Imports: (1) externos y `@nerdose/*`, (2) `@/` (no aplica en `ui`, que no tiene alias), (3) relativos de la misma carpeta; grupos separados por línea en blanco. Imports de solo tipos con `import type` (obligatorio por `verbatimModuleSyntax`).
- Sin `any`. Sin comentarios salvo el porqué no obvio.
- Lo compartido por `web` y `admin` va en `@nerdose/ui`, no copiado.

### Convención `styling` (partes aplicables, copiadas)

- Tokens expuestos por Tailwind como `bg-bg`, `bg-surface`, `text-text`, `text-text-muted`, `text-text-dim`, `border-border`, `text-accent`, `text-game-bug-hunt`, etc.
- «Use only the tokens above (or later, the Design System's). No literal hex colors, no arbitrary `[#abc]` color values in components.»
- «Tokens live only in `packages/ui`; `web` and `admin` must not redeclare them.»
- «Merge conditional classes with `cn()`; never concatenate class strings by hand.»
- «Focus is always visible: use `focus-visible:` rings with `--color-accent`; never `outline-none` without a replacement.»
- «State is never conveyed by color alone: pair it with an icon, text or pattern.»
- «Respect `prefers-reduced-motion`.» (los componentes de este plan no animan)
- Dark only: sin variantes `dark:`.
- Mobile-first desde 320 px; `sm:`/`md:`/`lg:` agregan layout. Sin scroll horizontal a 320 px. Targets táctiles ≥ 44×44 px.
- Orden de clases: layout, spacing, tipografía, color, variantes de estado.
- «No CSS-in-JS and no component CSS files, except the token file and third-party overrides.»

### Convención `accessibility` (partes aplicables, copiadas)

- Landmarks para header/nav/footer; un `<main>` y un `<h1>` por página (los pone la app, no `ui`).
- Elementos nativos primero; ARIA solo si no hay nativo.
- «Every image or icon is either decorative (`aria-hidden`) or has an accessible name.»
- «Result, errors and notices appear in `role="status"` (polite) or `role="alert"` (errors) regions.»
- «Dynamic updates are announced via live regions; do not move focus unexpectedly.»
- «axe-core reports zero violations in unit checks and e2e page checks.»

### Convención `testing-unit` (partes aplicables, copiadas)

- Vitest + React Testing Library en jsdom; axe-core vía `vitest-axe` (`toHaveNoViolations`).
- Setup: `import '@testing-library/jest-dom/vitest'`, `expect.extend(axeMatchers)`, `afterEach(cleanup)`.
- Consultar por rol, label o texto visible; `data-testid` solo si no hay consulta accesible.
- «Each interactive component has an axe check; fix violations instead of disabling rules.»
- Sin snapshots de árboles grandes. Nombres de test que describen el comportamiento.

### ADRs Relevantes

#### ADR-003: Monorepo y paquetes compartidos (reglas verbatim)

- Los paquetes internos MUST llamarse `@nerdose/<nombre>` (`@nerdose/core`, `@nerdose/db`, `@nerdose/ui`, `@nerdose/polyglot`, `@nerdose/content`, `@nerdose/game-<game_id>`).
- `apps/web` y `apps/admin` MUST NOT importar `@nerdose/db` ni `@nerdose/core/notify`.
- MUST NOT haber dependencias entre apps (`apps/*` no importa de otro `apps/*`). Lo compartido va en `packages/`.
- El gestor de paquetes MUST ser pnpm. Las tareas (`build`, `lint`, `typecheck`, `test`) MUST orquestarse con Turborepo.

Decisión: `packages/ui` = «componentes compartidos (header, banners, share, stat cards), tokens, track()».

#### ADR-002: Stack tecnológico (reglas aplicables, verbatim)

- Todo el código propio MUST ser TypeScript con `strict: true`. MUST NOT haber archivos `.js` de código fuente en `apps/` ni en `packages/` (salvo configuración de herramientas).
- `web` y `admin` MUST ser SPAs con React 19 + Vite.
- Los estilos MUST ser Tailwind CSS v4, con los tokens en `@theme`. MUST NOT cargarse fuentes ni CSS de CDNs de terceros.
- Los textos de UI MUST pasar por i18next con claves en `es` y `en`.
- Los tests MUST usar Vitest; los e2e, Playwright.

- Contraste: `text-warning` (`#FFB547`) y `text-text-muted` (`#9AA6B2`) sobre `bg-surface` (`#0F1318`). Verificar con los hex que ambos superan 4.5:1 y dejar el ratio medido en el resumen de la implementación (no está documentado en el DS).
