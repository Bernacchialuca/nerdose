# Story Plan: S-022 (core) - Paquete Grep Grid: contrato ampliado, definición y generador

## Status

**Status:** Completed

## Referencia de la Story

- **Story:** [S-022](../stories/S-022.paquete-grep-grid-contrato-definicion-generador.md)
- **Servicio:** core
- **Resumen:** Amplía el contrato `GameDefinition` de `@nerdose/core` con lo que necesita un juego de varias jugadas: `MoveContext.locale` (para que el `Feedback` salga en el idioma del jugador) y el tercer parámetro opcional `state` de `toPublic` (para que la vista pública pueda mostrar lo que el jugador ya descubrió). Son dos cambios de tipos en `packages/core/src/game-definition.ts`; no se agrega lógica en runtime.

> **Alcance de este plan:** solo el servicio `core` (`packages/core`), impacto **Bajo**. El paquete `@nerdose/game-grep-grid` (CA-2 a CA-12) es del plan del servicio `games` de esta misma story. Story puramente backend (`affects_ui: false`): no se leyó contexto de UX ni Design System.
>
> **Rutas:** las rutas de "Archivos a crear/modificar" son relativas a la raíz del paquete, `packages/core/`, salvo las de `docs/` (relativas a la raíz del monorepo).
>
> **Fuera de alcance:** el paquete `packages/games/grep-grid` (plan `games` de S-022), cualquier cambio en `packages/games/devdle` (plan `games`), `apps/api` (`GameplayService` pasa `ctx.locale` y el `state` a `toPublic`: S-023), `apps/generator`, `apps/web`, `docs/apis/api.yaml` y la base. ADR-006 y `docs/architectures/core/conventions/game-registry.md` **ya están actualizados** con el contrato nuevo (sección "Update (REQ-005)"): este plan los implementa, no los edita.

**`src/game-definition.ts` actual, completo (a modificar):**

```ts
import type { z } from 'zod';
import type { Locale } from './enums';

export const GAME_IDS = ['devdle', 'grep-grid', 'timeline', 'big-o', 'bug-hunt'] as const;

export type GameId = (typeof GAME_IDS)[number];

export type { Locale } from './enums';

export function isGameId(value: unknown): value is GameId {
  return typeof value === 'string' && (GAME_IDS as readonly string[]).includes(value);
}

export type MoveError = 'invalid_move' | 'not_in_word_list';

export interface MoveContext {
  isValidWord(word: string): boolean;
}

export interface GameDefinition<Payload, PublicView, State, Move, Feedback, Result, Stats> {
  id: GameId;
  version: number;
  moveSchema: z.ZodType<Move>;

  toPublic(p: Payload, locale: Locale): PublicView;
  initState(p: Payload, now: Date): State;
  applyMove(
    p: Payload,
    s: State,
    m: Move,
    now: Date,
    ctx: MoveContext,
  ): { state: State; feedback: Feedback } | { error: MoveError };
  isFinished(s: State): boolean;
  result(p: Payload, s: State, locale: Locale): Result;
  isWin(r: Result): boolean;
  score(r: Result): number;

  initialStats(): Stats;
  reduceStats(prev: Stats, r: Result): Stats;
  historyLabel(r: Result): string;
}
```

**`test/fixtures/fake-definition.ts` actual, completo (a ampliar):**

```ts
import { z } from 'zod';

import type { GameDefinition, GameId } from '../../src/game-definition';

export type FakeDefinition = GameDefinition<
  { word: string },
  { length: number },
  { attempts: number },
  { guess: string },
  { ok: boolean },
  { won: boolean },
  { played: number }
>;

export function makeDefinition(id: GameId): FakeDefinition {
  return {
    id,
    version: 1,
    moveSchema: z.object({ guess: z.string() }),
    toPublic: (p) => ({ length: p.word.length }),
    initState: () => ({ attempts: 0 }),
    applyMove: (p, s, m) => ({
      state: { attempts: s.attempts + 1 },
      feedback: { ok: m.guess === p.word },
    }),
    isFinished: (s) => s.attempts >= 6,
    result: () => ({ won: false }),
    isWin: (r) => r.won,
    score: (r) => (r.won ? 1 : 0),
    initialStats: () => ({ played: 0 }),
    reduceStats: (prev) => ({ played: prev.played + 1 }),
    historyLabel: (r) => (r.won ? '✓' : '✗'),
  };
}

export function makeWordDefinition(): FakeDefinition {
  return {
    ...makeDefinition('devdle'),
    applyMove: (p, s, m, _now, ctx) =>
      ctx.isValidWord(m.guess)
        ? { state: { attempts: s.attempts + 1 }, feedback: { ok: m.guess === p.word } }
        : { error: 'not_in_word_list' },
  };
}
```

### Convención `game-registry` (aplicable a `core`) — extracto verbatim

Reglas vigentes:

- "The `api` never serializes `challenges.payload` in a player response. Before the Play ends it answers `toPublic(payload, locale)`; after, `result(payload, state, locale)`."
- "`Feedback` returned for a move never contains a solution value that the game has not already revealed by design."
- "Every game has an anti-spoiler contract test; the build fails without it."

**Update (REQ-004):**

- "`applyMove(p, s, m, now, ctx: MoveContext)`: `ctx = { isValidWord(word) }` is built by the `api` from `WordList.has`; games that do not need it ignore it."

**Update (REQ-005)** — lo que implementa este plan:

- "`MoveContext = { isValidWord(word): boolean; locale: Locale }`: the `api` adds the locale it already resolved for `result`. A game uses it to localize `Feedback` (Grep Grid: `feedback.definition`); `Feedback` never carries `{ es, en }` (ADR-015). Devdle ignores it."
- "`toPublic(p, locale, state?)`: the `api` passes `play.state` only when the Play is `in_progress` (`game.toPublic(challenge.payload, locale, play?.status === 'in_progress' ? play.state : undefined)`); with no Play or a finished Play it passes nothing. With a state, `toPublic` may reveal only what the player already discovered in that Play (Grep Grid: `words[].definition` for the `term_id`s in `found_words`) and never anything about what is still hidden."
- "Both changes are additive: games that do not need them keep compiling and behave the same."
- "A move may be valid and leave the state unchanged (Grep Grid: `not_a_word`, `already_found`): `applyMove` returns the same state with a `feedback`, the `api` answers `200` and the idempotent `UPDATE plays SET state` still runs."
- "The anti-spoiler contract test of a game that uses `state` covers `toPublic` with no state, with the initial state and with intermediate states."

### ADRs Relevantes

#### ADR-006: Contrato `GameDefinition` y juegos como paquetes enchufables (actualizado por REQ-005)

**Decisión:** cada juego es un paquete `packages/games/<game_id>` que implementa el contrato `GameDefinition` de `@nerdose/core`.

```ts
// @nerdose/core — contrato de servidor (entrada ./definition de cada juego)
export interface GameDefinition<Payload, PublicView, State, Move, Feedback, Result, Stats> {
  id: GameId;                       // 'devdle' | 'grep-grid' | 'timeline' | 'big-o' | 'bug-hunt'
  version: number;                  // versión del schema de Payload
  moveSchema: z.ZodType<Move>;

  toPublic(p: Payload, locale: Locale, state?: State): PublicView;   // sin solución; state solo con la Play in_progress (REQ-005)
  initState(p: Payload, now: Date): State;
  applyMove(p: Payload, s: State, m: Move, now: Date, ctx: MoveContext):
    { state: State; feedback: Feedback } | { error: MoveError };   // 'invalid_move' | 'not_in_word_list'
  isFinished(s: State): boolean;
  result(p: Payload, s: State, locale: Locale): Result;      // incluye solución y explicación
  isWin(r: Result): boolean;
  score(r: Result): number;

  initialStats(): Stats;
  reduceStats(prev: Stats, r: Result): Stats;
  historyLabel(r: Result): string;  // "✓ 4/6", "8/8", "3/5", "✓ O(n log n)", "✗ L7"
}

export interface MoveContext { isValidWord(word: string): boolean; locale: Locale }   // lo arma la api (WordList.has y el locale resuelto, REQ-005); los juegos que no lo usan lo ignoran
```

**Reglas de Implementación (verbatim):**

- Cada juego MUST vivir en `packages/games/<game_id>`, con `game_id` ∈ `devdle | grep-grid | timeline | big-o | bug-hunt`.
- La entrada `./definition` MUST exportar un objeto que implemente `GameDefinition` de `@nerdose/core`, con todos los métodos de la interfaz.
- Las rutas de juego de la `api` MUST resolver el juego por el registry. MUST NOT haber `if (game_id === '…')` ni `switch` por juego en `apps/api` ni en el shell de `apps/web`.
- La `api` MUST NOT serializar `challenges.payload` en ninguna respuesta de jugador. Antes de terminar la Play solo puede responder `toPublic(payload, locale, state?)`; después, `result(payload, state)`.
- La `api` MUST pasar `state` a `toPublic` solo si la Play está `in_progress` (sin Play o con la Play terminada, `undefined`). Con `state`, `toPublic` MAY revelar únicamente lo que el jugador ya descubrió en esa Play (Grep Grid: `words[].definition` de los `term_id` presentes en `found_words`); MUST NOT revelar nada de lo no descubierto (REQ-005).
- `Feedback` MUST ir en el locale del jugador (`ctx.locale`), nunca como `{ es, en }` (ADR-015).
- `toPublic` MUST NOT incluir: la palabra de Devdle, `placements` de Grep Grid, `correct_order`/`event_date`/`fact_id` de Timeline, `answer` de Big O, ni `bug_node_id`/`failing_test`/`fix`/`line_of`/`mutation` de Bug Hunt.
- Cada juego MUST tener un test de contrato anti-spoiler: se serializa `toPublic(payload)` (sin estado y con estados intermedios, si el juego usa `state`) y toda respuesta pre-resultado, y se verifica que no contienen ningún valor de la solución.
- `moveSchema` MUST usarse tanto en `web` (antes de enviar) como en la `api` (`@hono/zod-validator`). Si el parse falla, la respuesta es `422 invalid_move`.
- `share(result, number)` MUST NOT incluir la solución y MUST terminar en `nerdose.dev`.
- `generate` MUST ser determinista: el mismo `{ date, seed, history }` da el mismo `Payload`. MUST NOT usar `Math.random()` ni la hora actual.
- `Payload` MUST incluir todos los textos que lee el jugador como `{ es, en }`. `verify` MUST fallar si falta algún idioma.
- Sumar un juego MUST requerir solo crear su paquete y registrarlo en los tres registries, sin cambiar rutas, tablas ni lógica de rachas.

**Consecuencia negativa registrada:** "Cambiar la interfaz obliga a tocar los 5 paquetes." (hoy solo existe `devdle`; ver "Hallazgo" más abajo).

### Decisiones de diseño de REQ-005 aplicables (verbatim)

- **Decisión 2 — `locale` en `MoveContext` (hallazgo del ciclo común).** "`GrepGridFeedbackFound.definition` es un `string` en el locale (api.yaml l. 1343; ADR-015 prohíbe `{es,en}` al jugador), pero `applyMove(p, s, m, now, ctx)` no recibe el locale. Se amplía `MoveContext` a `{ isValidWord(word): boolean; locale: Locale }`; la `api` ya construye `ctx` en `GameplayService.move()` y solo agrega el `locale` que ya resolvió para `result`. Devdle lo ignora. Alternativa descartada: feedback con `{es,en}` resuelto por la `api` (rompe ADR-015 y mete lógica por juego en el shell)."
- **Decisión 3 — `toPublic` con el estado de la Play (hallazgo del ciclo común).** "Al retomar (CA 14) y al cambiar de idioma (CA 19) hay que mostrar la definición de las palabras ya encontradas, pero `GrepGridState.found_words` guarda solo `{ term_id, cells }` y `toPublic(p, locale)` no conoce la Play. Se amplía el contrato a `toPublic(p, locale, state?: State)`: la `api` pasa `play.state` solo cuando la Play está `in_progress`. Grep Grid devuelve `words[i].definition` **únicamente** para los `term_id` presentes en `found_words`; las demás no llevan la propiedad. […]"
- **Riesgo registrado:** "ampliar `MoveContext` y `toPublic` rompe Devdle. **Mitigación:** cambios aditivos (propiedad nueva y parámetro opcional); `devdle` compila sin tocarlo y su suite sigue verde (CA 37)."
- **Impacto en `core` (tabla de servicios del REQ):** "Dos ampliaciones aditivas del contrato: `MoveContext.locale` (decisión 2) y `toPublic(p, locale, state?)` (decisión 3). Devdle compila y se comporta igual".

Sin cambios de rutas. `core` no expone HTTP. Los tipos de `core` son genéricos; los schemas concretos (`GrepGridPublicView`, `GrepGridState`, `GrepGridFeedbackFound`, etc.) de `docs/apis/api.yaml` los implementa el paquete `grep-grid`. Solo como referencia de para qué sirve cada ampliación:

- `GrepGridPublicView = { grid, words: [{ term_id, word, definition? }] }` — `definition`: "Opcional. Solo en las palabras ya encontradas por la Play `in_progress` del jugador, en el locale resuelto. Nunca en las no encontradas ni sin sesión (anti-spoiler, ADR-006)." → requiere `toPublic(p, locale, state?)`.
- `GrepGridFeedbackFound = { found: true, term_id, word, definition, cells }` con `definition` como `string` en el locale → requiere `ctx.locale`.

### Contexto de Flujos

#### `jugada-y-cierre-de-partida` — Paso 2 (extracto verbatim)

> **Acción:** `applyMove(payload, state, move, now, ctx)` del `GameDefinition`, con `ctx = { isValidWord, locale }` armado por la `api` (`locale` es el mismo que usa `result`):
> - `{ error: 'not_in_word_list' }` (solo Devdle) → […] respuesta `422 not_in_word_list`. El `state` no cambia y no consume intento.
> - `{ error: 'invalid_move' }` → ROLLBACK; `422 invalid_move`.
> - `{ state, feedback }` → **Operación de BD:** `plays` UPDATE `state`.
> - Jugada válida sin cambio de estado (solo Grep Grid): […] devuelven el mismo `state`. No son errores […].
>
> Grep Grid, `move.type = 'select'`: […] `feedback.definition` va en `ctx.locale`.

**Qué toca este plan:** el tipo de `ctx` (`MoveContext` gana `locale: Locale`). Quien arma `ctx` es la `api` (S-023).

#### `abrir-y-retomar-juego` — Paso 1 (extracto verbatim)

> `public_view = toPublic(payload, locale, state)`: la `api` pasa `plays.state` solo si la Play está `in_progress`; si no hay Play o ya terminó, `state` es `undefined`.
>
> | game_id | `public_view` |
> |---|---|
> | devdle | `{ length, possible_categories[] }` |
> | grep-grid | `{ grid: string[12][12], words: [{ term_id, word, definition? }] ×8 }` — `definition` solo en las palabras ya encontradas (`term_id` presentes en `plays.state.found_words`), en el locale resuelto; nunca en las no encontradas ni sin Play |

**Qué toca este plan:** la firma de `toPublic` (tercer parámetro opcional `state?: State`). Quien lo pasa es la `api` (S-023).

#### `generacion-diaria`

No aplica a `core` en esta story: `GameGenerator`, `GeneratorHistory` y `VerificationLog` no cambian.

### Hallazgo: `locale` requerido no es transparente para los llamadores — `NOT DOCUMENTED - needs verification`

La documentación (ADR-006, convención `game-registry`, REQ-005 decisión 2, story CA-1) define `MoveContext = { isValidWord(word): boolean; locale: Locale }` con `locale` **requerido** y a la vez afirma que el cambio es aditivo y que "`@nerdose/game-devdle` compila sin tocarlo".

Eso es cierto para quien **implementa** el contrato (el código de producción de Devdle compila y se comporta igual), pero no para quien **construye** un `MoveContext`: los tres sitios marcados arriba dejan de pasar `tsc --noEmit` (`TS2741`/`TS2345`: falta `locale`). `vitest run` no hace typecheck, así que **la suite de Devdle sigue verde**; lo que falla es `pnpm --filter @nerdose/game-devdle typecheck` y `pnpm --filter @nerdose/api typecheck`.

Cómo lo resuelve este plan (sin reabrir el diseño):

1. `core` implementa el contrato **tal como está documentado**: `locale: Locale` **requerido**. No se hace opcional: `feedback.definition = words[i].definition[ctx.locale]` (decisión 5) necesita un `Locale` garantizado, y un `locale?` obligaría a cada juego a inventar un default.
2. Este plan **no** toca `packages/games/devdle` ni `apps/api` (son de otros servicios). Las correcciones son de una línea cada una y quedan asignadas así:
   - `packages/games/devdle/src/definition/test-fixtures.ts` (`ALL_VALID`, `NONE_VALID`) y `definition.test.ts` (`spy`): agregar `locale: 'es'` → **plan `games` de S-022** (debe incluirlo explícitamente; son archivos de test, el código de producción de Devdle no se toca).
   - `apps/api/src/domain/gameplay/gameplay.service.ts` (`ctx`): agregar `locale` → **S-023** (ya está en su alcance: "`GameplayService` pasa `ctx.locale`").
3. Hasta que esos dos cambios entren, `pnpm typecheck` en la raíz falla en `@nerdose/game-devdle` y `@nerdose/api` por esos sitios exactos. Es esperado y no es un defecto de este plan; la Tarea 3 lo comprueba y lo deja documentado (cualquier **otro** error en consumidores sí es un defecto).

Si se prefiere que la raíz quede verde al cerrar esta story, la decisión es de producto/arquitectura (por ejemplo, mover la línea de la `api` a S-022) y hay que registrarla en el REQ; este plan no la toma.
