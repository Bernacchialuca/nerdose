# Story Plan: S-021 (ui) - Web: Devdle jugable (piezas compartidas de @nerdose/ui)

## Status

**Status:** In Progress

## Referencia de la Story

- **Story:** [S-021](../stories/S-021.web-devdle-jugable.md)
- **Servicio:** ui
- **Resumen:** Suma a `@nerdose/ui` (`packages/ui`) las piezas **transversales** que las tres pantallas de Devdle necesitan y que el DS `web` 1.4.1 ya especifica pero `ui` todavía no implementa: `GameHeader` (header de las pantallas de juego), las variants `success` / `failure` / `neutral` de `Banner` con slot de acción, `buttonClass` con la variant `icon` y el tamaño `share`, íconos Lucide del header (`HelpIcon`, `ChartIcon`, `ShareIcon`), `Badge` chip con `loose`, los tokens que faltan para las piezas de juego (roles tipográficos `type.title.game`, `type.brand.*`, `type.game.*`, colores `status.present` / `status.absent.*`, `text.separator`, anchos máximos del teclado y del aside) y el helper de analítica `track()` + `injectAnalytics()` que exige ADR-014 para `track('share:devdle')`. Las piezas derivadas se documentan en el DS (v1.5.0).

> **Alcance de este plan:** solo el servicio `ui`. Quedan **fuera** y van en los otros planes de S-021:
> - **`games` (devdle `./client`)**: `Instructions`, `Game`, `Result`, `share(result, number)` y las piezas propias de un solo juego del pattern `game-boards` (`devdle.cell`, `devdle.key`, `devdle.legend`, `devdle.distribution`, pista de categorías), incluidas sus adaptaciones Pendientes (señal no cromática correcta vs no está, escalado de celda a 320 px, tecla «presente», foco de tecla) y su documentación en `patterns/game-boards.md`.
> - **`web`**: módulo `game-host` (ruta `/:game_id`, `clientRegistry`, hooks de datos, botón de compartir con Web Share API / portapapeles y estado «✓ Copiado», estados de error), loader `$ cargando …`, cableado de `injectAnalytics` con `VITE_PLAUSIBLE_*` en `lib/env.ts`, `@source` de Tailwind para el client del juego y la home.
>
> **Rutas:** las rutas de "Archivos a crear/modificar" son relativas a `packages/ui/`, salvo las que empiezan con `docs/` o `apps/` (raíz del repo).
>
> **Regla de compatibilidad (no negociable, igual que S-011):** `web` y `admin` tienen que seguir compilando y pasando sus tests. **Toda API existente se conserva**: lo nuevo entra como props opcionales, variants nuevas o exports nuevos. Única excepción visual acordada: `Badge` chip pasa al padding de `chip.neutral` por defecto (6 10) y el único consumidor del padding "loose" (`next-game-placeholder.tsx` de `web`) recibe `loose` en la misma tarea para no cambiar su aspecto.

### Arquitectura del Servicio (`docs/architectures/ui/overview.md`, copiado)

- **Propósito:** Paquete `@nerdose/ui` (`packages/ui`): lo visual compartido entre `web` y `admin`. Contiene los tokens (`tokens.css` con el bloque `@theme` de Tailwind v4: fondo `#0A0C0F`, acento `#3DDC84`, `--font-mono`, acentos por juego), los componentes compartidos (header, banners, share, stat cards; desde REQ-003 también `Panel`, `Badge`, `StreakPill`, `StreakNumber`, `ProgressBar`, `TerminalWindow`, `SegmentedControl`), los helpers de clases `buttonClass` y `linkClass`, el helper `cn()` y `track()` (analítica opcional de ADR-014).
- **Tipo:** Library en React 19 (TypeScript estricto), sin build propio: exporta su fuente. No importa `@nerdose/db` ni `@nerdose/core/notify`.
- **Módulos:** `tokens` (`tokens.css` con `@theme`; fuente única de los tokens visuales), `components` (componentes compartidos de `web` y `admin`), `utils` (`cn()` y `track()`).
- **Design System:** cuando `docs/design-system/` defina los tokens, mandan sobre los de `styling` y `tokens.css` debe actualizarse para coincidir.

### Convenciones de Código (`_base`, partes aplicables, copiadas)

- TypeScript obligatorio, `strict`, sin `any` salvo en bordes con librerías sin tipos (envuelto en una función tipada).
- Naming: archivos `kebab-case` (`game-header.tsx`), componentes exportados `PascalCase`, tipos `PascalCase` sin prefijo `I`, constantes `SCREAMING_SNAKE_CASE`. Un componente principal por archivo; tests al lado como `*.test.tsx`.
- Imports: (1) externos y `@nerdose/*`, (2) `@/`, (3) relativos; grupos separados por línea en blanco; `import type` para tipos.
- Shared UI va en `packages/ui`; si un componente se necesita en ambas apps, va acá en lugar de duplicarse.
- Comentarios: por defecto ninguno; solo el porqué cuando no es obvio. Sin `// TODO` sin issue.
- Async: `async/await`; las promesas rechazadas sin manejar son un bug; los handlers que llaman código async manejan o muestran el error.

### Convención `styling` (partes aplicables, copiadas)

- Tailwind CSS v4 con configuración CSS-first: los tokens viven en un bloque `@theme` en `packages/ui`, compartido por `web` y `admin`.
- **Rules:**
  - Use only the tokens (or later, the Design System's). No literal hex colors, no arbitrary `[#abc]` color values in components.
  - Tokens live only in `packages/ui`; `web` and `admin` must not redeclare them.
  - Inter for prose, JetBrains Mono for everything else, both via `@fontsource/*`, self-hosted.
  - Merge conditional classes with `cn()`; never concatenate class strings by hand.
  - Text and interactive-element contrast meets WCAG 2.1 AA against the surface it sits on (4.5:1 text, 3:1 large text and UI components). Verify any new color pair.
  - Focus is always visible: use `focus-visible:` rings with `--color-accent`; never `outline-none` without a replacement.
  - State is never conveyed by color alone: pair it with an icon, text or pattern.
  - Respect `prefers-reduced-motion`.
  - No CSS-in-JS and no component CSS files, except the token file and third-party overrides.
- **Updates from REQ-003:** no global media queries (layout con `flex-wrap` y `repeat(auto-fit, minmax(min(300px, 100%), 1fr))`); `buttonClass` / `linkClass` aplican a `<button>` y a `<Link>` sin que `ui` importe `react-router`; **los tokens crecen de forma aditiva** (se conservan los nombres existentes); **static check:** los `.tsx` no contienen valores arbitrarios (`/\[(\d|#|rgb)/`) ni utilidades genéricas (`rounded-md`, `shadow-md`, `text-2xl`, `font-semibold`).
- Valores dinámicos (ancho de barra, countdown): variable CSS vía `style={{ '--w': pct + '%' }}` consumida en una clase.

### Convención `accessibility` (partes aplicables, copiadas)

- WCAG 2.1 AA. Elementos nativos primero (`<button>`, `<a>`); ARIA solo si no hay nativo.
- Todo lo operable con mouse es operable con teclado; foco visible (`focus-visible`) en todo elemento focusable.
- El feedback que usa color también se expresa con ícono, patrón o texto.
- Resultados, errores y avisos en regiones `role="status"` (polite) o `role="alert"` (errores).
- Touch targets ≥ 44 × 44 px. Reflow a 320 px sin scroll horizontal; soporte de zoom de texto al 200%.
- **Rules:** contraste ≥ 4.5:1 texto (3:1 texto grande y bordes de UI); ningún interactivo hecho con `<div>`/`<span>` con click; cada imagen o ícono es decorativo (`aria-hidden`) o tiene nombre accesible; el color nunca es el único portador de significado; el foco nunca se quita sin reemplazo visible; las actualizaciones dinámicas se anuncian por live regions sin mover el foco; axe-core reporta cero violaciones.

### Convención `testing-unit` (partes aplicables, copiadas)

- Vitest + Testing Library en jsdom; query por rol, label o texto visible (`data-testid` solo si no hay query accesible); `userEvent`, no `fireEvent`.
- Cada componente interactivo tiene un check de axe (`expect(await axe(container)).toHaveNoViolations()`); se corrigen las violaciones, no se desactivan reglas.
- Sin snapshots de árboles grandes; sin reloj real (fake timers); nombres de test que dicen el comportamiento.
- No se mockean módulos propios salvo para aislar una unidad.

### ADRs Relevantes

#### ADR-002: Stack tecnológico (reglas aplicables, verbatim)

- Todo el código propio MUST ser TypeScript con `strict: true`. MUST NOT haber archivos `.js` de código fuente en `apps/` ni en `packages/` (salvo configuración de herramientas).
- Los estilos MUST ser Tailwind CSS v4, con los tokens en `@theme`. MUST NOT cargarse fuentes ni CSS de CDNs de terceros.
- Los textos de UI MUST pasar por i18next con claves en `es` y `en`. Los textos de contenido MUST venir resueltos desde la `api`.
- Los tests MUST usar Vitest; los e2e, Playwright.
- **Consecuencia para `ui` (vigente desde S-011):** `ui` no tiene i18next. **Ningún componente contiene texto visible traducible propio**: todo texto entra por props/`children` y lo resuelve `web` con `t()`. Excepción documentada: glifos y notación (`>`, `_`, `/`, `▌`, `//`, `✓`, `✗`, `○`, `—`) y el contenido decorativo `aria-hidden`.

#### ADR-003: Monorepo y paquetes compartidos (reglas aplicables, verbatim)

- Los paquetes internos MUST llamarse `@nerdose/<nombre>` (`@nerdose/core`, `@nerdose/db`, `@nerdose/ui`, `@nerdose/polyglot`, `@nerdose/content`, `@nerdose/game-<game_id>`).
- `apps/web` y `apps/admin` MUST NOT importar `@nerdose/db` ni `@nerdose/core/notify`.
- MUST NOT haber dependencias entre apps (`apps/*` no importa de otro `apps/*`). Lo compartido va en `packages/`.
- Las tareas (`build`, `lint`, `typecheck`, `test`) MUST orquestarse con Turborepo desde `turbo.json`.

#### ADR-014: Métricas y analítica (reglas aplicables, verbatim)

- Decisión: **Analítica web:** script de Plausible en `web` detrás del flag de build `VITE_PLAUSIBLE_DOMAIN`, con eventos `share:<game_id>`. Todo pasa por un helper `track(event)` de `@nerdose/ui`.
- `web` MUST llamar solo a `track(event)` de `@nerdose/ui`. MUST NOT referenciar `window.plausible` fuera de ese helper.
- Si `VITE_PLAUSIBLE_DOMAIN` está vacío, el build MUST NOT inyectar el script de Plausible y `track()` MUST ser un no-op.
- Si `VITE_PLAUSIBLE_DOMAIN` tiene valor, `VITE_PLAUSIBLE_SCRIPT_URL` MUST ser obligatoria (el build falla si falta), y el script MUST inyectarse con `defer` y `data-domain`.
- El evento de share MUST llamarse exactamente `share:<game_id>` (por ejemplo `share:devdle`) y MUST NOT llevar propiedades personalizadas.
- `admin` MUST NOT cargar analítica.
- **Convención `analytics` de `web` (copiada, partes que fijan la API de `ui`):** "`@nerdose/ui` exports `track(event)` and the script injector"; "With `VITE_PLAUSIBLE_DOMAIN` empty: the script is **not** injected and `track()` is a no-op"; "With a value: the script is injected with `defer` and `data-domain`, from `VITE_PLAUSIBLE_SCRIPT_URL`"; "Never reference `window.plausible` outside that helper"; "Analytics must never break the app: `track()` swallows its own errors". La validación de las variables (`VITE_PLAUSIBLE_SCRIPT_URL` obligatoria si hay dominio) vive en `apps/web/src/lib/env.ts` (plan `web`); `ui` no lee `import.meta.env`.

#### ADR-006: Contrato GameDefinition (regla que acota a `ui`)

- Las rutas de juego MUST resolver el juego por el registry. MUST NOT haber `if (game_id === '…')` ni `switch` por juego en `apps/api` ni en el shell de `apps/web`. → Las piezas de `ui` reciben el `game` como `UiGameId` y resuelven el acento con el mapa `GAME_CLASSES`, nunca con condicionales por juego.

### API Context

`ui` no hace requests. Los datos que muestran sus componentes los resuelve `web` (por ejemplo `number` de `GET /api/games/devdle/today` para el metadato `#8` del header, `global_streak` para la píldora) y los pasa ya formateados por props. La story declara "Cambios de API: Ninguno".

### Database Context

No aplica (story: "Cambios de Base de Datos: Ninguno").

### Flow Context

`ui` no participa como actor de ningún flujo. Único punto de contacto, del flujo `preferencias-y-share` (Paso 3: Compartir, solo cliente), copiado:

1. `text = share(result, number)` del `client` del juego. Nunca incluye la solución y termina en `nerdose.dev`.
2. `navigator.share({ text })` si está disponible; si no, `navigator.clipboard.writeText(text)` y el aviso "copiado".
3. `track('share:<game_id>')` de `@nerdose/ui`. Es un no-op si `VITE_PLAUSIBLE_DOMAIN` está vacío.

- Error: el usuario cancela el share nativo → `AbortError` → se ignora; no se registra el evento.
- Compartir no hace ningún request a la `api`.

Este plan implementa el `track` del paso 3; los pasos 1-2 son de `games` y `web`.

### Integration Points

- **`web` (game-host)** consume `GameHeader`, `Banner` (`success`/`failure`/`neutral`/`warning`), `buttonClass({ variant: 'icon' })`, `buttonClass({ size: 'share', … })`, `HelpIcon`/`ChartIcon`/`ShareIcon`, `StreakPill`, `SegmentedControl`, `track` e `injectAnalytics`. Arma los links (`<Link>`) por `renderHome` y por `buttonClass` sobre su propio `<Link>`.
- **`games` (devdle `./client`)** consume tokens (`text-title-game`, `text-game-tile-lg`, `text-game-tile-sm`, `text-game-key`, `text-game-key-small`, `text-body-sm`, `text-body-sm-legend`, `text-code-share`, `bg-status-absent-bg`, `text-status-absent-text`, `border-status-present`, `text-status-present`, `max-w-keyboard`, `max-w-devdle-aside`), `Badge` chip, `Panel`, `cn` y `buttonClass`.
- **Tailwind y paquetes de juego (hallazgo, lo resuelve `web`/`games`):** `tokens.css` declara `@source "./components";`, que solo escanea `packages/ui/src/components/`. Las clases que escriba el client de Devdle (`packages/games/devdle/src/client/**`) no se generan salvo que `apps/web/src/index.css` agregue su propio `@source` (por ejemplo `@source "../../../packages/games/*/src/client";`). **No se toca `tokens.css` para esto**: `ui` no debe conocer a los paquetes de juego.
- **`@nerdose/core`**: `ui` no depende de `core`. `UiGameId = 'devdle' | 'grep-grid' | 'timeline' | 'big-o' | 'bug-hunt'` (mismo union que `GAME_IDS`), así un `GameId` es asignable sin cast. El evento de analítica se tipa como `` `share:${UiGameId}` ``.
- **Plausible (externo, sin documento en `docs/references/`):** el contrato que fija ADR-014 es "script con `defer` y `data-domain` desde `VITE_PLAUSIBLE_SCRIPT_URL`" y eventos `share:<game_id>` sin propiedades. La llamada del cliente es `window.plausible(eventName)`. El stub de cola que permite llamar antes de que cargue el script (`window.plausible = window.plausible || function () { (window.plausible.q = window.plausible.q || []).push(arguments) }`) es el snippet público de Plausible: **NOT DOCUMENTED en `docs/references/` - needs verification** contra la versión de Plausible CE que se despliegue (el deploy está diferido). El plan lo encapsula en `injectAnalytics` para que, si cambia, cambie en un solo lugar.

### Hallazgos técnicos verificados durante la planificación

1. **S-011 dejó diferidas exactamente estas piezas** ("Banner `success`/`failure`/`neutral`, … Button `outline-tinted`/`ghost`/`icon`/`share` quedan para los feature groups que las consuman (FG-3 a FG-10)"). Devdle es FG-3: este plan suma las que usan sus pantallas (`success`, `failure`, `neutral`, `icon`, `share`). `outline-tinted` y `ghost` siguen diferidas: ninguna pantalla de Devdle las usa.
2. **Faltan tokens que el DS ya define** y que el client de Devdle necesita (y no puede declarar: "Tokens live only in `packages/ui`"): `type.title.game`, `type.brand.logo.compact`, `type.brand.crumb`, `type.game.tile.lg`, `type.game.tile.sm`, `type.game.key`, `type.game.key.small`, `type.body.sm`, `type.body.sm.legend`, `type.code.share`, `status.present`, `status.absent.bg`, `status.absent.text`, `text.separator`. Los anchos máximos del teclado (620 px) y del aside de Devdle (380 px) están en `foundations/spacing.md` ("Otros anchos máximos") sin token: sin token, el client tendría que escribir `max-w-[620px]`, que la guarda estática prohíbe.
3. **`cn` solo conoce los roles de `theme.ts`**: cada `--text-*` nuevo tiene que sumarse a `TEXT_ROLES` o `tailwind-merge` lo trata como color y lo descarta (`test/cn.test.ts` verifica que `theme.ts` coincida con `tokens.css`).
4. **Toda clase tiene que estar escrita literal bajo `src/components/`** (Tailwind solo escanea esa carpeta). El helper de analítica no tiene clases y puede vivir en `src/analytics.ts`.
5. **`test/public-api.test.ts` fija la lista exacta de exports** y que todos sean funciones; `src/components/components.test.ts` fija la lista de archivos fuente y prohíbe hex (`/#[0-9a-fA-F]{3,8}\b/`), arbitrarios y genéricos. Ambos se actualizan en la Tarea 7.

#### Component specs (copiados de `components/*.md`)

**`game-header` v1.0.0**
- **Propósito:** header de las 5 pantallas de partida. Reemplaza el nav por un breadcrumb de terminal `> nerdose / {juego}` con el nombre del juego en su acento, y suma las acciones de la partida. Usar en toda pantalla de juego (jugando o resultado); pantallas de plataforma → `app-header`.
- **Anatomía:** (1) Container `<header>`, `flex-wrap`, `space-between`, gap 16, padding **14 32**, `border-bottom: 1px solid #1E252E`. (2) Breadcrumb (gap 18, `flex-wrap`): Logo — link a Home, `>` en `accent.brand` + `&nbsp;nerdose`, `type.brand.logo.compact` (Mono 800 18), sin cursor; Separador `/` en `text.separator`, `aria-hidden`, hereda Inter 16; Juego — slug en kebab-case (`devdle`, `bug-hunt`, `big-o`, `tech-timeline`, `grep-grid`), `type.brand.crumb` en `game.{j}.accent`; Metadato — "desafío del 30/10[ · categoría]", `type.label.comment` (Mono 13), `text.dim`. (3) Acciones (gap 8), en este orden: button `icon` "Cómo se juega" → `icon` "Estadísticas" (link) → Compartir → language-selector → streak-pill (`<span>` con solo el número).
- **Variants:** `playing` — Compartir deshabilitado (neutro, «Disponible al terminar la partida»); `finished` — Compartir activo con el acento del juego (`accent`).
- **Sizes:** único; todos los controles miden 44px de alto.
- **States:** Compartir deshabilitado/activo (ver button); botones `icon` hover/active **Pendiente**; focus: **requisito** foco visible ≥ 3:1.
- **Spacing:** padding 14 32; sin media queries: breadcrumb y acciones envuelven; en anchos chicos las 5 acciones ocupan su propia fila.
- **Accesibilidad:** botones `icon` con `aria-label` ("Cómo se juega", "Estadísticas"); Compartir deshabilitado con `aria-disabled` y nombre que explique el motivo ("Compartir resultado (disponible al terminar)"); separador `aria-hidden`. **Breadcrumb: requisito** — exponerlo como navegación con nombre (`<nav aria-label>` con lista) y el juego actual con `aria-current="page"`. Orden visual = orden del DOM. Contraste: slug en acento sobre `#0A0C0F` ≥ 7,4:1; metadato 6,8:1; íconos 11,3:1.
- **Contenido:** slug en kebab-case, minúscula, igual en ES y EN. Metadato: "desafío del {dd/mm}" + "· {categoría}" — **el producto usa `#número`** (decisión #12, REQ-004).
- **Do:** mostrar Compartir siempre, deshabilitado mientras se juega; pintar el slug con el acento. **Don't:** agregar el nav global; poner el cursor parpadeante en el logo.
- **API (spec):** `game: GameId`, `date: string`, `category?: string`, `finished: boolean`, `onShare` / `onHelp`, `streak: number | null`.

Contraste: título sobre `#0C1A12` 15,2:1 y sobre `#1C0F0E` 15,8:1; subtítulos 10,0:1 y 9,8:1; `neutral` 7,5:1; `warning` 8,2:1.
- **Contenido:** título con el dato; fallo sin culpa. **Don't:** usar `failure` para errores del sistema; otro ícono para `warning`; más de un banner a la vez.
- **API (spec):** `variant`, `title` (no en `neutral`), `children`, `action` (slot para un Button `md`), `game` (borde de la acción en `neutral`).

**`button` v1.2.0 (partes nuevas)**
- `icon`: acción solo-ícono de 44×44, `button.icon.*` ("Cómo se juega" `circle-help`, "Estadísticas" `chart`). `aria-label` obligatorio; SVG `aria-hidden`.
- **Compartir** es `accent` (tamaño `share`) con ícono `share`: activo al terminar, deshabilitado durante el juego.
- Size `share`: 44px (alto fijo), padding horizontal 14px, gap 8px, `type.button.md`. Size `icon`: 44×44, ícono 18px.
- Deshabilitado (neutro): fondo `bg.control`, borde `border.control`, texto `text.disabled`, `cursor: not-allowed`; usar `aria-disabled="true"` (no `disabled`), el motivo va en el nombre accesible.
- Hover derivado (S-011): `secondary` borde `border.control` → `border.control.hover` (`#3A424C`), texto sin cambio. Hover de `icon`: **Pendiente** (lo deriva este plan, ver "Piezas derivadas").
- Contraste `icon` `#C3CCD5`/`#11151A` 11,3:1.

**`chip` v1.2.0**
- `chip.neutral`: sin fondo, borde `border.control`, texto `text.muted`, padding **6 10** ("git", "mutación: > → >="). `chip.neutral` loose: padding **6 12** ("próximamente").
- Mono 12 (`type.meta`), píldora, `white-space: nowrap`. No interactivos. Grupo: `flex-wrap`, gap 6. Si una lista de chips es una lista, marcarla como `<ul>`.
- **API (spec):** `kind`, `tone`, `loose: boolean = false`, `strong`, `children`.

#### Patterns — `game-boards` (lo que toca a `ui`)

#### Guidelines — Accesibilidad (`guidelines/accessibility.md`, placeholder v0.1.0, lo aplicable)

WCAG AA; foco visible ≥ 3:1; no comunicar estado solo con color; íconos decorativos `aria-hidden`, funcionales con `aria-label`; live regions para feedback dinámico; targets táctiles ≥ 44×44 con separación ≥ 8px (las acciones del header están a 8px).

#### DS Gaps — `web`

**Aceptados** (REQ-004 → Revisión UX → Design System, resolución "Dejar anotado"):
- `loader` (devdle-instrucciones/partida/resultado): "el DS no define spinners/skeletons; se resuelve con texto Mono `$ cargando …` derivado de la identidad". Lo implementa `web`; no hay pieza de `ui`.

Los demás gaps del REQ se resolvieron como **Reemplazar** (sin `pendiente-DS`): informativos → `banner` `neutral`/`warning`; `aviso-jugada` → hint del juego (`games`); grillas/teclado/distribución/leyenda → patterns de `game-boards` (`games`); `pista-categorias` → `chip.neutral`; `toast-copiado` → estado de `btn-compartir` (`web`).

**Nuevos:** ninguno. Lo que este plan deriva no son gaps de tipo sino "Pendientes dentro de piezas existentes" (ver la tabla siguiente) y se documenta en el DS en la Tarea 8.

export type AnalyticsEvent = `share:${UiGameId}`;
type Plausible = ((event: string) => void) & { q?: unknown[] };
declare global { interface Window { plausible?: Plausible } }

let enabled = false;

export function injectAnalytics({ domain, scriptUrl }: { domain: string | undefined; scriptUrl: string | undefined }): void {
  if (!domain || !scriptUrl || enabled) return;
  // stub de cola del snippet de Plausible (ver Integration Points)
  window.plausible = window.plausible ?? Object.assign(

  script.src = scriptUrl;
