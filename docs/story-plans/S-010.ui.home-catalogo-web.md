# Story Plan: S-010 (ui) - Home y catálogo en web

## Status

**Status:** Completed

## Referencia de la Story

- **Story:** [S-010](../stories/S-010.home-catalogo-web.md)
- **Servicio:** ui
- **Resumen:** Agrega a `@nerdose/ui` (`packages/ui`) los dos componentes compartidos que la home de `web` necesita sobre los tokens de `ui`: la **tarjeta** (`Card`, contenedor de las 5 tarjetas de juego y del resumen «Tu progreso») y la **alerta de error** (`Alert`, el bloque `alerta-sistema` + slot para «Reintentar»). Suma el token `--color-error` del Design System, que S-009 dejó pendiente para esta story.

> **Alcance de este plan:** solo el servicio `ui` (impacto **Bajo** en la story: «Componentes compartidos que hagan falta (tarjeta, alerta) sobre los tokens de `ui`»). Todo lo demás de S-010 es de `web` (plan `S-010.web.*`): módulo `catalog`, ruta `/`, metadatos estáticos de los 5 juegos y claves i18n, query `today`, `#número`, racha global, cuenta regresiva con refetch y jitter, CTAs por estado, loader, barra de progreso, estados de la pantalla y e2e. Este plan **no** toca `apps/web` ni `apps/admin`.
>
> **Rutas:** las rutas de "Archivos a crear/modificar" son relativas a `packages/ui/`, salvo cuando se indica la raíz del repo.
>
> **Regla clave (ADR-002):** «Los textos de UI MUST pasar por i18next con claves en `es` y `en`». `ui` no tiene i18next: **ningún componente de `ui` contiene texto visible propio**. Todo texto (nombre del juego, descripción, mensaje de error, «Reintentar») entra por props/`children` y lo resuelve `web` con `t()`.
>
> **Fuera de alcance (decisión de este plan):** botón/CTA compartido (los CTA de las tarjetas son links de `react-router` con variantes primary/secondary/disabled con `aria-disabled`; `ui` no puede importar el router y la story limita el alcance a «tarjeta, alerta»), barra de progreso, loader, etiqueta de racha, cuenta regresiva y heatmap. Los implementa `web`. Si `admin` llega a necesitarlos, se mueven a `ui` en una story futura.

## Contexto Arquitectónico

### Stack Tecnológico

- **Lenguaje:** TypeScript `strict: true`, `noUncheckedIndexedAccess: true`, `verbatimModuleSyntax: true` (`tsconfig.base.json`). Node.js 24.
- **Librería:** React 19 (`manifest.yaml` de `ui`: `type: library`, `language: react`). `react ^19.3.1` como `peerDependencies` y `devDependencies`.
- **Estilos:** Tailwind CSS v4. `ui` publica `tokens.css` (bloque `@theme` + `@source "./components";`) y clases en sus componentes; el CSS lo compilan `web` y `admin`.
- **Helper de clases:** `cn()` = `twMerge(clsx(inputs))` (`clsx ^2.1.1`, `tailwind-merge ^3.7.0`).
- **Tests:** Vitest `^5.1.0` (raíz), entorno `jsdom ^30.1.3`, `@testing-library/react ^16.3.3`, `@testing-library/jest-dom ^7.0.1`, `vitest-axe ^0.1.0`. **Se agrega** `@testing-library/user-event ^14.6.8` (misma versión que `apps/web`) para las interacciones del slot de acción de `Alert`.
- **Lint:** ESLint flat config de la raíz; `packages/ui/**/*.{ts,tsx}` en `REACT_FILES` (`jsx-a11y`, `react-hooks`) y `no-restricted-imports` contra `@nerdose/db` y `@nerdose/core/notify`.

### Arquitectura del Servicio (overview de `ui`, copiado)

### Convenciones de Código (`_base` de `ui`, aplicables)

- Naming: archivos `kebab-case` (`card.tsx`), componentes exportados `PascalCase` (`export function Card()`), tipos `PascalCase` sin prefijo `I` (`CardProps`). Un componente principal por archivo; **tests al lado del archivo** como `*.test.tsx`.
- Imports: (1) externos y `@nerdose/*`, (2) `@/` (no aplica en `ui`), (3) relativos de la misma carpeta; grupos separados por línea en blanco. Imports de solo tipos con `import type` (obligatorio por `verbatimModuleSyntax`).
- Sin `any`. Sin comentarios salvo el porqué no obvio.
- Lo compartido por `web` y `admin` va en `@nerdose/ui`, no copiado.
- Desde un paquete de juego solo se importa `./client`, y **solo desde las apps**: `ui` no importa ningún `@nerdose/game-*`.

### Convención `styling` (partes aplicables, copiadas)

- Tokens expuestos por Tailwind como `bg-bg`, `bg-surface`, `text-text`, `text-text-muted`, `text-text-dim`, `border-border`, `text-accent`, `text-game-bug-hunt`, etc. Con este plan: `text-error`, `border-error`.
- «Use only the tokens above (or later, the Design System's). No literal hex colors, no arbitrary `[#abc]` color values in components.»
- «Tokens live only in `packages/ui`; `web` and `admin` must not redeclare them.»
- «Per-game accent is applied by the game's own `client` via its token, never with a literal hex.» (En la home, el acento de cada tarjeta lo pone `web` con `text-game-<game_id>` sobre el `<h2>`; `Card` no conoce juegos.)
- «Merge conditional classes with `cn()`; never concatenate class strings by hand.»
- «Focus is always visible: use `focus-visible:` rings with `--color-accent`; never `outline-none` without a replacement.»
- «State is never conveyed by color alone: pair it with an icon, text or pattern.»
- «Respect `prefers-reduced-motion`.» (los componentes de este plan no animan)
- Dark only: sin variantes `dark:`.
- Mobile-first desde 320 px; `sm:`/`md:`/`lg:` agregan layout. Sin scroll horizontal a 320 px. Targets táctiles ≥ 44×44 px.
- Orden de clases: layout, spacing, tipografía, color, variantes de estado.
- «No CSS-in-JS and no component CSS files, except the token file and third-party overrides.»

### Convención `accessibility` (partes aplicables, copiadas)

- Landmarks para header/nav/footer; un `<main>` y un `<h1>` por página (los pone la app, no `ui`).
- Elementos nativos primero; ARIA solo si no hay nativo.
- «Every image or icon is either decorative (`aria-hidden`) or has an accessible name.»
- «Result, errors and notices appear in `role="status"` (polite) or `role="alert"` (errors) regions.»
- «Dynamic updates are announced via live regions; do not move focus unexpectedly.»
- «No interactive element is built from a `<div>` or `<span>` with a click handler; use a native control.»
- «Color is never the only carrier of meaning.»
- «axe-core reports zero violations in unit checks and e2e page checks.»

### Convención `testing-unit` (partes aplicables, copiadas)

- Vitest + React Testing Library en jsdom; axe-core vía `vitest-axe` (`toHaveNoViolations`). Setup ya existente en `test/setup.ts`.
- Consultar por rol, label o texto visible; `data-testid` solo si no hay consulta accesible.
- «Use `userEvent`, not `fireEvent`, for interactions.»
- «Each interactive component has an axe check; fix violations instead of disabling rules.»
- Sin snapshots de árboles grandes. Nombres de test que describen el comportamiento.

### ADRs Relevantes

#### ADR-003: Monorepo y paquetes compartidos (reglas verbatim, aplicables)

- El gestor de paquetes MUST ser pnpm, con workspaces declarados en `pnpm-workspace.yaml` (`apps/*`, `packages/*`, `packages/games/*`). MUST NOT usarse npm, yarn ni bun.
- Las tareas (`build`, `lint`, `typecheck`, `test`) MUST orquestarse con Turborepo desde `turbo.json`.
- Los paquetes internos MUST llamarse `@nerdose/<nombre>` (`@nerdose/core`, `@nerdose/db`, `@nerdose/ui`, `@nerdose/polyglot`, `@nerdose/content`, `@nerdose/game-<game_id>`).
- `apps/api` MUST importar solo `./definition` de cada juego. `apps/web` y `apps/admin` MUST importar solo `./client`. `apps/generator` MUST importar solo `./generator` (y `./definition` si lo necesita para validar).
- `apps/web` y `apps/admin` MUST NOT importar `@nerdose/db` ni `@nerdose/core/notify`.
- MUST NOT haber dependencias entre apps (`apps/*` no importa de otro `apps/*`). Lo compartido va en `packages/`.

Decisión: `packages/ui` = «componentes compartidos (header, banners, share, stat cards), tokens, track()».

#### ADR-002: Stack tecnológico (reglas aplicables, verbatim)

- Todo el código propio MUST ser TypeScript con `strict: true`. MUST NOT haber archivos `.js` de código fuente en `apps/` ni en `packages/` (salvo configuración de herramientas).
- `web` y `admin` MUST ser SPAs con React 19 + Vite. MUST NOT usarse SSR ni Next.js/Remix.
- Cada juego MUST cargarse en `web` con `React.lazy` en la ruta `/:game_id`. Shiki MUST cargarse solo en las rutas `big-o` y `bug-hunt`.
- Los estilos MUST ser Tailwind CSS v4, con los tokens en `@theme`. MUST NOT cargarse fuentes ni CSS de CDNs de terceros.
- Los textos de UI MUST pasar por i18next con claves en `es` y `en`. Los textos de contenido MUST venir resueltos desde la `api`.
- Los tests MUST usar Vitest; los e2e, Playwright.

> Relación con CA-7 («no importa ningún `client` de juego»): como `web` va a usar `Card`/`Alert` en la home, `ui` tampoco puede arrastrar código de juegos. La guarda de la Tarea 4 lo verifica.

### Flow Context

**primera-visita-y-sesion** (lado `web`, pasos 1, 3 y 4) y **cambio-de-dia-y-publicacion** (paso 4, copiado):

> **Paso 4: Refetch del cliente** — Origen: web · Destino: api · Tipo: REST. **Acción:** al llegar `seconds_to_reset` a 0, el front espera entre 0 y 3 s al azar y pide `GET /api/today`. TanStack Query invalida las queries de juego y de stats.

**Lo que aporta `ui`:** nada del flujo en sí. Solo los contenedores visuales: `Card` para las 5 tarjetas (visibles incluso en «error de sistema», con nombre y descripción estáticos) y `Alert` para el mensaje de error con «Reintentar». La lógica (query, refetch con jitter, estados) es de `web`.

### Código Reutilizable

- **`cn`** (`packages/ui/src/cn.ts`): `cn(...inputs: ClassValue[]): string`. Combinar las clases base de cada componente con `className` (gana la del consumidor: `cn('p-4', 'p-6') === 'p-6'`).
- **`Banner`** (`packages/ui/src/components/banner.tsx`): `Banner({ title: ReactNode; children?: ReactNode; className?: string })`. Aviso **persistente de advertencia** (`role="status"`, `border-warning`), de ancho completo con márgenes de grilla. **No** se reutiliza para el error de carga: semántica distinta (`status` polite vs `alert`), color distinto y `Alert` lleva una acción. Se toma su forma (borde izquierdo de 4px + `bg-surface` + texto coloreado) para que ambos avisos se vean de la misma familia.
- **`AppHeader` / `BrandMark`**: no se usan en este plan.
- **`tokens.css`**: `--color-surface`, `--color-border`, `--color-text`, `--color-text-muted`, más `--color-error` (nuevo, Tarea 1).
- **`test/setup.ts`, `test/vitest-axe.d.ts`**: ya configurados; los tests nuevos usan `axe` de `vitest-axe` sin setup adicional.
- **Guarda `src/components/components.test.ts`**: recorre todos los `.tsx` no-test de `src/components/`; cubre automáticamente `card.tsx` y `alert.tsx`. La Tarea 4 la amplía.
- Duplicación existente en `web` que **no** se resuelve en este plan (anotado para una story futura de `Button`): estilos de botón inline en `apps/web/src/app/not-found.tsx` (`inline-flex min-h-11 … bg-accent … text-on-accent … focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-accent`) y `apps/web/src/app/route-error.tsx` (`min-h-11 border border-border-strong px-4 text-accent …`).
