> - Imagen de despliegue, CI e infraestructura de los toolchains (decisión 14 del REQ: diferidos).

### Decisiones de planificación

1. **No cambia ninguna configuración del workspace.** `pnpm-workspace.yaml` ya incluye `packages/*`; `turbo.json` ya toma los scripts `lint`, `typecheck` y `test` del paquete; el `vitest.config.ts` raíz ya incluye `packages/*/vitest.config.ts`; y `eslint.config.js` ya impide importar `@nerdose/polyglot` desde `web`, `admin`, `api` y las entradas `./definition`/`./client` de los juegos (verificado leyendo `eslint.config.js`). "`@nerdose/polyglot` en el workspace" se cumple con **tests de regresión** que lo fijan, no con cambios de configuración. Esos tests pasan desde el primer momento: son guardas, no test-first en rojo.
2. **El título de la sección del README es contrato.** `packages/polyglot/test/integration/toolchains.ts` arma sus errores con `const HINT = 'see README "Requisitos"';` (por ejemplo `Missing toolchain: go (Go >= 1.25 required, see README "Requisitos")`). Por eso los toolchains van dentro de la sección `## Requisitos` que ya existe, sin renombrarla, y un test del workspace extrae ese nombre del archivo de `polyglot` y verifica que el README tiene ese encabezado.
3. **Las versiones se escriben igual que en los mensajes de error.** El README usa `Go >= 1.25` y `JDK 21` (ASCII, como CA-6 y como los errores de `requireToolchains`), para que quien busca el texto del error en el README lo encuentre.
4. **Cache de Turborepo.** La tarea `@nerdose/polyglot#test` tiene `cache: true` (verificado con `turbo run test --dry=json`) y la presencia de un toolchain no es un input del hash: en una máquina donde `pnpm test` ya pasó, desinstalar Go puede devolver el resultado cacheado. No se toca `turbo.json` (la convención define `test` con cache y es un caso de borde local). En cambio el README indica cómo verificar los toolchains sin cache: `pnpm --filter @nerdose/polyglot test` (corre Vitest directo, sin Turborepo).
5. **Árbol de `packages/` del README.** Hoy lista solo `core`, `db` y `ui` (faltan también `content` y `games/`, deuda previa). Este plan agrega solo `polyglot/` y actualiza la línea de introducción en consecuencia; completar `content` y `games/` queda fuera de alcance para no mezclar cambios.

### ADRs Relevantes

- **ADR-002: Stack tecnológico**
  - Decisión: TypeScript en todo, Node.js 24 LTS. El `generator` usa toolchains Go ≥ 1.25 y JDK 21 LTS; Java corre en modo *source-file* (`java Main.java`).
  - Reglas de Implementación (las que aplican a este plan, copiadas textualmente):
    - Todo el código propio MUST ser TypeScript con `strict: true`. MUST NOT haber archivos `.js` de código fuente en `apps/` ni en `packages/` (salvo configuración de herramientas).
    - `api` y `generator` MUST correr en Node.js 24 LTS. `engines.node` MUST ser `">=24 <25"`.
    - Los tests MUST usar Vitest; los e2e, Playwright.
- **ADR-003: Monorepo y paquetes compartidos**
  - Decisión: monorepo con pnpm workspaces y Turborepo; `packages/polyglot/` contiene el árbol de código, los emisores JS/Go/Java y el runner multi-lenguaje.
  - Reglas de Implementación (copiadas textualmente):
    - El gestor de paquetes MUST ser pnpm, con workspaces declarados en `pnpm-workspace.yaml` (`apps/*`, `packages/*`, `packages/games/*`). MUST NOT usarse npm, yarn ni bun.
    - Las tareas (`build`, `lint`, `typecheck`, `test`) MUST orquestarse con Turborepo desde `turbo.json`.
    - Los paquetes internos MUST llamarse `@nerdose/<nombre>` (`@nerdose/core`, `@nerdose/db`, `@nerdose/ui`, `@nerdose/polyglot`, `@nerdose/content`, `@nerdose/game-<game_id>`).
    - Cada paquete de juego MUST exponer por `exports` tres entradas: `./definition`, `./client` y `./generator`.
    - `apps/api` MUST importar solo `./definition` de cada juego. `apps/web` y `apps/admin` MUST importar solo `./client`. `apps/generator` MUST importar solo `./generator` (y `./definition` si lo necesita para validar).
    - `./definition` y `./client` MUST NOT importar `polyglot`, `node:child_process` ni nada que ejecute código.
    - `apps/web` y `apps/admin` MUST NOT importar `@nerdose/db`.
    - `@nerdose/core` MUST exponer una sola entrada `.`, isomorfa (corre en Node y en el navegador, sin dependencias de Node): MUST NOT importar `node:*`. (Hasta el ADR-017 existía una entrada `./notify`; se eliminó.)
    - `@nerdose/db` MUST ser el único lugar con el schema Drizzle y las migraciones.
    - MUST NOT haber dependencias entre apps (`apps/*` no importa de otro `apps/*`). Lo compartido va en `packages/`.
- **ADR-007: Generator worker y pipeline**
  - Decisión: el runner usa `child_process.execFile` con timeout de 10 s, usuario no root y un `main` por variante y lenguaje. Java en modo source-file.
  - Reglas de Implementación (las que aplican a este plan, copiadas textualmente):
    - El runner MUST usar `execFile` (nunca `exec` con shell), timeout de 10 000 ms, y MUST correr como usuario no root.
    - Los toolchains MUST ser Node 24, Go ≥ 1.25 y JDK 21.

### Puntos de Integración

- **`@nerdose/polyglot` — regla de usuario no root (convención `code-runner`, copiada):**
  > **Non-root user.** If the process runs as root, `RUNNER_UID` and `RUNNER_GID` must be integers greater than 0; they are passed to `execFile` as `uid`/`gid`. Without them the runner returns `{ ok: false, kind: 'runtime_error', stderr: 'runner_requires_non_root', durationMs: 0 }` and runs nothing. Not root (local development): runs as the current user. Both variables are read on every call.
  >
  > **`chown` (pending verification with the hosting).** `mkdtemp` creates the directory as `0700` owned by root, so before running as `RUNNER_UID` the runner `chown`s the directory and the source file to it.
- **Toolchains (convención `code-runner`, copiada):** "Toolchains in the environment: Node 24, Go >= 1.25, JDK 21 (Java in source-file mode, `java Main.java`)." / "Required toolchains: Node 24, Go >= 1.25, JDK 21. Versions are not silently substituted." / "testing: tests that run toolchains are integration tests and require them installed".
- **Comandos por lenguaje del runner (copiado):** `js` → `node main.js`; `go` → `go build -o main main.go` y después `<dir>/main`; `java` → `java Main.java`.
- **REQ-009, decisión 14 (copiada):** "README de arranque: Node 24, Go ≥ 1.25 y JDK 21 en el `PATH` del `generator` (el arranque no los valida: un toolchain faltante se ve como `run_<lang>` fallido con `toolchain_missing`, y el `generator` loguea un `warn` al arrancar si `go version` o `java -version` fallan). Los tests de `polyglot` y de `verify` que ejecutan toolchains son de integración y **fallan** (no se saltean) si falta uno, con un mensaje que lo nombra. Imagen, CI y aislamiento de red quedan diferidos (decisión del usuario)." El `warn` del `generator` es de S-045: el README de este plan no lo describe todavía.
