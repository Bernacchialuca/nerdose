# Story Plan: S-030 (games) - Base de reportes y recálculo de agregados en core

## Status

**Status:** Completed

## Referencia de la Story

- **Story:** [S-030](../stories/S-030.base-reportes-recalculo-core.md)
- **Servicio:** games
- **Resumen:** Implementa el miembro `culprits(p)` del contrato `GameDefinition` en la entrada `./definition` de los tres paquetes de juego existentes: Devdle devuelve 1 `term`, Grep Grid 8 `term` y Timeline 5 `timeline_fact`, cada uno con `id` y `label`. Un test por paquete verifica que los `id` coinciden con `generator.usedBankItems(p)`. Así la `api` puede validar el culpable de una anulación (`422 invalid_culprit`) y el admin puede listar los candidatos sin leer el payload ni importar `./generator`.

> **Alcance de este plan:** solo el servicio `games` (`packages/games/devdle`, `packages/games/grep-grid`, `packages/games/timeline`). Cubre la parte de **CA-4** que corresponde a los juegos. `db` (CA-1, CA-2) y `core` (CA-3, CA-5 y el tipo/miembro de CA-4) ya están **Completed** en esta misma rama (`S-030.db.*`, `S-030.core.*`).

### Estado de partida (verificado al planificar)

- `@nerdose/core` ya exporta `type Culprit` y `type CulpritKind` y declara `culprits(p: Payload): Culprit[]` como miembro **obligatorio** de `GameDefinition` (`packages/core/src/game-definition.ts`).
- Por eso hoy `tsc --noEmit` **falla** en los tres paquetes con `TS2741: Property 'culprits' is missing ...` en `src/definition/index.ts` (Devdle l. 26, Grep Grid l. 18, Timeline l. 15). Los tests de Vitest pasan porque Vitest no typechequea. El plan de `core` lo dejó anotado como consecuencia transitoria: este plan **debe** aplicarse antes de mergear la rama (`game-package`: "Changing the `GameDefinition` interface touches all five packages in the same commit"; se cumple a nivel de rama/PR).
- `usedBankItems` existe en cada `./generator`: Devdle `(p) => [p.term_id]`, Grep Grid `(p) => p.words.map((w) => w.term_id)`, Timeline `(p) => p.items.map((i) => i.fact_id)`.

### Decisiones de planificación

1. **Fórmula por juego (REQ-007, decisión 3, verbatim):** "Devdle → `[{ kind: 'term', id: p.term_id, label: p.word }]`; Grep Grid → los 8 `words` (`term_id`, `word`); Timeline → los 5 `items` (`fact_id`, `label`). Big O y Bug Hunt devolverán `[]` (solo `template`/`none`)."
2. **Orden = orden del payload = orden de `usedBankItems`.** Grep Grid recorre `p.words` (no `p.placements`); Timeline recorre `p.items` (no `p.correct_order`, que son `opaque_id`). Así `culprits(p).map((c) => c.id)` es **igual** (`toEqual`, con orden) a `usedBankItems(p)`, que es la aserción de CA-4.
3. **Big O y Bug Hunt no existen todavía** (`packages/games/` solo tiene `devdle`, `grep-grid`, `timeline`). No hay nada que implementar acá; cuando se creen sus paquetes implementarán `culprits: () => []` porque el contrato lo exige (el compilador lo impone). La parte "Big O y Bug Hunt devuelven `[]`" de CA-4 queda cubierta a nivel contrato por el plan de `core` (TS-33 de ese plan, con `makeDefinition('big-o')`). Se deja anotado; no es un bloqueo.
4. **Dónde vive el test de coincidencia.** `./definition` no puede importar `./generator` (`game-package`, y lo verifica `test/boundaries.test.ts` para archivos fuente). El test que compara contra `usedBankItems` se pone en `src/generator/culprits.test.ts` de cada paquete, porque `./generator` sí puede importar `./definition`. Los tests de comportamiento puro (forma, valores, pureza) van en `src/definition/definition.test.ts`.
5. **`culprits` contiene la solución y no es anti-spoiler.** El `label` de Devdle es la palabra del día y el de Grep Grid las 8 palabras. `culprits` es solo para el admin (`AdminChallenge.culprits`) y la validación de la anulación; la `api` nunca lo pone en una respuesta de jugador (regla de ADR-006 sobre `toPublic`/`result`). No se toca `toPublic`, así que los tests anti-spoiler existentes no cambian y deben seguir pasando.
6. **Pureza.** `culprits` es una función pura: sin I/O, sin reloj, no muta el payload y devuelve un arreglo nuevo en cada llamada (como el resto de los miembros: `toPublic` copia con `map`/spread).
7. **Sin imports nuevos de runtime.** Solo se agrega `type Culprit` si hace falta anotar; con la anotación `GameDefinition<…>` del objeto el tipo se infiere del contrato. Las únicas importaciones externas permitidas en `./definition` siguen siendo `@nerdose/core` y `zod`.

## Contexto Arquitectónico

### Stack Técnico

- TypeScript estricto (`strict: true`, `noUncheckedIndexedAccess: true`, target ES2022), ESM (`"type": "module"`).
- Monorepo pnpm + Turborepo. Scripts por paquete: `lint` (`eslint .`), `typecheck` (`tsc --noEmit`), `test` (`vitest run`).
- Zod 4 (`zod ^4.6.7`) para schemas; Vitest como runner (`expectTypeOf` disponible desde `vitest`).
- Paquetes: `@nerdose/game-devdle`, `@nerdose/game-grep-grid`, `@nerdose/game-timeline`, todos con dependencia `@nerdose/core: workspace:*`.

### Arquitectura del Servicio

`games` es una library (manifest `type: library`, `language: node`) con un paquete por juego y tres entradas separadas (ADR-003, ADR-006).

```
packages/games/<game_id>/
├── package.json              # name @nerdose/game-<game_id>, exports map below
├── src/
│   ├── definition/           # server contract: GameDefinition implementation
│   │   ├── index.ts          # exports `definition`
│   │   ├── schemas.ts        # Zod: payload, move, public view, result
│   │   └── *.test.ts         # contract tests incl. anti-spoiler
│   ├── client/               # React UI: Instructions, Game, Result, share()
│   │   ├── index.ts
│   │   └── *.test.tsx
│   ├── generator/            # GameGenerator: generate() and verify()
│   │   ├── index.ts          # exports `generator`
│   │   └── *.test.ts
│   └── shared/               # pure types and helpers used by more than one entry
└── (extra assets of the game, e.g. wordlist/ for devdle)
```

**Qué puede importar cada entrada (`game-package`, verbatim):**

| Entry | May import | Must not import |
|---|---|---|
| `./definition` | `@nerdose/core` (`.`), `zod`, `shared/` | `@nerdose/polyglot`, `node:*`, React, `./generator`, `./client`, anything that executes code |
| `./client` | `@nerdose/core` (`.`), `zod`, `react`, `@nerdose/ui`, `shared/`, types from `./definition` | `@nerdose/polyglot`, `node:*`, `./generator`, runtime code of `./definition` that carries solutions |
| `./generator` | `@nerdose/core` (`.`), `zod`, `@nerdose/polyglot`, `shared/`, `./definition` | `./client`, React |

**Reglas de `game-package` relevantes (verbatim):**

- `./definition` implements every method of `GameDefinition`; `toPublic` never includes the solution (per-game list in ADR-006).
- Every game has an anti-spoiler contract test: serialize `toPublic(payload)` and every pre-result response and verify none contains a solution value.
- `./definition` and `./client` never import `@nerdose/polyglot`, `node:child_process` or anything that executes code (enforced by ESLint, see `monorepo-tooling`).
- Changing the `GameDefinition` interface touches all five packages in the same commit.

`test/boundaries.test.ts` de cada paquete verifica que los archivos fuente de `src/definition/` solo importan `@nerdose/core`, `zod` y rutas relativas dentro de `src/definition` (Devdle) o `src/definition`/`src/shared` (Grep Grid, Timeline). Los `*.test.ts` y `test-fixtures.ts` están excluidos del chequeo, pero por claridad el test de coincidencia vive en `src/generator/`.

**Manejo de errores:** `culprits` no lanza errores. El código `invalid_culprit` (422) lo lanza la `api` (S-032) cuando el `{ kind, id }` pedido no está en `game.culprits(payload)`. Regla de `error-handling`: "Never `throw new Error(...)` in domain code."

**Testing (`testing`, reglas aplicables):**
- "Unit tests are for pure functions. If it does I/O, write an integration test." → `culprits` es puro: solo tests unitarios, sin contenedores.
- "Every game has an anti-spoiler contract test" → se mantiene sin cambios.
- "Test files are co-located or under `test/`, suffixed `.test.ts`; `describe` names the unit and `it` the scenario."
- "Reset mocks and timers between tests."

### ADRs Relevantes

**ADR-006: Contrato `GameDefinition`**

- **Decisión:** cada juego es un paquete `packages/games/<game_id>` que implementa el contrato `GameDefinition` de `@nerdose/core`, con tres entradas (`./definition`, `./client`, `./generator`) y un registry por consumidor. REQ-007 suma el miembro `culprits(p)` (el bloque de código del ADR todavía no lo muestra; queda anotado para `/product-change-technical-definition`, ver plan de `core`, decisión 9).
- **Reglas de Implementación (verbatim):**
  - Cada juego MUST vivir en `packages/games/<game_id>`, con `game_id` ∈ `devdle | grep-grid | timeline | big-o | bug-hunt`.
  - La entrada `./definition` MUST exportar un objeto que implemente `GameDefinition` de `@nerdose/core`, con todos los métodos de la interfaz.
  - Las rutas de juego de la `api` MUST resolver el juego por el registry. MUST NOT haber `if (game_id === '…')` ni `switch` por juego en `apps/api` ni en el shell de `apps/web`.
  - La `api` MUST NOT serializar `challenges.payload` en ninguna respuesta de jugador. Antes de terminar la Play solo puede responder `toPublic(payload, locale, state?)`; después, `result(payload, state)`.
  - La `api` MUST pasar `state` a `toPublic` solo si la Play está `in_progress` (sin Play o con la Play terminada, `undefined`). Con `state`, `toPublic` MAY revelar únicamente lo que el jugador ya descubrió en esa Play (Grep Grid: `words[].definition` de los `term_id` presentes en `found_words`); MUST NOT revelar nada de lo no descubierto (REQ-005).
  - `Feedback` MUST ir en el locale del jugador (`ctx.locale`), nunca como `{ es, en }` (ADR-015).
  - `toPublic` MUST NOT incluir: la palabra de Devdle, `placements` de Grep Grid, `correct_order`/`event_date`/`fact_id` de Timeline, `answer` de Big O, ni `bug_node_id`/`failing_test`/`fix`/`line_of`/`mutation` de Bug Hunt.
  - Cada juego MUST tener un test de contrato anti-spoiler: se serializa `toPublic(payload)` (sin estado y con estados intermedios, si el juego usa `state`) y toda respuesta pre-resultado, y se verifica que no contienen ningún valor de la solución.
  - `moveSchema` MUST usarse tanto en `web` (antes de enviar) como en la `api` (`@hono/zod-validator`). Si el parse falla, la respuesta es `422 invalid_move`.
  - `share(result, number)` MUST NOT incluir la solución y MUST terminar en `nerdose.dev`.
  - `generate` MUST ser determinista: el mismo `{ date, seed, history }` da el mismo `Payload`. MUST NOT usar `Math.random()` ni la hora actual.
  - `Payload` MUST incluir todos los textos que lee el jugador como `{ es, en }`. `verify` MUST fallar si falta algún idioma.
  - Sumar un juego MUST requerir solo crear su paquete y registrarlo en los tres registries, sin cambiar rutas, tablas ni lógica de rachas.
- **Aplicación:** `culprits` completa "todos los métodos de la interfaz" en los tres paquetes. Como `culprits` incluye la solución, no se usa en `toPublic` ni en respuestas de jugador.

**ADR-015: Contratos JSON y errores** — `invalid_culprit` (422) ya está en `ERROR_CATALOG` (plan de `core`). Este plan no lo lanza; lo lanza la `api` en S-032.

### Contrato en `@nerdose/core` (ya implementado)

```ts
// packages/core/src/game-definition.ts
export type CulpritKind = 'term' | 'timeline_fact';

/** Bank item referenced by a challenge; the admin picks one when voiding (REQ-007). */
export interface Culprit {
  kind: CulpritKind;
  id: string;
  label: string;
}

export interface GameDefinition<Payload, PublicView, State, Move, Feedback, Result, Stats> {
  id: GameId;
  version: number;
  moveSchema: z.ZodType<Move>;

  toPublic(p: Payload, locale: Locale, state?: State): PublicView;
  initState(p: Payload, now: Date): State;
  applyMove(p: Payload, s: State, m: Move, now: Date, ctx: MoveContext):
    { state: State; feedback: Feedback } | { error: MoveError };
  isFinished(s: State): boolean;
  result(p: Payload, s: State, locale: Locale): Result;
  isWin(r: Result): boolean;
  score(r: Result): number;

  initialStats(): Stats;
  reduceStats(prev: Stats, r: Result): Stats;
  historyLabel(r: Result): string;
  culprits(p: Payload): Culprit[];
}
```

`@nerdose/core` exporta `type Culprit`, `type CulpritKind` y `createGameRegistry` desde `.`.

### Contexto de API

No hay rutas nuevas en este servicio. El consumidor de `culprits` es la `api` (S-032), vía el registry. Forma contratada en `docs/apis/api.yaml`:

```yaml
# AdminChallenge (required: [id, game_id, date, number, status, payload, verification, void_reason, voided_at, culprits])
culprits:
  type: array
  description: Ítems de banco referenciados por el desafío (`GameDefinition.culprits`)
  items:
    type: object
    required: [kind, id, label]
    properties:
      kind: { type: string, enum: [term, timeline_fact] }
      id: { type: string, format: uuid }
      label: { type: string }
```

`VoidRequest.culprit.id`: "Obligatorio si `kind` es `term` o `timeline_fact`, prohibido si no; debe estar en `AdminChallenge.culprits`". Response `422` de `POST /api/admin/challenges/{challenge_id}/void`: "`validation_error` (body inválido) o `invalid_culprit` (el culpable no pertenece al desafío)".

**Payloads de origen (schemas Zod existentes, campos exactos):**

- Devdle `payloadSchema`: `term_id: string (min 1)`, `word: /^[A-Z]{4,12}$/`, `category`, `definition: { es, en }`, `summary: { es, en }`, `date: YYYY-MM-DD`.
- Grep Grid `payloadSchema`: `date`, `grid: string[12][12]`, `words: Array<{ term_id, word, definition: { es, en } }>` (`.length(WORDS_COUNT)` = 8), `placements: Array<{ term_id, from, to, direction }>` (8).
- Timeline `payloadSchema`: `date`, `prompt: { es, en }`, `items: Array<{ fact_id, opaque_id: /^[a-z0-9]{6}$/, label: string (min 1), category, event_date, date_precision, note: { es, en } }>` (`.length(ITEMS_COUNT)` = 5), `correct_order: string[5]` (de `opaque_id`).

### Contexto de Base de Datos

Sin cambios. Referencia: `challenges.payload` (jsonb) guarda el payload completo; los `id` de culpable son `terms.id` (Devdle, Grep Grid) y `timeline_facts.id` (Timeline), que la `api` pasa a `status = 'rejected'` al anular (paso 2.4 del flujo).

### Contexto de Flujo

**anulacion-de-desafio** (`docs/flows/anulacion-de-desafio.md`), paso 1 — este plan provee la pieza que valida el culpable:

> **Paso 1: Pedido de anulación** — Origen: admin → Destino: api (REST). `POST /api/admin/challenges/{challenge_id}/void`, `Authorization: Bearer <jwt>`.
> ```json
> {
>   "void_reason": "string — obligatorio",
>   "culprit": {
>     "kind": "term | timeline_fact | template | none",
>     "id": "uuid — obligatorio si kind es term o timeline_fact"
>   }
> }
> ```
> Validaciones: JWT válido → el challenge existe → `challenges.status == 'published'` (si no, `409 not_voidable`).

REQ-007 agrega a este paso: "Culpable: si `kind ∈ {term, timeline_fact}`, `game.culprits(payload)` debe contener `{ kind, id }` (un `term` no vale para Timeline ni un `timeline_fact` para Devdle/Grep Grid) → si no, `422 invalid_culprit` antes de escribir nada (CA 21)."

> **Paso 2.4** — según `culprit.kind`: `term` → `terms` UPDATE `status = 'rejected'`, `rejection_reason = void_reason` WHERE `id = culprit.id`; `timeline_fact` → `timeline_facts` (ídem); `template` / `none` → sin cambios.

**Qué cambia este plan en el flujo:** ningún paso; implementa `culprits(p)` que la `api` usa en el paso 1 y que alimenta `AdminChallenge.culprits` en `admin-login-y-consultas` paso 2.
