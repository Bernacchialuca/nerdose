# Story Plan: S-058 (web) - Quitar la analítica (Plausible) de la plataforma

## Status

**Status:** Completed

## Referencia de la Story

- **Story:** [S-058](../stories/S-058.quitar-analitica-plausible.md)
- **Servicio:** web
- **Resumen:** `apps/web` deja de tener analítica y deja de leer variables `VITE_PLAUSIBLE_*`. Se borran `src/lib/analytics.ts`, `analytics.test.ts`, `src/lib/env.ts` y `env.test.ts`; `main.tsx` deja de llamar a `initAnalytics()`; `ShareButton` deja de llamar a `track`; los 5 tests de ruta (`game`, `grep-grid`, `timeline`, `big-o`, `bug-hunt`) dejan de mockear y esperar `track` conservando los casos de share nativo, copia y cancelación; se borra el test TS-5 de `game-host-boundaries.test.ts`. Se actualiza el catálogo de código reutilizable de `web`. Story de borrado: no se agrega código de producto nuevo ni hay cambios visuales.

> **Alcance de este plan:** solo el servicio `web` (`apps/web` y `docs/reusable-code/web/`). Queda **fuera**:
> - **`ui`** (misma story, plan `S-058.ui.quitar-analitica-plausible.md`): `packages/ui/src/analytics.ts`, su test, los exports de `src/index.ts` y `test/public-api.test.ts` (CA-2).
> - **`games`** (misma story, plan `S-058.games.*`): listas prohibidas de `packages/games/*/test/boundaries.test.ts` (CA-5, parte de juegos).
> - **`admin`**: nada que borrar (CA-6, verificado en la story).
> - **Documentación técnica** (`docs/architectures/web/**`, ADR-014, flujo `preferencias-y-share`, PRD, UX): ya actualizada con el cambio de alcance. No se toca.
>
> **Orden con `ui` (CRÍTICO):** este plan se implementa **antes** que el de `ui` o **en el mismo cambio**. Hoy `web` importa `injectAnalytics` y `track` de `@nerdose/ui`; si `ui` borra los exports primero, `pnpm typecheck` de `web` falla (CA-7). Este plan por sí solo deja `web` verde con `ui` todavía exportando los helpers (simplemente ya no los usa).
>
> **Rutas:** las de «Archivos a crear/modificar» son relativas a `apps/web/`, salvo las que empiezan con `docs/` o `packages/` (raíz del repo).

### Convenciones activas (partes aplicables, verbatim)

#### `_base`

- «Entry point is `index.html` + `src/main.tsx`, which mounts `<App />` inside `StrictMode`.»
- «All `import.meta.env` access happens in **one place** (`src/lib/env.ts`), validated with Zod at module load so a bad build fails fast.»
- «Known variables: none. The Plausible variables (`VITE_PLAUSIBLE_*`) were removed with web analytics in REQ-011; a new variable goes through `src/lib/env.ts` as above.»
- «Default: no comments. Clear names explain the code.» / «Comment only the why when it is not obvious.»
- «Type-only imports use `import type`.»
- Orden de imports: «(1) external libraries and `@nerdose/*`, (2) `@/` imports, (3) relative imports from the same folder. Separate groups with a blank line.»

Consecuencia (decisión de la story): con cero variables conocidas, `src/lib/env.ts` se borra. Si en el futuro hace falta una `VITE_*`, se vuelve a crear según `_base`.

#### `game-clients` (Share, verbatim)

- «`share(result, number, locale)` produces the text. The shell calls `navigator.share({ text })` when available and falls back to `navigator.clipboard.writeText`, with a visible confirmation message. Sharing emits no analytics event (web analytics was removed in REQ-011).»
- «Share text is never built by the shell; it always comes from the game's `share()`.»

#### `testing-unit` (reglas aplicables, verbatim)

- «Mock the network with MSW, never the app's own modules (api client, hooks) except to isolate a single unit.»
- «Tests do not rely on the real date or timers; use fake timers.»
- «Test names state the behavior ("shows ... when ..."), not the implementation.»
