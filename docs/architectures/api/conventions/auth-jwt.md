# Authentication JWT (Node, hono/jwt)

Admin authentication for `/api/admin/*` (ADR-010): the password is checked against a scrypt hash with `node:crypto`, and a short-lived HS256 JWT is issued and verified with `hono/jwt`. Service-local replacement of the catalog default (jose, access + refresh): there is one owner, no refresh tokens and no roles.

## When to use

- The `api`, for the `/api/admin/*` routes only.
- Player identity does not use JWT (see `player-identity`).

## Package

```
hono               # hono/jwt: sign, verify, jwt middleware
node:crypto        # scrypt, timingSafeEqual, randomBytes (built in)
```

## Configuration

```ts
// apps/api/src/domain/admin/admin-auth.ts
import { scrypt, timingSafeEqual } from 'node:crypto';
import { promisify } from 'node:util';
import { sign } from 'hono/jwt';

const scryptAsync = promisify(scrypt) as (pw: string, salt: Buffer, len: number, opts: object) => Promise<Buffer>;

// ADMIN_PASSWORD_HASH = scrypt$<N>$<r>$<p>$<salt_base64>$<hash_base64>
export async function verifyPassword(password: string, stored: string): Promise<boolean> {
  const [, N, r, p, salt, hash] = stored.split('$');
  const expected = Buffer.from(hash!, 'base64');
  const actual = await scryptAsync(password, Buffer.from(salt!, 'base64'), expected.length,
    { N: Number(N), r: Number(r), p: Number(p) });
  return actual.length === expected.length && timingSafeEqual(actual, expected);
}

export async function signAdminToken(secret: string, now = Math.floor(Date.now() / 1000)) {
  const exp = now + 28800; // 8 h
  const token = await sign({ sub: 'admin', iat: now, exp }, secret, 'HS256');
  return { token, expires_at: new Date(exp * 1000).toISOString() };
}
```

## How to use

### Login

```ts
// POST /api/admin/login  (rate limited: 5 / 15 min / IP, see security)
const { password } = c.req.valid('json');
if (!(await verifyPassword(password, env.ADMIN_PASSWORD_HASH))) throw new AppError('invalid_credentials');
return c.json(await signAdminToken(env.ADMIN_JWT_SECRET)); // 200 { token, expires_at }
```

### Protecting admin routes

```ts
// apps/api/src/domain/admin/admin-auth.middleware.ts
import { jwt } from 'hono/jwt';

export const adminAuth = (secret: string) => [
  jwt({ secret, alg: 'HS256' }),   // reads Authorization: Bearer <token>
];

// on failure the middleware error is translated by the global handler to 401 unauthorized
admin.use('/api/admin/*', skipFor(['/api/admin/login', '/api/admin/health'], adminAuth(env.ADMIN_JWT_SECRET)));
```

The middleware also checks the claims: `sub === 'admin'` and a non-expired `exp`.

### Generating the hash

```bash
pnpm --filter api admin:hash   # reads the password from stdin, prints scrypt$N$r$p$salt$hash
```

## Rules

- The password is compared with `crypto.scrypt` and `crypto.timingSafeEqual`. No plain-text password variable exists anywhere.
- `ADMIN_PASSWORD_HASH` has the format `scrypt$<N>$<r>$<p>$<salt_base64>$<hash_base64>`; the repo ships the `admin:hash` script to generate it.
- The token is a JWT HS256 signed with `hono/jwt` and `ADMIN_JWT_SECRET` (>= 32 random bytes). Claims are exactly `sub: "admin"`, `iat` and `exp = iat + 28800`.
- Never use `jsonwebtoken` or `jose`, and never use another algorithm: `alg` is pinned to `HS256` on verification.
- `POST /api/admin/login` answers `200 { token, expires_at }` (ISO 8601 UTC) or `401 invalid_credentials`.
- Every `/api/admin/*` route except `POST /api/admin/login` and `GET /api/admin/health` requires a valid `Authorization: Bearer <jwt>`; otherwise `401 unauthorized`.
- There are no refresh tokens, no roles and no multiple users. Rotating `ADMIN_JWT_SECRET` invalidates all sessions.
- `/api/admin/*` never reads or emits the `nd_pid` cookie.
- Secrets come from `env`, never hardcoded; the secret and the hash are never logged.
- In tests: use a test secret and a hash generated by `hashPassword`; do not skip verification.

## Integration with other conventions

- **http-server**: the middleware is mounted on `/api/admin/*`.
- **error-handling**: invalid credentials and token failures become `invalid_credentials` and `unauthorized`.
- **security**: the login route has its own rate limit (5 / 15 min / IP).
- **env-config**: `ADMIN_PASSWORD_HASH` and `ADMIN_JWT_SECRET` are validated at startup.
