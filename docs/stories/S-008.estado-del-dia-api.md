# S-008: Estado del día en la api

**Status:** Completed
**Created:** 2026-11-04
**Source:** REQ-002

## Historia de Usuario

**Como** jugador de Nerdose,
**quiero** consultar el estado del día (número de desafío, cuenta regresiva y estado de los 5 juegos) con o sin sesión,
**para** ver el catálogo y saber cuándo llega el próximo desafío.

## Criterios de Aceptación

### CA-1: Número de desafío

**DADO** hoy `2026-12-01` y `LAUNCH_DATE = 2026-11-24`
**CUANDO** se consulta `GET /api/today`
**ENTONCES** `number = 8` (REQ CA 8)

### CA-2: Sin desafíos

**DADO** que no existen generadores ni desafíos publicados
**CUANDO** se consulta el estado del día
**ENTONCES** los 5 juegos devuelven `challenge_status = none`, `global_streak = { current: 0, max: 0 }` y `completed_today = 0` (REQ CA 9)

### CA-3: Sin sesión

**DADO** un navegador sin cookie
**CUANDO** se consulta `GET /api/today`
**ENTONCES** `200` con `has_session = false`, los 5 juegos, número y cuenta regresiva, sin estado de partidas (REQ CA 11)

### CA-4: Con sesión

**DADO** una cookie válida
**CUANDO** se consulta el estado del día
**ENTONCES** `has_session = true`; `play_status` y `history_label` en `null`, `current_streak` en 0

### CA-5: Fecha del cliente ignorada

**DADO** que el cliente envía una fecha propia en la consulta
**CUANDO** el servidor responde
**ENTONCES** la ignora y usa el día UTC del servidor (REQ CA 12)

### CA-6: Antes del lanzamiento

**DADO** que hoy es anterior a `LAUNCH_DATE`
**CUANDO** se consulta el estado del día
**ENTONCES** `number = null` y el resto del catálogo responde normalmente (REQ CA 17)

### CA-7: Idioma y límite

**DADO** `?lang=` o `Accept-Language`
**CUANDO** se responde
**ENTONCES** se resuelve el idioma (Player → `lang`/`Accept-Language` → `es`); sobre 600 req/min por IP responde `429` con `Retry-After`

## Diseño Técnico

### Servicios Afectados

| Servicio | Impacto | Cambios Necesarios | Estado |
|----------|---------|-------------------|--------|
| api | Medio | Módulo `publishing` mínimo: `TodayCache` con repositorio que devuelve lista vacía, handler de `GET /api/today` con `playerSession('optional')` y `locale` | Done |
| docs | Bajo | `Today.number` nullable en `docs/apis/api.yaml`; convenciones `platform-day` de `api` y `core` actualizadas (ya aplicado) | Done |

### Cambios de API

#### Endpoints Existentes a Modificar

**`GET /api/today`** (ref: `docs/apis/api.yaml` l. 158; schema `Today` l. 1077)
- **Cambio:** `Today.number` pasa a `{ type: integer, minimum: 1, nullable: true }` (`null` antes del lanzamiento). Ya aplicado en `api.yaml`.
- **Justificación:** no devolver números ≤ 0 antes del lanzamiento (REQ CA 17).
- **Implementación:** query `lang?`; funciona sin cookie; `429` a 600 req/min por IP.

#### Nuevos Endpoints

Ninguno.

### Cambios de Base de Datos

Ninguno. No hay tabla `challenges` en este request: la `TodayCache` se alimenta de un repositorio vacío. Sin sesión no se consulta la base; con sesión tampoco se leen `plays` ni estadísticas.

### Flujo de Interacción

#### Escenario: estado del día (CA 8, 9, 11, 12, 17)

**Trigger:** `GET /api/today`.

1. **[api - publishing]** `today = today(clock.now())`, `number = challengeNumber(today, LAUNCH_DATE)`, `next_reset_at`, `seconds_to_reset`.
2. **[api - publishing]** `TodayCache` vacía → 5 juegos con `challenge_status: none`.
3. **[api]** Idioma: `locale` del Player → `?lang`/`Accept-Language` → `es`. Response `200 Today`.

**Outcome:** contrato completo del día, con campos de partida vacíos que FG-3 llenará sin cambiar la API.

**Manejo de errores:** `429` con `Retry-After`; `500 internal_error` con formato común.

### Flujos Afectados

- **primera-visita-y-sesion** (ref: docs/flows/primera-visita-y-sesion.md) — implementa los pasos 1 y 3 (hasta FG-3 sin lecturas de `plays`/stats).
- **cambio-de-dia-y-publicacion** (ref: docs/flows/cambio-de-dia-y-publicacion.md) — el cálculo del nuevo día; la publicación single-flight queda para FG-3.
