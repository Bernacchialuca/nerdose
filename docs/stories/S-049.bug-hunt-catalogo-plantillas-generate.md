# S-049: Bug Hunt: catálogo de plantillas, mutaciones y generate

**Status:** Completed
**Created:** 2026-11-14
**Source:** REQ-010

## Historia de Usuario

**Como** Sistema,
**quiero** generar de forma determinista un desafío de Bug Hunt a partir de una plantilla con parámetros y una sola mutación,
**para** ofrecer cada día una función de 8 a 15 líneas con un bug que se pueda encontrar.

## Criterios de Aceptación

### CA-1: Generación completa

`generate` elige plantilla, parámetros y una mutación, calcula los tests con `evaluate` y produce el payload completo con `code` en 3 lenguajes, `bug_line`, `pickable_lines`, `fix` y explicación bilingüe (REQ CA 11)

### CA-2: Mutante equivalente

Una mutación sin ningún test que falle se descarta y se prueba otro sitio, plantilla o parámetros (REQ CA 12)

### CA-3: Pocos tests que pasan

Un candidato donde la mutada pasa menos de 2 tests se descarta (REQ CA 14)

### CA-4: Test oculto

`failing_test` es el más chico de los que fallan y no está entre los 2–3 `visible_tests` (REQ CA 15)

### CA-5: Variedad

Una combinación plantilla + parámetros + mutación usada en los últimos 60 días (o próximos 60) se descarta, contando `approved`, `published` y `voided` (REQ CA 16)

### CA-6: Determinismo y distribución

Mismo `{ date, seed, history }` produce el mismo payload; con 2000 seeds cada `bug_type` sale entre 8 % y 22 %; una simulación de 180 días no falla por variedad

### CA-7: Catálogo

≥ 12 plantillas, cada una con `evaluate(build)` igual a `reference` en ≥ 500 entradas por combinación, 8–15 líneas y ≤ 3 niveles en los 3 lenguajes, `checkPortable` limpio y cada `bug_type` aplicable en ≥ 4 plantillas

### Cambios de API

Sin cambios.

### Cambios de Base de Datos

Ninguno.

### Flujo de Interacción

1. **[generator - generate]** tipo de bug uniforme, plantilla, parámetros.
2. **[generator - tests]** casos borde y al azar hasta 10; `expected = evaluate(correcta)`.
3. **[generator - mutación]** sitios barajados con el `rng`; primer candidato válido.
4. **[generator - payload]** test oculto, visibles, código, líneas, fix y explicación.

### Flujos Afectados

- **generacion-diaria** (ref: docs/flows/generacion-diaria.md) — paso 3 (se edita en S-050)

### Consideraciones Técnicas

Plantillas iniciales: `extreme_index`, `count_where`, `sum_range`, `first_index_where`, `last_index_where`, `all_where`, `any_where`, `binary_search`, `is_palindrome`, `max_window_sum`, `is_sorted`, `count_equal_neighbors`. Strings fuera de v1. Operadores por `bug_type` según la decisión 5 del REQ. Lógica pura sobre `polyglot`, sin ejecutar procesos.
