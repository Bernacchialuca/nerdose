# S-003: Esqueleto de la api con health

**Status:** Ready
**Created:** 2026-11-03
**Source:** REQ-001

## Historia de Usuario

**Como** desarrollador de Nerdose,
**quiero** una `api` Hono mínima con `GET /api/health` y `GET /api/admin/health`,
**para** verificar la conexión a la base con el rol `nerdose_api` y tener la base técnica sobre la que se agregan los endpoints de negocio.

## Criterios de Aceptación

### CA-1: Health OK

**DADO** el entorno en marcha y la base migrada
**CUANDO** se solicita `GET /api/health`
**ENTONCES** responde `200` con `{ "status": "ok", "db": "ok" }` (REQ AC 5)

### CA-2: Health admin OK

**DADO** el entorno en marcha
**CUANDO** se solicita `GET /api/admin/health` sin autenticación
**ENTONCES** responde `200` con `{ "status": "ok", "db": "ok" }` (REQ AC 6, a nivel de `api`)

### CA-3: Base no disponible

**DADO** PostgreSQL no disponible
**CUANDO** se solicita cualquiera de los dos health
**ENTONCES** responde `503 { "status": "degraded", "db": "error" }` en menos de 3 s, sin colgarse y sin exponer detalles internos (REQ AC 13)

### CA-4: Variable de entorno faltante

**DADO** falta `DATABASE_URL` u otra variable requerida
**CUANDO** se arranca la `api`
**ENTONCES** el proceso aborta al inicio con código distinto de 0 y un mensaje que nombra la variable (REQ AC 14)

### CA-5: Rol observable al arrancar

**DADO** la base migrada y `.env.local` configurado
**CUANDO** arranca la `api`
**ENTONCES** registra `{ db_role: 'nerdose_api' }`; si la base no responde, registra `warn` y arranca igual (REQ AC 4, parte `api`)

### CA-6: Ruta inexistente

**DADO** la `api` en marcha
**CUANDO** se solicita una ruta no definida
**ENTONCES** responde `404 { "error": { "code": "not_found", "message": "…" } }`

## Diseño Técnico

### Servicios Afectados

| Servicio | Impacto | Cambios Necesarios | Estado |
|----------|---------|-------------------|--------|
| api | Alto | Bootstrap Hono, `env.ts` (`@t3-oss/env-core`), logger Pino, `buildApp(deps)`, `GET /api/health` y `GET /api/admin/health`, registry de juegos vacío (`games/registry.ts`), `infra/database` con ping, verificación del rol, `.env.example` | Pending |

### Cambios de API

Se implementan **sin cambios de contrato** (ref: `docs/apis/api.yaml`):

- `GET /api/health` (`getHealth`, `security: []`): `200 Health {status: ok, db: ok}` / `503 Health {status: degraded, db: error}`.
- `GET /api/admin/health` (`getAdminHealth`, `security: []`): mismo chequeo, no exige JWT.

Schema `Health` sin cambios.

### Cambios de Base de Datos

Ninguno (solo `SELECT 1` y `SELECT current_user`).

### Flujo de Interacción y Consideraciones Técnicas

- `buildApp(deps)` con `requestId()`, `requestContext(logger)`, `secureHeaders()`, `app.onError(errorHandler)` y `app.notFound`. Sin CORS.
- Ambas rutas comparten handler que llama a `deps.health.check()`; el ping (`SELECT 1`, timeout 2 s) vive en `infra/database`, el handler no accede a la base.
- El error de la base va al log (`warn`), no a la respuesta.
- `errorHandler` con mensaje en español fijo (sin resolución de locale todavía). Middlewares de `Origin`/`Content-Type` y rate limit llegan con la primera mutación (Feature Group 2).
- Variables en `env.ts`: `NODE_ENV`, `PORT` (default 3000), `LOG_LEVEL`, `SERVICE_NAME`, `DATABASE_URL` (rol `nerdose_api`). `.env.example` con valores vacíos y comentarios.
- **Pruebas:** `app.request` contra la base real (200); contra URL inalcanzable con driver real (503 en < 3 s); `createEnv` sin `DATABASE_URL` falla nombrando la variable.
