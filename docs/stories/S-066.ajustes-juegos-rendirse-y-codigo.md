# S-066: Ajustes de juegos: código sin scroll, Rendirse en Devdle y pista en el lateral

**Status:** Completed
**Created:** 2026-11-25
**Source:** REQ-012

> **Retroactiva:** implementada fuera del workflow el 2026-11-25 (rama `feature/ajustes-juegos`, commits `3a0dde1`, `63d3b49`, `81427dc`, `45be8f2` y `5f5b452`, merge `27c1e2d`) y documentada después. **Sin story plan** (implementado fuera del workflow, sin story plan). `api.yaml` (jugada `give_up`) y `button.md` (changelog de `error-outline`) se actualizaron en esa misma rama.

## Historia de Usuario

**Como** jugador,
**quiero** leer el código sin scrollear de costado, poder rendirme en Devdle, tener la pista a mano y ver que los botones se pueden tocar,
**para** jugar más cómodo sin cambiar las reglas.

## Criterios de Aceptación

### CA-1: Código sin scroll horizontal (Big O y Bug Hunt)

**DADO** una línea de código más ancha que el bloque
**CUANDO** se muestra en la partida, el resultado o el fix
**ENTONCES** salta de línea con sangría colgante: la sangría queda fija a la izquierda y la continuación arranca alineada con el código de esa línea (`CodeText`); el número de línea, la barra y los tags no se mueven

### CA-2: Resultado de Bug Hunt sin tipo de bug

El resultado del jugador ya no muestra el chip «tipo: …»; la preview del admin lo sigue mostrando

### CA-3: Cursor de mano

Todo `<button>` y `[role=button]` habilitado muestra `cursor: pointer` (regla base en `packages/ui/src/tokens.css`); los deshabilitados (`disabled` o `aria-disabled="true"`) no

### CA-4: Variant `error-outline`

`buttonClass({ variant: 'error-outline' })` da borde `status-error-border`, texto `status-error-soft`, sin relleno, hover con borde `status-error` y fondo `status-error-bg`, peso 500; deshabilitado, neutro con `cursor-not-allowed`. «⚑ Rendirse» de Devdle y de Grep Grid lo usan (Grep Grid deja su clase local)

### CA-5: Rendirse en Devdle

**DADO** una partida de Devdle en curso
**CUANDO** el jugador toca «⚑ Rendirse» (lateral, ancho completo) y confirma «Sí, rendirme» en el diálogo («¿Rendirte?», «Vas a cerrar la partida con N de 6 intentos usados…», foco en «Seguir jugando»)
**ENTONCES** se envía `{ give_up: true }`, la Play cierra `lost` con `result.gave_up: true` y `score` 6, cuenta para la racha, la distribución suma una derrota y el resultado muestra el banner `failure` «Te rendiste: X/6» con la palabra (C-55)

### CA-6: Rendirse solo con la partida en curso

Después de rendirse no se acepta ninguna jugada (`invalid_move`) y no se puede rendir una partida terminada; `moveSchema` solo acepta `give_up: true`. Si la jugada de rendirse falla, el diálogo vuelve a quedar disponible para reintentar o cerrar

### CA-7: Pista en el lateral

**DADO** una partida de Devdle en curso sin pista
**CUANDO** el jugador toca «💡 Pista» (botón `secondary` de ancho completo, justo arriba de «Rendirse»)
**ENTONCES** el botón pasa a «Cancelar» (`aria-pressed`), las casillas libres de la fila actual se vuelven botones «Revelar la letra N» (las posiciones ya resueltas en verde no), el hint dice «> tocá una casilla de la fila actual para revelar su letra · Esc cancela», y Escape, «Cancelar» o escribir cancelan la elección; al tocar una casilla se envía `{ hint }` y el botón queda «💡 Letra N: X» deshabilitado

### Cambios de API

#### Endpoints Existentes a Modificar

**`POST /api/games/{game_id}/today/move`** (ref: docs/apis/api.yaml, `DevdleMove`, `DevdleState`, `DevdleResult`, `DevdleFeedback`)
- **Cambio:** Devdle acepta `{ give_up: true }`; feedback `{ gave_up: true }`; `state.gave_up` y `result.gave_up`.
- **Justificación:** C-55.

### Cambios de Base de Datos

Ninguno.

### Flujo de Interacción

#### Escenario: rendirse en Devdle

1. **[web - Devdle]** «⚑ Rendirse» → `SurrenderDialog` (`alertdialog`) → «Sí, rendirme» → `onMove(giveUpMoveSchema.parse({ give_up: true }))`.
2. **[api]** `applyMove` → `isFinished` → cierre `lost`, rachas y stats en la misma transacción → `200 { feedback: { gave_up: true }, result, streaks, game_stats }`.
3. **[web]** muestra `devdle-resultado` con «Te rendiste: X/6».

**Manejo de errores:**
- La jugada falla → el diálogo vuelve a `open` (se puede reintentar o cerrar).

### Flujos Afectados

- **jugada-y-cierre-de-partida** (ref: docs/flows/jugada-y-cierre-de-partida.md) — jugada `give_up` de Devdle y cierre con `result.gave_up`.
