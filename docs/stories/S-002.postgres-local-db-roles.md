# S-002: PostgreSQL local, db y migración de roles

**Status:** Ready
**Created:** 2026-11-03
**Source:** REQ-001

## Historia de Usuario

**Como** desarrollador de Nerdose,
**quiero** levantar PostgreSQL 16 con Docker Compose y aplicar una migración que cree los roles de servicio,
**para** que `api` y `generator` se conecten con permisos mínimos y sin DDL.

## Criterios de Aceptación

### CA-1: PostgreSQL local disponible

**DADO** un equipo con Docker instalado y el repositorio clonado
**CUANDO** se ejecuta `docker compose up`
**ENTONCES** PostgreSQL 16 queda disponible en `127.0.0.1:5432` (REQ AC 1)

### CA-2: Migración crea roles

**DADO** PostgreSQL 16 en ejecución y vacío
**CUANDO** se ejecuta `pnpm --filter @nerdose/db db:migrate`
**ENTONCES** se aplican las migraciones y existen `nerdose_owner`, `nerdose_api` y `nerdose_generator` con sus `GRANT` (REQ AC 2)

### CA-3: Migración idempotente

**DADO** una base ya migrada
**CUANDO** se ejecuta `db:migrate` nuevamente
**ENTONCES** termina sin errores y sin cambios (REQ AC 3)

### CA-4: DDL rechazado para roles de servicio

**DADO** conexiones como `nerdose_api` y `nerdose_generator`
**CUANDO** ejecutan `CREATE TABLE t (id int)`
**ENTONCES** PostgreSQL rechaza con `42501 permission denied for schema public` (REQ AC 15)

### CA-5: Credenciales sin versionar

**DADO** `DATABASE_URL_API` y `DATABASE_URL_GENERATOR` definidas
**CUANDO** termina `db:migrate`
**ENTONCES** se ejecuta `ALTER ROLE` con la contraseña de cada URL, validando que el usuario sea el rol esperado, y se puede conectar con esas URLs; ninguna contraseña está en el repo (REQ AC 16)

### CA-6: Base caída al migrar

**DADO** PostgreSQL apagado
**CUANDO** se ejecuta `db:migrate`
**ENTONCES** sale con código 1 y un mensaje de conexión

### Cambios de Base de Datos

Sin tablas nuevas. Nueva migración `0000_roles_and_grants` (SQL manual, `drizzle-kit generate --custom`) en `packages/db/migrations/`:

```sql
DO $$ BEGIN
  IF NOT EXISTS (SELECT 1 FROM pg_roles WHERE rolname = 'nerdose_api') THEN
    CREATE ROLE nerdose_api LOGIN;
  END IF;
  IF NOT EXISTS (SELECT 1 FROM pg_roles WHERE rolname = 'nerdose_generator') THEN
    CREATE ROLE nerdose_generator LOGIN;
  END IF;
END $$;

REVOKE CREATE ON SCHEMA public FROM PUBLIC;
GRANT USAGE ON SCHEMA public TO nerdose_api, nerdose_generator;

DO $$ BEGIN
  EXECUTE format('REVOKE CREATE, TEMPORARY ON DATABASE %I FROM PUBLIC', current_database());
  EXECUTE format('GRANT CONNECT ON DATABASE %I TO nerdose_api, nerdose_generator', current_database());
END $$;
```

- No se usa `ALTER DEFAULT PRIVILEGES` (ADR-004 exige `GRANT` explícitos por tabla y columna).
- Los roles se crean sin contraseña; `nerdose_owner` ya existe antes de migrar (Compose en local, `createRoles` en tests).

### Flujo de Interacción y Consideraciones Técnicas

**Script `db:migrate`** (`packages/db/scripts/migrate.ts`, con `tsx`):
1. conecta con `DATABASE_URL_OWNER`;
2. aplica las migraciones (`drizzle-orm/postgres-js/migrator`, registro en `drizzle.__drizzle_migrations`);
3. si están definidas, sincroniza contraseñas de `nerdose_api`/`nerdose_generator` desde `DATABASE_URL_API`/`DATABASE_URL_GENERATOR`;
4. cierra la conexión y sale con 0, o con 1 y mensaje si falla.

**`@nerdose/db/testing`:** `createRoles(adminUri)` crea `nerdose_owner` (dueño de `public`), `nerdose_api` y `nerdose_generator` con contraseñas aleatorias y devuelve sus URLs; `migrateAsOwner(url)`; `truncateAll(owner)` (no-op hoy).

**Pruebas (integración, Testcontainers):** las migraciones crean los roles; una segunda ejecución no aplica nada; `CREATE TABLE` como cada rol de servicio da `42501`; el paso de credenciales permite conectar con la URL del rol.

**Riesgos:** en local `nerdose_owner` es superusuario del contenedor (en Testcontainers no); las pruebas de permisos corren con roles de servicio. `pnpm test` depende de Docker; el `globalSetup` falla con mensaje claro sin daemon. Seguridad: PostgreSQL solo en loopback; `DATABASE_URL_OWNER` solo lo lee el script de migración.
