# S-043: Paquete Big O: definición y registro en la api

**Status:** Completed
**Created:** 2026-11-14
**Source:** REQ-009

## Historia de Usuario

**Como** jugador,
**quiero** poder empezar, jugar y cerrar una partida de Big O con validación en el servidor,
**para** responder la complejidad del código y que mi racha y mis estadísticas se actualicen.

## Criterios de Aceptación

### CA-1: Vista pública sin spoilers

**DADO** un Challenge de Big O `published`
**CUANDO** se pide `GET .../today` con la Play `in_progress`
**ENTONCES** la respuesta trae solo `code` en los 3 lenguajes y las 8 `options` en orden fijo, sin `answer`, `trap_option`, `explanation`, `recipe` ni `recipe_category` (REQ CA 1, 18)

### CA-2: Empezar es idempotente

**DADO** un jugador sin Play
**CUANDO** hace `start` dos veces
**ENTONCES** existe una sola Play `in_progress` con `state = {}` (REQ CA 2)

### CA-3: Acierto

**DADO** respuesta `o_n_log_n`
**CUANDO** confirma `{ language: java, option: o_n_log_n }`
**ENTONCES** Play `won`, `code_language = java`, `preferred_code_language = java` y `result` con `BigOResult` y explicación estructurada (REQ CA 4)

### CA-4: Error

**DADO** respuesta `o_n_log_n`
**CUANDO** confirma `o_n2` en Go
**ENTONCES** Play `lost`, `code_language = go`, `result` con elegida y correcta (REQ CA 5)

### CA-5: Partida terminada

**DADO** una Play cerrada
**CUANDO** se envía otra jugada
**ENTONCES** `409 game_finished` y nada cambia (REQ CA 6)

### CA-6: Jugada inválida

**DADO** una opción fuera de las 8 o un lenguaje fuera de js/go/java
**CUANDO** se envía
**ENTONCES** `422 invalid_move`, la Play sigue `in_progress` y no cambia la preferencia (REQ CA 7)

### CA-7: Retomar

**DADO** una opción seleccionada sin confirmar
**CUANDO** el jugador vuelve el mismo día
**ENTONCES** la Play sigue `in_progress` con `state = {}` y sin intento perdido (REQ CA 8)

### CA-8: Cierre transaccional

**DADO** racha de Big O 3 y racha global 5
**CUANDO** confirma su respuesta
**ENTONCES** racha de Big O, racha global, stats por `recipe_category` e historial se actualizan en la misma transacción con días neutros (REQ CA 9)

### CA-9: Anulado

**DADO** un Challenge de Big O `voided`
**CUANDO** se intenta jugar
**ENTONCES** `409 challenge_voided`; las Play cuentan como `voided` sin afectar la racha (REQ CA 20)

## Diseño Técnico

### Servicios Afectados

| Servicio | Impacto | Cambios Necesarios | Estado |
|----------|---------|-------------------|--------|
| games (big-o) | Alto | Paquete `@nerdose/game-big-o` con `shared` y `./definition`: schemas, `toPublic`, `applyMove`, `result`, `codeLanguage`, `reduceStats`, `historyLabel`, `culprits = []`, `bankUsage = null` | Done |
| api | Medio | Una línea en `registry.ts`; tests de integración del ciclo completo | Done |

### Cambios de API

Implementa los schemas ya contratados y ajusta `BigOState` (nuevo), `BigOResult` (+`trap_option`, `explanation` estructurada `BigOExplanation`), `EmptyState` (descripción), `GameStatsView.extra` de big-o y ejemplos de Big O en `GET .../today` y `POST .../move`. Ver `docs/apis/api.yaml` (actualizado al crear las stories).

### Cambios de Base de Datos

Sin migración. `player_game_stats.extra` de big-o = `{ by_category: { <recipe_category>: { played, correct } } }`. `plays.state = BigOState`.

### Flujo de Interacción

1. **[web]** `GET .../today` → **[api]** `toPublic(payload)` = `{ code, options }`.
2. **[web]** `POST .../start` → Play `in_progress`, `state = {}`.
3. **[web]** `POST .../move { language, option }` → **[api]** `moveSchema.safeParse` (falla = `422`) → `applyMove` → `result` → cierre + rachas + stats + preferencia en una transacción.

### Consideraciones Técnicas

Payload: `{ recipe, recipe_category, code, answer, trap_option, explanation }` (REQ decisión 5). Estado vacío mientras `in_progress`. `./definition` no importa `polyglot` ni `node:child_process` (ADR-003). Test anti-spoiler adaptado: `toPublic` devuelve exactamente `code` y `options`, y `options` es igual a `BIG_O_OPTIONS` para cualquier payload. Share: `🧮 Big O #N` / `🟩|🟥 <Lenguaje>` / `nerdose.dev`. `historyLabel`: `✓ O(...)` / `✗`.
