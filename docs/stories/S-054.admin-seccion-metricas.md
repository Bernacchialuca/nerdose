# S-054: Admin: sección Métricas

**Status:** Completed
**Created:** 2026-11-15
**Source:** REQ-011

## Historia de Usuario

**Como** Responsable,
**quiero** abrir la sección Métricas del admin y elegir un rango,
**para** ver cuánta gente juega, si vuelve y qué desafíos fallan.

## Criterios de Aceptación

### CA-1: Acceso

Sin sesión de admin redirige al login y no muestra cifras (REQ CA 21)

### CA-2: Rango

Por defecto, los últimos 30 días UTC; el rango vive en la URL (`/metrics?from&to`) (REQ RF 11)

### CA-3: Validación

Un rango con `from > to`, futuro o mayor a 366 días muestra su mensaje, no consulta y no muestra datos; un 422 del servidor muestra su `message` (REQ CA 20)

### CA-4: Cifras y tablas

Muestra 4 cifras resumen y 4 tablas HTML (jugadores diarios con días vacíos en 0, retención, rachas con la nota «viva a hoy, no depende del rango», calidad ordenable con `aria-sort`), con porcentajes de un decimal y «—» si `null` (REQ CA 13-18)

### CA-5: Vacío, carga y error

Sin actividad cada tabla dependiente del rango dice «Sin datos en el rango.»; hay estados de carga y de error con «Reintentar»; un 401 vuelve al login (REQ CA 19)

### CA-6: Shell y analítica

El shell suma el ítem «Métricas» y el admin no importa analítica (REQ CA 26)

## Diseño Técnico

### Servicios Afectados

| Servicio | Impacto | Cambios Necesarios | Estado |
|----------|---------|-------------------|--------|
| admin | Medio | Módulo `metrics` (`/metrics`), validación con `validateMetricsRange`, tablas con `dataTableClass` de `@nerdose/ui`, ítem en el shell | Done |

### Cambios de API

Consume `GET /api/admin/metrics` de S-053.

### Cambios de Base de Datos

Ninguno.

### Flujo de Interacción

1. `RequireAuth`, rango en la URL, validación antes de consultar.
2. `useQuery` a `/api/admin/metrics`; la tabla de calidad se ordena con estado local.

### Flujos Afectados

- **admin-login-y-consultas (paso 5)** (ref: docs/flows/admin-login-y-consultas.md)

### Consideraciones Técnicas

**UX y Design System:** pantalla `metricas` P-05 (`docs/ux/surfaces/admin/screens/metricas.md`). Catálogo de DS de `admin` vacío: se deriva de `@nerdose/ui` y de los specs de `web` (gaps aceptados). Modo auto: no se crean componentes de DS. Cada tabla define su métrica al pie.
