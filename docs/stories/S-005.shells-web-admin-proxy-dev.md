# S-005: Shells de web y admin con proxy de mismo origen y pnpm dev

**Status:** Ready
**Created:** 2026-11-03
**Source:** REQ-001

## Historia de Usuario

**Como** desarrollador de Nerdose,
**quiero** que `web` y `admin` arranquen con un shell vacío y reenvíen `/api` a la `api` en el mismo origen, y que `pnpm dev` levante los 4 servicios,
**para** validar de punta a punta el esqueleto del sistema antes de construir funcionalidad de negocio.

## Criterios de Aceptación

### CA-1: Arranque completo

**DADO** la base migrada y variables definidas desde `.env.example`
**CUANDO** se ejecuta `pnpm dev`
**ENTONCES** arrancan `web`, `admin`, `api` y `generator`, con `api` y `generator` conectados con su propio rol (REQ AC 4)

### CA-2: Health por el origen de web

**DADO** el entorno de desarrollo en marcha
**CUANDO** se solicita `GET http://localhost:5173/api/health`
**ENTONCES** responde `200` con `{ "status": "ok", "db": "ok" }` (REQ AC 5)

### CA-3: Health por el origen de admin

**DADO** el entorno de desarrollo en marcha
**CUANDO** se solicita `GET http://localhost:5174/api/admin/health`
**ENTONCES** responde `200` con `{ "status": "ok", "db": "ok" }` (REQ AC 6)

### CA-4: Admin solo reenvía /api/admin

**DADO** el entorno en marcha
**CUANDO** se solicita `GET http://localhost:5174/api/health`
**ENTONCES** no llega a la `api` (intencional, replica producción)

### CA-5: Shell de web

**DADO** el entorno en marcha
**CUANDO** se abre `web` en el navegador
**ENTONCES** se ve un shell vacío con fondo oscuro, JetBrains Mono y acento `#3DDC84`, sin contenido de juego (REQ AC 7)

### CA-6: Pantalla vacía de admin

**DADO** el entorno en marcha
**CUANDO** se abre `admin` en el navegador
**ENTONCES** se ve una pantalla vacía de Admin, sin login ni funcionalidad (REQ AC 8)

### CA-7: Accesibilidad

**DADO** los componentes renderizados con Testing Library
**CUANDO** se ejecuta `vitest-axe`
**ENTONCES** no hay violaciones en `web` ni en `admin`

## Diseño Técnico

### Servicios Afectados

| Servicio | Impacto | Cambios Necesarios | Estado |
|----------|---------|-------------------|--------|
| web | Medio | SPA Vite + React 19 en `:5173`, proxy `/api` → `http://localhost:3000`, shell vacío con tokens de `@nerdose/ui`, JetBrains Mono self-hosted, `QueryClientProvider`, router mínimo, test de accesibilidad | Done |
| admin | Bajo | SPA Vite en `:5174`, proxy `/api/admin` → `http://localhost:3000`, pantalla vacía de Admin (UI solo en español) | Done |
| workspace | Bajo | Tarea `dev` de Turborepo (`persistent`, sin cache) para las 4 apps, README de arranque (`docker compose up -d` → `db:migrate` → `pnpm dev`) | Pending |

### Cambios de API

Ninguno. Consume `GET /api/health` y `GET /api/admin/health` (S-003) a través del proxy.

### Cambios de Base de Datos

Ninguno.

### Flujo de Interacción y Consideraciones Técnicas

- Revisión UX del request: sin impacto UX (el shell y la pantalla vacía son andamiaje, no pantallas del producto). Design System en `placeholder`: mandan los tokens de la convención `styling`.
- Puertos: `api` 3000, `web` 5173, `admin` 5174 (se corrigió `testing-e2e` de admin, que repetía 5173).
- Proxy de Vite sin CORS; si la `api` está caída el proxy responde 502/504 (aceptable en desarrollo).
- **Pruebas:** `web` renderiza el shell con clases `bg-bg`, `font-mono`, `text-accent` y sin violaciones axe; `admin` renderiza la pantalla vacía sin formulario de login ni violaciones axe; verificación del health por cada origen.
- **Dependencias en runtime:** `web`/`admin` → `api` solo vía proxy.
