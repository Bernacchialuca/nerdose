# S-041: Paquete polyglot: árbol, emisores JS/Go/Java y runner

**Status:** Ready
**Created:** 2026-11-14
**Source:** REQ-009

## Historia de Usuario

**Como** equipo de desarrollo,
**quiero** un paquete `@nerdose/polyglot` con un árbol de código neutral, emisores a JS, Go y Java y un runner que ejecute cada lenguaje,
**para** que el generator de Big O (y a futuro Bug Hunt) emita el mismo algoritmo en 3 lenguajes y lo verifique ejecutándolo.

## Criterios de Aceptación

### CA-1: Misma línea por sentencia

**DADO** un árbol de prueba con `for`, `while`, `if`, `let`, `compound`, `half` y recursión
**CUANDO** se emite a JS, Go y Java
**ENTONCES** los 3 códigos tienen la misma cantidad de líneas y cada nodo cae en la misma línea (`lineOf`) (REQ CA 17)

### CA-2: Programa ejecutable

**DADO** una función emitida y una lista de llamadas
**CUANDO** se arma con `emitProgram` / `wrapFunction`
**ENTONCES** el `main` de cada lenguaje llama la función una vez por lista de argumentos e imprime un entero por línea, sin instrumentación dentro de la función (REQ RF 9)

### CA-3: Ejecución correcta

**DADO** un programa válido en cada lenguaje
**CUANDO** se corre con `runInLanguage`
**ENTONCES** devuelve `ok: true` con `stdout` y `durationMs`, y los 3 lenguajes dan los mismos enteros (REQ CA 11)

### CA-4: Fallas tipificadas

**DADO** un programa con error de compilación, otro que excede el timeout de 10 s, un toolchain ausente y una salida excesiva
**CUANDO** se corren
**ENTONCES** el runner devuelve `ok: false` con `kind` `compile_error`, `timeout`, `toolchain_missing` u `output_too_large`, nunca lanza (REQ CA 13)

### CA-5: Aislamiento del runner

**DADO** el proceso corre como root
**CUANDO** se llama al runner
**ENTONCES** exige `RUNNER_UID`/`RUNNER_GID`; si faltan devuelve `runtime_error` con `runner_requires_non_root` sin ejecutar; usa `execFile` sin shell, entorno mínimo y limpia el directorio temporal en `finally` (ADR-007)

### CA-6: Toolchains documentados

**DADO** un desarrollador nuevo
**CUANDO** lee el README
**ENTONCES** encuentra los prerrequisitos Go >= 1.25 y JDK 21; los tests de integración fallan con mensaje claro si falta un toolchain (REQ decisión 14)

### Flujo de Interacción

1. **[polyglot - tree]** builders construyen el árbol con ids `n1`, `n2`… deterministas.
2. **[polyglot - emit]** `emit(func, lang)` → `{ code, lineOf }`; `emitProgram`/`wrapFunction` agregan el `main`.
3. **[polyglot - runner]** `runInLanguage(lang, source)` escribe en `mkdtemp`, ejecuta con `execFile` y devuelve `RunOutcome`.

### Flujos Afectados

- **generacion-diaria** (ref: docs/flows/generacion-diaria.md) — la verificación usa `runInLanguage` (consumido en S-045)

### Consideraciones Técnicas

Convenciones: `docs/architectures/polyglot/conventions/{code-tree,code-runner}.md`. Subconjunto portable (enteros chicos, sin overflow, `half` solo de no negativos). `polyglot` no sabe nada de Big O. Los tests con toolchains son de integración y fallan si falta uno. Solo `./generator` de los juegos puede importar el paquete (reglas ESLint existentes).
