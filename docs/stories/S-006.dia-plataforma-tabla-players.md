# S-006: Día de la plataforma y tabla players

**Status:** Completed
**Created:** 2026-11-04
**Source:** REQ-002

## Historia de Usuario

**Como** desarrollador de Nerdose,
**quiero** que `@nerdose/core` exponga el día de la plataforma y el número de desafío, y que exista la tabla `players` con sus permisos,
**para** contar con la base compartida de la que dependen la `api` y el `web` para sesión, idioma y día UTC.

## Criterios de Aceptación

### CA-1: Día UTC y número de desafío

**DADO** `LAUNCH_DATE = 2026-11-24` y el día `2026-12-01`
**CUANDO** se invoca `challengeNumber(day, launchDate)`
**ENTONCES** devuelve `8` (REQ CA 8)

### CA-2: Número nulo antes del lanzamiento

**DADO** un día anterior a `LAUNCH_DATE`
**CUANDO** se invoca `challengeNumber`
**ENTONCES** devuelve `null`, nunca un número menor que 1 (REQ CA 17)

### CA-3: Cuenta regresiva

**DADO** un instante `now`
**CUANDO** se invocan `nextResetAt(now)` y `secondsToReset(now)`
**ENTONCES** devuelven las 00:00 UTC siguientes y los segundos restantes (≥ 0)

### CA-4: Enums compartidos

**DADO** el paquete `@nerdose/core`
**CUANDO** se importan `LOCALES`, `CODE_LANGUAGES` e `isGameId()`
**ENTONCES** exponen `es/en`, `js/go/java` y los 5 `game_id` (devdle, bug-hunt, big-o, timeline, grep-grid)

### CA-5: Migración de players

**DADO** la base con la migración `0000`
**CUANDO** se ejecuta `db:migrate`
**ENTONCES** existen los enums `locale` y `code_language`, la tabla `players` con sus defaults (`locale = es`, `preferred_code_language = js`) y el índice `idx_players_created_at`

### CA-6: Permisos por rol

**DADO** la migración `0001_players` aplicada
**CUANDO** se conecta como `nerdose_api`
**ENTONCES** puede `SELECT`, `INSERT` y `UPDATE` sobre `players`; `nerdose_generator` no tiene acceso

## Diseño Técnico

### Servicios Afectados

| Servicio | Impacto | Cambios Necesarios | Estado |
|----------|---------|-------------------|--------|
| core | Medio | Módulo `platform-day`: `today(now)`, `challengeNumber(day, launchDate)` (nullable), `nextResetAt(now)`, `secondsToReset(now)`; enums `LOCALES`, `CODE_LANGUAGES` e `isGameId()` | Done |
| db | Medio | Enums PG `locale`, `code_language`; tabla `players` con índice `idx_players_created_at`; migración `0001_players` (drizzle-kit + `GRANT SELECT, INSERT, UPDATE ON players TO nerdose_api`, forward-only) | Done |

### Cambios de API

Ninguno.

### Cambios de Base de Datos

**`players`** (ref: `docs/db-schemas/nerdose-db.md` l. 140, sin cambios respecto del diseño)
- **Enums nuevos:** `locale` (`es`, `en`), `code_language` (`js`, `go`, `java`).
- **Campos:** `id uuid PK default gen_random_uuid()`, `locale locale NOT NULL default 'es'`, `preferred_code_language code_language NOT NULL default 'js'`, `user_id uuid NULL` (sin FK en v1), `created_at timestamptz NOT NULL default now()`, `last_seen_at timestamptz NOT NULL default now()`.
- **Índice:** `idx_players_created_at (created_at)`.
- **Permisos:** `GRANT SELECT, INSERT, UPDATE ON players TO nerdose_api` (l. 490).

### Flujo de Interacción

#### Escenario: cálculo del día y del número

1. **[core]** `today(now)` devuelve la fecha UTC `YYYY-MM-DD`; `challengeNumber(day, launchDate)` devuelve `day − launchDate + 1` o `null` si `day < launchDate`.
2. **[core]** `nextResetAt(now)` y `secondsToReset(now)` derivan de las 00:00 UTC siguientes.

**Outcome:** funciones puras, isomorfas, reutilizables por `api`, `generator` y `web`.

**Manejo de errores:** `launchDate` inválida es responsabilidad de quien parsea el env (S-007).

### Flujos Afectados

- **primera-visita-y-sesion** (ref: docs/flows/primera-visita-y-sesion.md) — `number` puede ser `null`; base de tiempo y entidad Player.
- **cambio-de-dia-y-publicacion** (ref: docs/flows/cambio-de-dia-y-publicacion.md) — provee `nextResetAt` y `secondsToReset`.

### Consideraciones Técnicas

- Funciones puras, sin acceso a reloj propio (el reloj se inyecta); el cliente nunca calcula "hoy" (`platform-day`).
- Migración forward-only con `GRANT` manual obligatorio (ADR-004); sin PII en `players`.
- Sin dependencias nuevas.
