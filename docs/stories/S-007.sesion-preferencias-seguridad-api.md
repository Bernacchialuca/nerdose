# S-007: Sesión anónima, preferencias y seguridad HTTP en la api

**Status:** Completed
**Created:** 2026-11-04
**Source:** REQ-002

## Historia de Usuario

**Como** jugador anónimo de Nerdose,
**quiero** que la `api` me cree una sesión anónima con cookie y me deje guardar mi idioma y lenguaje de código preferido,
**para** entrar sin registrarme y conservar mis preferencias entre visitas.

## Criterios de Aceptación

### CA-1: Primera sesión con idioma del navegador

**DADO** un navegador sin cookie con `Accept-Language: en-US`
**CUANDO** hace `POST /api/session`
**ENTONCES** se crea un Player con `locale = en` y `preferred_code_language = js` y se setea `nd_pid` (HttpOnly, Secure, SameSite=Lax) (REQ CA 1)

### CA-2: Idioma no soportado

**DADO** `Accept-Language: pt-BR`
**CUANDO** se crea la sesión
**ENTONCES** el Player queda con `locale = es` (REQ CA 2)

### CA-3: Sesión idempotente

**DADO** una cookie `nd_pid` válida con Player existente
**CUANDO** se llama `POST /api/session`
**ENTONCES** no se crea otro Player, se renueva la cookie y se actualiza `last_seen_at`; `created = false` (REQ CA 3)

### CA-4: Cookie huérfana

**DADO** una cookie `nd_pid` cuyo Player no existe
**CUANDO** se llama `POST /api/session`
**ENTONCES** se crea un Player nuevo y se reemplaza la cookie sin error (REQ CA 4)

### CA-5: Rate limit de sesiones

**DADO** una IP con 20 sesiones creadas en 10 minutos
**CUANDO** intenta la 21
**ENTONCES** recibe `429 rate_limited` con mensaje genérico (REQ CA 13)

### CA-6: Origen y content-type

**DADO** una mutación con `Origin` no permitido o sin `Content-Type: application/json`
**CUANDO** llega a la `api`
**ENTONCES** se rechaza con `403 forbidden_origin` o `415 unsupported_media_type` sin crear Player (REQ CA 14)

### CA-7: Actualización parcial de preferencias

**DADO** un Player existente
**CUANDO** envía solo `preferred_code_language = go` a `PATCH /api/me/preferences`
**ENTONCES** se actualiza ese campo y `locale` no cambia (REQ CA 7)

### CA-8: Preferencias inválidas

**DADO** un body con `locale = fr`, `preferred_code_language = rust` o vacío
**CUANDO** se procesa
**ENTONCES** `422 validation_error` y el Player no se modifica (REQ CA 15)

### CA-9: Preferencias sin sesión

**DADO** un pedido sin cookie válida
**CUANDO** llega a `PATCH /api/me/preferences`
**ENTONCES** `401 no_session` sin modificar datos (REQ CA 16)

### CA-10: Resolución del idioma

**DADO** cualquier respuesta de la `api`
**CUANDO** se resuelve el idioma
**ENTONCES** se usa `locale` del Player → `Accept-Language` → `es`

## Diseño Técnico

### Servicios Afectados

| Servicio | Impacto | Cambios Necesarios | Estado |
|----------|---------|-------------------|--------|
| api | Alto | Env (`LAUNCH_DATE`, `WEB_ORIGIN`, `ADMIN_ORIGIN`, `TRUST_PROXY_HEADER`) en `config/env.ts` y `.env.example`; `secureHeaders`, `bodyLimit`, `originAndContentType`, rate limit en memoria (`hono-rate-limiter`); middlewares `playerSession` y `locale`; módulo `identity` con `POST /api/session` y `PATCH /api/me/preferences` | Done |

### Cambios de API

#### Endpoints Implementados sin Cambios de Contrato

Ambos ya están especificados en `docs/apis/api.yaml`; esta story los **implementa**.

**`POST /api/session`** (api.yaml l. 95): body `{}`, response `SessionResponse` `{ locale, preferred_code_language, created }`, `Set-Cookie: nd_pid`. Errores `403 forbidden_origin`, `415 unsupported_media_type`, `429 rate_limited` (20 / 10 min por IP).

**`PATCH /api/me/preferences`** (api.yaml l. 126): body `PreferencesUpdate` (`minProperties: 1`, `locale?`, `preferred_code_language?`), response `Preferences`. Errores `401 no_session`, `403`, `415`, `422 validation_error`, `429` (30 / min por `player_id`).

#### Nuevos Endpoints

Ninguno.

### Cambios de Base de Datos

#### Tablas Existentes a Modificar

Ninguna. Usa `players` creada en S-006 (`INSERT`, `UPDATE`, `SELECT` con el rol `nerdose_api`).

#### Nuevas Tablas

Ninguna.

### Flujo de Interacción

#### Escenario: primera sesión (CA 1-4, 13, 14)

**Trigger:** `POST /api/session` con `Content-Type: application/json`, body `{}`.

1. **[api - security]** Rate limit por IP → `originAndContentType(WEB_ORIGIN)`.
2. **[api - identity]** Sin `nd_pid` válido: `INSERT INTO players (locale, preferred_code_language) VALUES (pickLocale(Accept-Language), 'js')`; log `PlayerCreated` (sin IP). Con cookie válida: `UPDATE players SET last_seen_at = now()`.
3. **[api]** `Set-Cookie: nd_pid=<id>; HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age=34560000`. Response `200 { locale, preferred_code_language, created }`.

**Outcome:** Player persistido y cookie funcional.

**Manejo de errores:** `429 rate_limited`, `403 forbidden_origin`, `415 unsupported_media_type` en el formato de error común (ADR-015).

#### Escenario: cambio de preferencias (CA 7, 15, 16)

1. **[api - identity]** Rate limit 30/min por `player_id` → `playerSession('required')` (`401 no_session`) → Zod `PreferencesUpdate` (`422 validation_error`) → `UPDATE players SET ... WHERE id = $1`; log `PlayerPreferencesChanged`.
2. **[api]** Response `200 Preferences`.

**Outcome:** preferencias persistidas; solo cambian los campos enviados.

### Flujos Afectados

### Consideraciones Técnicas

**Seguridad:**
- Cookie con los mismos atributos en todos los ambientes (`Secure` funciona en `http://localhost`); `player_id` nunca se toma del body/query.
- `WEB_ORIGIN=http://localhost:5173` y `ADMIN_ORIGIN=http://localhost:5174` en `.env.example`, obligatorias en todo ambiente; `process.env` solo se lee en `config/env.ts`.
- `secureHeaders()` y `bodyLimit`; sin PII ni IP en logs.

**Performance:**
- Rate limit y caches en memoria (ADR-012).

**Dependencias:**
- `hono-rate-limiter` como dependencia nueva de `api`.
