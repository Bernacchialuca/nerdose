# S-061: IP del rate limit no falsificable y logs sin player_id

**Status:** Completed
**Created:** 2026-11-25
**Source:** REQ-012

> **Retroactiva:** implementada fuera del workflow el 2026-11-25 (rama `feature/seguridad-rate-limit-y-logs`, commit `5ed6274`, merge `cdedec0`) y documentada después. **Sin story plan** (implementado fuera del workflow, sin story plan). ADR-012 y las convenciones `security`, `player-identity` y `env-config` se actualizaron en esa misma rama.

## Historia de Usuario

**Como** Responsable del producto,
**quiero** que el límite por IP no se pueda saltear desde el cliente y que los logs no guarden la credencial del jugador,
**para** que el rate limit proteja de verdad (NFR-S08) y un log filtrado no permita suplantar a nadie.

## Criterios de Aceptación

### CA-1: `X-Forwarded-For` desde la derecha

**DADO** `TRUST_PROXY_HEADER=X-Forwarded-For` y `TRUST_PROXY_HOPS=1` (default)
**CUANDO** llega `X-Forwarded-For: 6.6.6.6, 203.0.113.7`
**ENTONCES** la clave del límite es `203.0.113.7` (la que agregó el proxy) y cambiar la primera entrada en cada request no saltea el límite; con más hops que entradas se usa la primera

### CA-2: Otros headers de confianza enteros

**DADO** `TRUST_PROXY_HEADER=X-Real-IP` (o `CF-Connecting-IP`, `Fly-Client-IP`)
**CUANDO** llega el request
**ENTONCES** la clave es el valor completo del header

### CA-3: Sin header, la IP de la conexión

**DADO** que no hay `TRUST_PROXY_HEADER`, o que el request no trae el header configurado
**CUANDO** se calcula la clave
**ENTONCES** es la IP de la conexión (`getConnInfo`); `'unknown'` solo queda cuando no hay socket (`app.request` en tests), así que ya no hay un balde compartido por todos

### CA-4: Aviso en producción

**DADO** `NODE_ENV=production` sin `TRUST_PROXY_HEADER`
**CUANDO** arranca la `api`
**ENTONCES** loguea un `warn` explicando que detrás de un proxy todos los clientes compartirían la IP del proxy

### CA-5: Nueva variable `TRUST_PROXY_HOPS`

`TRUST_PROXY_HOPS` es opcional, entero ≥ 1, default 1, validada al arrancar y documentada en `apps/api/.env.example`

### CA-6: Logs con `player_ref`

**DADO** cualquier log con identidad de jugador (`PlayerCreated`, `PlayerPreferencesChanged`, `PlayStarted`, `PlayFinished`, `StreaksUpdated`, `GuessRejected`, `PlayVoidAcknowledged` y el logger hijo de `player-session`)
**CUANDO** se escribe
**ENTONCES** lleva `player_ref` (primeros 8 hex de `sha256(player_id)`, `@/shared/player-ref`) y nunca `player_id`

## Diseño Técnico

### Servicios Afectados

| Servicio | Impacto | Cambios Necesarios | Estado |
|----------|---------|-------------------|--------|
| api | Medio | `http/middleware/rate-limit.ts`: `clientIp(config: { TRUST_PROXY_HEADER?, TRUST_PROXY_HOPS? })`; controllers (`identity`, `gameplay`, `quality`, `admin`) pasan `deps.config`; `config/env.ts` + `.env.example` con `TRUST_PROXY_HOPS`; `index.ts` con el `warn`; nuevo `shared/player-ref.ts` (re-exportado por `admin.service.ts`); `player-session.ts` y los servicios loguean `player_ref` | Done |

### Cambios de API

Ninguno en el contrato HTTP. Cambia solo cómo se calcula la clave del `429`.

### Cambios de Base de Datos

Ninguno.

### Flujo de Interacción

1. **[api - limit]** `clientIp(env)` lee el header configurado: `X-Forwarded-For` → `entries[len − hops]`; otro header → valor entero; ausente → IP del socket.
2. **[api - player-session]** al resolver la cookie, `logger.child({ player_ref })`.

### Flujos Afectados

- **primera-visita-y-sesion** (ref: docs/flows/primera-visita-y-sesion.md) — origen de la IP del límite de sesiones; `PlayerCreated` con `player_ref`.
- **abrir-y-retomar-juego**, **jugada-y-cierre-de-partida**, **preferencias-y-share** — eventos de dominio con `player_ref`.

### Consideraciones Técnicas

**Seguridad:**
- Detrás de un proxy hay que configurar `TRUST_PROXY_HEADER` (preferible un header que el proxy pisa) y `TRUST_PROXY_HOPS` si hay más de uno.
- ADR-009 suma la regla de logs; ADR-012 ya tenía la corrección de la IP.

## Evidencia de tests

- `apps/api/test/http/rate-limit.test.ts`: entrada del proxy desde la derecha; IP inventada a la izquierda no cambia la clave; más hops que entradas; otro header entero; sin header o ausente usa la conexión; sin socket cae a `unknown`; inventar la primera no saltea el límite (HTTP).
- `apps/api/test/http/session.test.ts`, `start.test.ts`, `move.test.ts`, `preferences.test.ts`, `acknowledge-void.test.ts`, `anti-spoiler.test.ts`: los logs llevan `player_ref` y no `player_id`.
- `apps/api/test/env.test.ts`, `apps/api/test/env-example.test.ts`: `TRUST_PROXY_HOPS` validada y presente en `.env.example`.
