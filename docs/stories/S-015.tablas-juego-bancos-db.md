# S-015: Tablas de juego y bancos

**Status:** Ready
**Created:** 2026-11-06
**Source:** REQ-004

## Historia de Usuario

**Como** desarrollador de Nerdose,
**quiero** que la base tenga las tablas de desafíos, partidas, estadísticas, términos y ejecuciones de jobs con sus restricciones y permisos,
**para** que la API y el generator persistan el ciclo completo de juego.

## Criterios de Aceptación

### CA-1: Migración forward-only

**DADO** una base con `0000_roles_and_grants` y `0001_players`
**CUANDO** se aplica `0002_gameplay_and_banks`
**ENTONCES** crea los enums `game_id`, `challenge_status`, `play_status`, `bank_item_status`, `term_category`, `job_run_status` y las tablas `challenges`, `plays`, `rejected_guesses`, `player_game_stats`, `player_stats`, `terms`, `job_runs` tal como las define `nerdose-db.md`

### CA-2: Unicidad y vigencia del desafío

**DADO** `challenges`
**CUANDO** se intenta insertar dos desafíos vigentes (`approved`, `published`, `voided`) para (juego, fecha)
**ENTONCES** `uq_challenges_active_game_date` lo impide; uno `rejected` o `draft` no choca (REQ CA 31)

### CA-3: Payload inmutable y transiciones

**DADO** un desafío `approved`
**CUANDO** se intenta modificar su `payload` o hacer una transición de estado inválida
**ENTONCES** los triggers `challenges_payload_immutable` y `challenges_status_transition` lo rechazan (REQ CA 32)

### CA-4: Una Play por jugador y desafío

**DADO** `plays`
**CUANDO** se inserta una segunda Play para (jugador, desafío)
**ENTONCES** `uq_plays_player_challenge` la rechaza

### CA-5: Checks e integridad

**DADO** las tablas nuevas
**CUANDO** se insertan filas fuera de rango (`number < 1`, `voided` sin motivo, contadores negativos, `max_streak < current_streak`, `term` fuera de `^[A-Z]{4,12}$`, textos sin `es`/`en`, `rejected` sin motivo, `word` fuera de `^[A-Z]+$`)
**ENTONCES** los checks los rechazan; un término `rejected` no puede volver a `approved` (`bank_items_rejected_terminal`)

### CA-6: Permisos por rol

**DADO** los roles `nerdose_api` y `nerdose_generator`
**CUANDO** operan sobre las tablas nuevas
**ENTONCES** tienen exactamente los `GRANT` de `nerdose-db.md` (l. 489-503); `nerdose_api` no puede modificar `payload`, y los tests de permisos lo verifican

### CA-7: Esquema Drizzle

**DADO** `packages/db/src/schema/`
**CUANDO** se compila
**ENTONCES** refleja las tablas y los enums (los de `game_id` y `term_category` derivan de `GAME_IDS` y `TERM_CATEGORIES` de `core`)

## Diseño Técnico

### Servicios Afectados

| Servicio | Impacto | Cambios Necesarios |
|----------|---------|-------------------|
| db | Alto | Migración `0002_gameplay_and_banks` (drizzle-kit + SQL manual para índices parciales, checks, triggers y `GRANT`); schema Drizzle; helpers de `@nerdose/db/testing` para sembrar desafíos |

### Cambios de API

Ninguno.

### Cambios de Base de Datos

Tablas nuevas: `challenges`, `plays`, `rejected_guesses`, `player_game_stats`, `player_stats`, `terms`, `job_runs`; diseño sin cambios respecto de `docs/db-schemas/nerdose-db.md`. Se agrega la nota de `job_runs.summary.skipped` y la forma de `player_game_stats.extra` de Devdle (`{ "guesses": { "1": n, …, "6": n }, "losses": n }`). Fuera de alcance: `challenge_reports`, `timeline_facts`, `generation_requests`, `generation_failures`, vistas `metrics_*`.

### Flujo de Interacción

Sin flujo de usuario. Es la base de S-018, S-019 y S-020.

### Flujos Afectados

- Todos los que persisten estado de juego: `abrir-y-retomar-juego`, `jugada-y-cierre-de-partida`, `generacion-diaria`, `carga-de-bancos`, `estadisticas-del-jugador`.

### Consideraciones Técnicas

**Riesgos:** `GRANT` omitidos rompen en runtime; los tests de integración con Testcontainers verifican cada rol. El `GRANT` de `UPDATE` en `challenges` para la API es por columnas.
